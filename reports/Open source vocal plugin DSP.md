# Open-source DSP assembles a studio vocal chain

Every module of a studio-grade vocal chain has an open-source reference that a GPL-3.0-or-later Rust DAW may legally port, and every module except pitch correction runs with no look-ahead. The strongest sources are **freeverb3 as shipped inside Dragonfly Reverb** (Dattorro plate, Lexicon-224-style room and zita-derived hall, GPL-2.0-or-later), **Airwindows** (MIT: Channel9 console, Tube2, ToTape, Pressure4, kPlate), the **Surge and Chowdhury code** (delay, bucket-brigade, exciter, spring, tape hysteresis), **Fons Adriaensen's and Robin Gareus's x42 code** (darc leveller, zita-at1 retuner), **Vicanek- and Ivantsov-style matched filters** for an EQ that does not cramp at 48 kHz, and **HIIR** half-band oversampling that costs about 0.07 ms. "Best-sounding" is not proven by the research: no source the researchers could open ranks these tools on vocals, so the selection rests on what each author says, on what the code does, and on licence fit. Three groups of code must be re-derived from formulas and never copied: GPL-2.0-only wording (the TAL/YK Juno chorus, Wavechild670), AGPL (ZL Equalizer, ZL Compressor, the `tdpsola` crate) and unlicensed or GPL-3.0-only code (GreyBoxDRC, two authors' Faust compressors, and the Chowdhury GPL-3.0 code if "or later" is to be kept). The recommended build is a fixed-order strip: auto-level, high-pass, expander, optional tuner, de-esser, corrective EQ, FET-style then opto-style compression, tone EQ, one colour slot (Clean, Tube, Console, Tape, Exciter), width (micro-pitch, Juno chorus, ADT), then a six-type delay feeding a five-type reverb (Plate, Room, Hall, Chamber, Spring), and a zero-latency limiter. The dry vocal passes through at most about four samples of oversampling delay; an opt-in tuner adds a stated 3.3 ms. Five of the six research files were cut short, so the reverb shortlist, the reverb CPU statement and the whole dynamics design below are **this report's synthesis** from the constants the notes do contain, and are labelled as such.

**Evidence key.** A code citation with no tag means a researcher cloned the repository on 18 November 2026 and read that file. **(secondary)** means the fact comes from a search-result summary of a page nobody could open. **(computed)** means a numeric experiment or arithmetic done by a researcher, or in a few marked cases by this report, on cited formulas; it is not a published figure. **(synthesis)** means a recommendation made by this report or by the researchers, not a quoted fact. Hosts for the primary papers (dafx.de, aes.org, vicanek.de, cytomic.com, arxiv.org) and for the forums (KVR, Gearspace, airwindows.com) were blocked, so paper formulas are quoted from the open code that implements them.

Three points need care. First, the only popular open Juno-60 chorus code is TAL-derived and carries "GNU General Public License Version 2" with no "or any later version" clause, so the clean route is the MIT-licensed Juno-60 measurements plus the BSL-1.0 bucket-brigade line ([YK Chorus README](https://github.com/SpotlightKid/ykchorus/blob/master/README.md); [Juno60 Chorus README](https://github.com/pendragon-andyh/Juno60/blob/master/Chorus/README.md)). Second, the notes disagree about Calf: three researchers read file headers saying LGPL "either version 2 of the License, or (at your option) any later version", while a fourth read a README line saying "This project is licensed under LGPL-2.1-only" ([Calf modules_comp.cpp](https://github.com/calf-studio-gear/calf/blob/HEAD/src/modules_comp.cpp); [Calf README](https://github.com/calf-studio-gear/calf/blob/master/README.md)). Check the header of each Calf file before copying from it. Third, GPL-3.0 code without "or later" wording can be combined, but the combined binary can then only ship under version 3. The project keeps its "or later" option by porting from the permissive and "or later" sources and re-deriving the Jiles-Atherton tape solver, the Vicanek filters and the Pultec network from their published equations (synthesis). JUCE, which every Chowdhury and Surge plugin sits on, was not checked this session, so port the mathematics and never link the framework.

## How each recommended source makes its sound

### Reverb: three freeverb3 engines and a spring cover the vocal types

The reverb notes stop before their recommendation, so the shortlist here is synthesis. The evidence for it is specific. Dragonfly is the only open reverb that ships vocal-labelled presets: "Vocal Studio" and Small, Medium and Large "Vocal Hall" in the hall, and Small, Medium and Large "Vocal Room" in the room ([hall DistrhoPluginInfo.h](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-hall-reverb/DistrhoPluginInfo.h); [room DistrhoPluginInfo.h](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-room-reverb/DistrhoPluginInfo.h)). The Dattorro plate is verified in three independent code bases and in the paper. The alternatives rule themselves out in their authors' words. Cloud Seed "does not attempt to model any specific device, or even to be a general-purpose reverb plugin at all. It is best employed as a special effect" ([CloudSeed readme](https://github.com/ValdemarOrn/CloudSeed/blob/master/readme.md)). Airwindows calls Galactic "a super-reverb designed specially for pads and space ambient" and says of kChamberAR "I didn't get the Abbey Road chamber" ([Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)). MVerb has no modulation at all, and its early-reflection taps land with the loudest taps latest, because its offsets are measured from the write head ([MVerb.h](https://github.com/martineastwood/mverb/blob/master/MVerb.h)). Freeverb "doesn't contain predelay, or any EQ" ([Freeverb readme](https://github.com/sinshu/freeverb/blob/main/readme.txt)).

**Plate: the Dattorro figure-eight tank.** The input is mono-summed, DC-blocked and low-passed, then passes four series allpasses. It enters a loop of two halves, each built as modulated allpass → long delay → one-pole damping low-pass → decay gain → allpass → long delay, with the end of each half feeding the other. Each output is seven signed taps read from inside the delays and allpasses, which is how one mono tank yields decorrelated stereo ([strev.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/strev.cpp); [Plateau Dattorro.cpp](https://github.com/ValleyAudio/ValleyRackFree/blob/main/src/Plateau/Dattorro.cpp)). All lengths are stored at 29,761 Hz and scale by fs/29,761 (×1.6128 at 48 kHz). The earlier research in this project read the paper and confirmed the lengths and coefficients against its Figure 1 and Tables 1 and 2 ([Dattorro 1997](https://ccrma.stanford.edu/~dattorro/EffectDesignPart1.pdf)).

| Element | @ 29,761 Hz | @ 48 kHz (computed) |
|---|---|---|
| Input allpasses (coefficients 0.75, 0.75, 0.625, 0.625) | 142, 107, 379, 277 | 229, 173, 611, 447 |
| Left half: modulated allpass / delay / allpass / delay | 672 / 4453 / 1800 / 3720 | 1084 / 7182 / 2903 / 6000 |
| Right half: modulated allpass / delay / allpass / delay | 908 / 4217 / 2656 / 3163 | 1464 / 6801 / 4284 / 5101 |
| Left output taps (signs + + − + − − −) | 266, 2974, 1913, 1996, 1990, 187, 1066 | 429, 4797, 3085, 3219, 3210, 302, 1719 |
| Right output taps (same signs) | 353, 3627, 1228, 2673, 2111, 335, 121 | 569, 5850, 1981, 4311, 3405, 540, 195 |

The paper's coefficients are decay diffusion 1 = 0.70 on the two modulated allpasses, decay diffusion 2 = clamp(decay + 0.15, 0.25, 0.50), damping 0.0005, bandwidth 0.9995 and output tap gain 0.6. The implementations differ in allpass sign convention and in modulation, so port one of them consistently. freeverb3 computes the loop gain from a reverb time as `decay = 10^(−3·tankDelay/(rt60·fs))`, with `tankDelay` the mean of the four delay lengths, and modulates with two LFOs at 1.0 and 1.1 Hz plus a little noise. Plateau modulates all four tank allpasses with triangle LFOs at 0.10, 0.15, 0.12 and 0.18 Hz and a 16-sample excursion, and adds an in-loop high-pass ([strev.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/strev.cpp); [Plateau Dattorro.hpp](https://github.com/ValleyAudio/ValleyRackFree/blob/main/src/Plateau/Dattorro.hpp)). Dragonfly's default plate is a different algorithm, "Nested" (`nrevb`): 18 parallel low-pass-feedback combs per channel (49–98 ms) followed by series allpasses, which is dense from the first tens of milliseconds and has no size control ([nrevb.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/nrevb.cpp)). The Dattorro tank is the better single plate for this project because its topology is cross-verified and it has a real decay and size law (synthesis).

**Room: freeverb3 `progenitor2`.** Its source ties its output taps to "The Lexicon 224 manual". Each half-loop is damping low-pass → two modulated allpasses → a double-nested allpass → a triple-nested allpass, joined by short plain delays, and the two halves cross-feed with a bass-boost path: `outL += loopdecay·(crossR + bassb·lpf(bassAP(crossR)))`. Tables at 34,125 Hz are `allpassL = {239, 392, 1944, 612, 1212, 121, 816, 1264}`, `allpassR = {205, 329, 2032, 368, 1452, 5, 688, 1340}`, `delayL = {1, 2, 1055, 344, 1572, 0}` and `delayR = {1, 625, 835, 500, 16, 1460}`. The diffusion defaults are 0.375, 0.312, 0.406 and 0.25, and the decay law is `loopdecay = 10^(log10(0.237)/(rt60/RSFactor))`. In front sit ten series modulated allpasses per channel (L `{617, 535, 434, 347, 218, 162, 144, 122, 109, 74}`, coefficient −0.78) and a four-allpass cross-feed diffuser mixed at 0.4. Each output is 15 signed taps with weights 0.469, 0.219, 0.064 and 0.045, and the researcher's instruction is to port those tap expressions verbatim from the file ([progenitor.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/progenitor.cpp); [progenitor2.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/progenitor2.cpp)).

**Hall: freeverb3 `zrev2`, the zita-rev1 network with shelving decay.** Eight lines each hold a modulated allpass followed by a modulated delay, mixed by an 8×8 Hadamard matrix done as three butterfly stages. Total loop times are `{153.129, 210.389, 127.837, 256.891, 174.713, 192.303, 125.000, 219.991}` ms, of which the allpass parts are `{20.346, 24.421, 31.604, 27.333, 22.904, 29.291, 13.458, 19.123}` ms; the allpass coefficient is 0.6 with alternating sign per line and the line gain is `sqrt(1/8)·10^(−3·L/(rt60·fs))`. What turns the zita prototype into a vocal hall is the damping: a low shelf and a high shelf inside every line, whose gain is set so that the band's decay time is exactly `rt60·factor`. The defaults are 1.3× below 500 Hz and 0.3× above 3.6 kHz. The mono input feeds lines 0–1 with a plus sign and 2–3 with a minus sign for left, and 4–7 likewise for right. The outputs are `0.2·(x0 − x1 + x2 − x3)` and `0.2·(x4 + x5 − x6 − x7)`, followed by a 22 ms feed-forward comb whose tap gain is a 2.4 Hz LFO of opposite sign on each side, which decorrelates the channels ([zrev.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/zrev.cpp); [zrev2.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/zrev2.cpp)). Dragonfly maps Size (10–60 m) to a length scale of size/80, so its 12 m "Vocal Studio" runs lines of roughly 19–39 ms (computed by this report from that mapping) ([dragonfly-hall DSP.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-hall-reverb/DSP.cpp)).

**Early reflections** for room and hall are one tapped delay line per channel. Dragonfly loads preset 1: left taps at 19.9, 35.4, 38.9, 41.4, 69.9 and 79.6 ms with gains 1.020, 0.818, 0.635, 0.719, 0.267 and 0.242; right taps 1 ms later with gains 1.021, 0.820, 0.633, 0.722, 0.187 and 0.243. A cross-channel path adds a 0.3 ms delay and a 750 Hz allpass, and 20 % of the early signal is sent into the late reverb ([earlyref.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/earlyref.cpp)).

Two freeverb3 mechanics matter for a real-time Rust port. Every length is `floor(length·fs·RSFactor/refFs)` and then **incremented until prime**, so the integer lengths change with sample rate and size; the search belongs at parameter-change time, with buffers pre-allocated for the largest size. Modulated allpasses read with first-order allpass interpolation, which keeps magnitude flat inside the loop, whereas the linear interpolation used by Cloud Seed, Galactic and Surge adds high-frequency loss that darkens long tails ([revbase.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/revbase.cpp); [allpass_t.hpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/allpass_t.hpp)). Pre-delay in all of these is a plain integer delay on the wet signal, so it never delays the dry voice.

**Spring: the chowdsp model inside Surge XT.** Each channel computes `x = tanh(in − feedbackGain·delayOut)`, high-passes at 40 Hz, and runs 16 cascaded Schroeder allpasses of `(0.35 + 3·size)` ms each with gain `±(0.5 − 0.4·spin)`. The signal crosses the same 16 allpasses again before the long feedback delay of `1000 + size·0.099·fs` samples, so one loop trip is 32 allpass stages; that dispersion is the spring "drip". Decay follows `T60 = 0.5·9^(0.95·decay − 0.7·(1 − size²))` seconds, and a four-delay Householder "reflection network" (0.07, 0.17, 0.23 and 0.29 s × size) is subtracted ([SpringReverbProc.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/SpringReverbProc.cpp); [ReflectionNetwork.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/ReflectionNetwork.h)).

**An optional character plate: Airwindows kPlateA.** Its author describes it as "a plate reverb, not unlike its namesake atop Abbey Road" and kStation as "a realistic small room modeled after David Bowie's vocal reverb" that is there "to merge with your vocal" ([Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)). kPlateA is five cascaded banks of five delays (25 primes from 5 to 829 samples) mixed by an un-normalised Householder step `y_i = 3·x_i − 2·(sum of the other four)`, with a regeneration gain of 0.000256–0.0002975 that sits just under the lossless value 1/5⁵ = 0.00032. Around the tank it has a roughly 600 Hz input high-pass, a soft clip before and an inverse soft clip after, and nine 0.5-coefficient allpasses in a 3×3 block instead of early reflections; the right channel walks the same 5×5 delay grid in transposed order for stereo ([kPlateAProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/kPlateA/kPlateAProc.cpp); [kPlateA.h](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/kPlateA/kPlateA.h)). Its tables are raw 44.1 kHz sample counts, so it runs about 8 % smaller at 48 kHz by design. Only kPlateA's left channel was read line by line, and kStation's inner loop was not read, so both wait for a second reading pass.

In this code the reverb "type" is decided by four things: whether a discrete early-reflection stage exists, how long the recirculating delays are, how much series-allpass diffusion sits in front of or inside the loop, and how decay varies with frequency. Plates have no early taps, instant density and high-frequency-only damping. Rooms have signed early taps, short nested-allpass loops and decays of 0.2–1 s. Halls have early taps, long lines of 125–257 ms and three-band decay. None of the open reverbs read is a dedicated chamber: Dragonfly's "Small Chamber" and "Large Chamber" are hall presets (size 16–20 m, decay 0.8–1.0 s, low multiplier 1.1–1.3, high multiplier 0.25–0.35), so Chamber here is a voicing of the hall engine and not a separate port ([hall DistrhoPluginInfo.h](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-hall-reverb/DistrhoPluginInfo.h)).

The vocal presets in the source are more conservative than mixing folklore. Dragonfly's vocal halls use pre-delays of 0–12 ms, decays of 0.8–2.4 s, high cuts of 5.8–6.25 kHz and high-frequency decay multipliers of 0.30–0.40; its vocal rooms use 0–4 ms and 0.3–1.0 s; its plates use 0–20 ms and 0.2–1.0 s ([hall presets](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-hall-reverb/DistrhoPluginInfo.h); [room presets](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-room-reverb/DistrhoPluginInfo.h); [plate presets](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-plate-reverb/DistrhoPluginInfo.h)). Mix-time guidance runs longer: Sound On Sound gives "a plate reverb emulation with a decay time of 1.2 seconds or so and a pre-delay of 60-80ms" ([SOS: Choosing the right reverb](https://www.soundonsound.com/techniques/choosing-right-reverb)). The short Dragonfly values suit live monitoring and the SOS values suit playback, which is a judgement of the researchers and not a sourced claim.

### Delay and modulation: one stereo core, skinned six ways

Every delay studied filters, and optionally saturates, inside the feedback loop, and builds its stereo behaviour from a 2×2 feedback matrix. One core therefore serves all types (synthesis from the cited code):

```
tapL, tapR   = read(bufL, timeL), read(bufR, timeR)        // 4-point Hermite or 3rd-order Lagrange
fL, fR       = saturate(lowpass(highpass(tapL))), ...       // in-loop tone and colour
writeL       = a·in + g·(d·fL + c·fR)
writeR       = b·in + g·(d·fR + c·fL)
stereo/dual: d=1, c=0, a=b      ping-pong from mono: a=1, b=0, d=0, c=1      cross blend: d=0.618, c=0.382
unequal L/R note values: gR = g^(timeR/timeL)
```

Surge's Dual Delay is the clean reference. It writes `wL = inL + fb·tapL + cf·tapR`, cubes the feedback and crossfeed gains, filters the loop with a 2-pole low-pass and a high-pass at Q 0.707, offers soft, tanh and hard clippers in the loop, and reads with a 12-tap windowed-sinc interpolator. Its "clean" mode handles time changes by crossfading two taps over half the delay time (clamped to 10 ms–0.5 s), while its "tape" mode lags the time so the pitch glides ([sst-effects Delay.h](https://github.com/surge-synthesizer/sst-effects/blob/main/include/sst/effects/Delay.h)). Calf supplies the equal-decay law `fb_right = fb^(time_r/time_l)` and a default of 3/16 against 5/16 notes ([Calf modules_delay.cpp](https://github.com/calf-studio-gear/calf/blob/master/src/modules_delay.cpp)). Airwindows Doublelay supplies the golden-ratio direct/cross split ([DoublelayProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Doublelay/DoublelayProc.cpp)).

**Tape character** is produced four ways in open code, and no repository read puts a physical hysteresis model inside an echo loop. Cocoa Delay slews its read head (`readPos += (target − readPos)·10·dt`, about a 100 ms time constant), reads with 4-point Hermite interpolation, wanders the time with a damped random walk, and runs low-pass → high-pass → an Airwindows-style drive in the loop ([CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp)). Airwindows TapeDelay2 is a fixed 88,200-sample loop read at variable speed, with a band-pass in the regeneration path and flutter keyed to signal amplitude; its author calls it "one of the good ones" ([TapeDelay2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/TapeDelay2/TapeDelay2Proc.cpp); [Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)). Calf's "Tape" medium is a 6 kHz low-pass plus a 4.5 kHz band-pass of Q 0.25 on each repeat ([Calf modules_delay.cpp](https://github.com/calf-studio-gear/calf/blob/master/src/modules_delay.cpp)). CHOW Tape supplies the best wow and flutter generator. Wow is a cosine at `4.5^rate − 1` Hz (0–3.5 Hz) plus an Ornstein-Uhlenbeck random process low-passed at 10 Hz. Flutter is three harmonically related cosines at f, 2f and 3f with amplitudes 230, 80 and 99 samples and phase offsets 0, 13π/4 and −π/10 ([WowProcess.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/WowProcess.cpp); [FlutterProcess.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/FlutterProcess.cpp)).

**Bucket-brigade character** in open source means the Holters and Parker model: an array of N buckets clocked at `2·N/delay`, with the input anti-alias filter and the output reconstruction filter expressed as parallel one-pole sections evaluated at the exact fractional clock-tick times. Two implementations exist, both using Juno-60 filter poles, with reference cutoffs of 9.9 kHz in and 9.5 kHz out ([chowdsp_BBDFilterBank.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_dsp_utils/Delay/BBD/chowdsp_BBDFilterBank.h); [string-machine bbd_filter.cpp](https://github.com/jpcima/string-machine/blob/master/sources/bbd/bbd_filter.cpp)). They disagree: chowdsp omits the real poles, its input residues differ, and one output residue pair has the opposite sign. The paper could not be opened to settle it, so that discrepancy must be resolved before a line-for-line port. ChowMatrix's working settings are 4096 stages with a 2 kHz filter and 0.85 make-up, or 16,384 stages with 9 kHz and 0.65 ([ChowMatrix VariableDelay.cpp](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Delay/VariableDelay.cpp)). Companding and clock noise are not modelled in any delay path read. A cheaper "analog" voice that keeps the tone and drops the clock aliasing is an ordinary interpolated delay with 2–4-pole low-passes whose cutoff falls as the delay lengthens, plus soft saturation (synthesis).

**Ducking** has exactly one source-backed design: Cocoa follows `|inL + inR|` with attack and release rates of about 100 ms and scales only the wet output, `wet *= 1 − min(1, duckAmount·follower)`, leaving the feedback alone ([CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp)). Tempo sync is a table of factors times the beat length 60/bpm: 1/16 = 0.25, 1/8 triplet = 1/3, 1/8 = 0.5, dotted 1/8 = 0.75, 1/4 = 1, dotted 1/4 = 1.5 ([ChowMatrix TempoSyncUtils.h](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Delay/TempoSyncUtils.h)).

**Micro-pitch widening** has one structure in every source: a circular buffer with two read taps half a window apart, moving at rate (1 − ratio) and crossfaded by a triangular or Hann window, with left shifted down and right shifted up. Mutable Instruments Clouds advances `phase += (1 − ratio)/size`, weights the taps `tri` and `1 − tri`, and uses a window of 128–2047 samples. mda Detune uses a Hann window, a default of about ±19 cents and a 1024-sample buffer. Airwindows Doublelay defaults to about −15.7 and +15.5 cents ([Clouds pitch_shifter.h](https://github.com/pichenettes/eurorack/blob/master/clouds/dsp/fx/pitch_shifter.h); [mdaDetuneProcessor.cpp](https://github.com/studiorack/mda/blob/master/source/mdaDetuneProcessor.cpp); [DoublelayProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Doublelay/DoublelayProc.cpp)). The shifter delays only the wet voices by about half a window, so the dry vocal stays undelayed. The Eventide H3000 reference value is about 9 cents up on one side and down on the other (secondary) ([Mix Online H3000 review](https://www.mixonline.com/technology/eventide-h3000-factory-plug-in-a-real-world-review)).

**The Juno-60 chorus** can be built cleanly from measurements. One triangle LFO drives two 256-stage lines with inverted modulation on the right. Mode I is 0.513 Hz and mode II 0.863 Hz, both sweeping 1.54–5.15 ms on the left and 1.51–5.40 ms on the right in stereo. Mode I+II is 9.75 Hz over 3.22–3.56 and 3.28–3.65 ms in mono. junox adds a 7237 Hz one-pole low-pass before the lines, 10,644 Hz low-passes after them and 44 % dry ([junox chorus.js](https://github.com/pendragon-andyh/junox/blob/master/src/junox/chorus.js); [Juno60 Chorus README](https://github.com/pendragon-andyh/Juno60/blob/master/Chorus/README.md)). Those delays are in flanger territory, which is why the effect reads as wide and glossy and not as detuned. For a thicker chorus the Surge settings (four voices, 15.6 ms, 0.25 Hz) are the better start ([Surge ChorusEffectImpl.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/ChorusEffectImpl.h)). No trustworthy open Dimension D exists: the hardware facts are secondary and no rate or delay numbers were found, so a "Dimension" mode would be tuned by ear.

**ADT** in Airwindows is two static short taps with polarity control and saturation (`B⁴·4790` samples, about 6.8 ms at the default), with no LFO. Its author's mono guidance is the useful part: an inverted short tap cancels bass, and two inverted taps cut bass "while averaging out the comb-filter effects" ([ADTProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/ADT/ADTProc.cpp); [Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)). A true Abbey-Road-style ADT, one 20–40 ms tap wobbled by a slow random LFO, is built from the tape-delay core with the CHOW wow generator (synthesis).

### EQ: matched minimum-phase sections remove cramping at no latency

Almost every open EQ still uses plain RBJ bilinear biquads, which are forced to 0 dB at Nyquist. At 48 kHz that is audible exactly where vocal "air" lives. A researcher ported each design to Python and measured the maximum error against the analog prototype from 20 Hz to 20 kHz (computed; formula sources: [chowdsp_CoefficientCalculators.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_filters/Utils/chowdsp_CoefficientCalculators.h), [ZamEQ2Plugin.cpp](https://github.com/zamaudio/zam-plugins/blob/master/plugins/ZamEQ2/ZamEQ2Plugin.cpp), [ivantsov filters.h](https://github.com/yIvantsov/ivantsov-filters/blob/main/filters.h)):

| Case at 48 kHz | RBJ bilinear | Vicanek | Orfanidis | Ivantsov (Omega) |
|---|---|---|---|---|
| Bell +6 dB, 8 kHz, Q 1.0 | 1.11 dB | 0.23 dB | 0.20 dB | 0.29 dB |
| Bell +6 dB, 12 kHz, Q 1.0 | 2.34 dB | 0.34 dB | 0.53 dB | 0.29 dB |
| Bell +6 dB, 16 kHz, Q 1.0 | 3.35 dB | 0.22 dB | 1.96 dB | 0.34 dB |
| High shelf +6 dB, 12 kHz, Q 0.707 | 0.88 dB | 0.08 dB (chowdsp-style) | not tested | 0.14 dB |
| Low-pass 12 kHz, Q 0.707 | 13.5 dB at 20 kHz | 0.82 dB | not tested | 0.59 dB |
| High-pass 100 Hz, Q 0.707 | 0.000 dB | 0.000 dB | not tested | 0.000 dB |

The practical choice is a matched minimum-phase biquad computed in f64 at control rate: zero latency and one biquad of CPU. Oversampling is the wrong tool, since a 2× bilinear EQ still cramps one octave higher and needs anti-alias filters for a process that is linear. The Vicanek peaking design, as implemented in chowdsp_utils (GPL-3.0, so re-derive it from the published paper), keeps the analog poles and fits the numerator at three frequencies:

```
w0 = 2π·fc/fs ; q = 1/(2Q)
a1 = −2·e^(−q·w0)·cos(sqrt(1−q²)·w0)      (cosh(sqrt(q²−1)·w0) if q > 1)
a2 = e^(−2q·w0)
φ1 = sin²(w0/2) ; φ0 = 1 − φ1 ; φ2 = 4·φ0·φ1
A0 = (1+a1+a2)² ; A1 = (1−a1+a2)² ; A2 = −4·a2
peaking, G ≥ 1 linear, prototype (s² + G·s/Q + 1)/(s² + s/Q + 1):
  R1 = (A0φ0 + A1φ1 + A2φ2)·G² ; R2 = (−A0 + A1 + 4(φ0−φ1)A2)·G²
  B0 = A0 ; B2 = (R1 − R2·φ1 − B0)/(4φ1²) ; B1 = R2 + B0 + 4(φ1−φ0)·B2
  W = (√B0 + √B1)/2 ; b0 = (W + sqrt(W² + B2))/2 ; b1 = (√B0 − √B1)/2 ; b2 = −B2/(4·b0)
cuts: design the boost 1/G and swap numerator and denominator
```

chowdsp clamps Q to [0.1, 30) and silently falls back to the bilinear design below 1 kHz, where the two are indistinguishable anyway ([chowdsp_VicanekHelpers.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_filters/Utils/chowdsp_VicanekHelpers.h)). Calling it with pole Q = Q·A and gain A² (A = 10^(dB/40)) gives the familiar symmetric boost/cut convention. If one uniform, permissively licensed code path is preferred, Ivantsov's design with Omega correction stayed within 0.35 dB on every bell and shelf tested and within about 0.6 dB on the high-pass and low-pass cases, needs only square roots and one `tan`, has an MIT reference, and is the only one of the four that accepts corner frequencies above Nyquist ([ivantsov filters.h](https://github.com/yIvantsov/ivantsov-filters/blob/main/filters.h)). Orfanidis covers bells only and is the weakest for wide bells near Nyquist.

Below about 1 kHz, and for anything modulated, use the Simper trapezoidal state-variable filter, available as an MIT/Apache Rust crate:

```
g = tan(π·fc/fs) ; k = 1/Q ; a1 = 1/(1 + g·(g + k)) ; a2 = g·a1 ; a3 = g·a2
v3 = v0 − ic2eq ; v1 = a1·ic1eq + a2·v3 ; v2 = ic2eq + a2·ic1eq + a3·v3
ic1eq = 2·v1 − ic1eq ; ic2eq = 2·v2 − ic2eq ; out = m0·v0 + m1·v1 + m2·v2
bell:       A = 10^(dB/40), k = 1/(Q·A),          m0 = 1,  m1 = k·(A² − 1),   m2 = 0
low shelf:  g = tan(π·fc/fs)/√A,                  m0 = 1,  m1 = k·(A − 1),    m2 = A² − 1
high shelf: g = tan(π·fc/fs)·√A,                  m0 = A², m1 = k·(1 − A)·A,  m2 = 1 − A²
high-pass:  out = v0 − k·v1 − v2
```

([simper-filter lib.rs](https://docs.rs/simper-filter/0.1.1/src/simper_filter/lib.rs.html)). The precision argument is measured, not theoretical: an f32 direct-form high-pass at 30 Hz and 48 kHz carries round-off noise at about −84 dBFS and worsens to −62 dBFS for 20 Hz at 192 kHz, while the same filter as an f32 state-variable filter stays between about −109 and −118 dBFS (computed). Keep filter state in f64, smooth parameters over 10–20 ms, recompute coefficients every 16–32 samples and set flush-to-zero on the audio thread. x42 fil4 ramps coefficients per sample and limits each parameter to a factor-of-two change per call, and EQ1979 low-passes its gains at 10 Hz and recomputes every sample ([fil4 filters.h](https://github.com/x42/fil4.lv2/blob/master/src/filters.h); [EQ1979 jsfx](https://github.com/D4p0up/eq1979/blob/main/bellesondes_eq1979.jsfx)).

**The air band** is the one place a vocal EQ needs a corner at or above Nyquist. Luftikus, the MIT Maag-EQ4-style plugin, solves it with pre-computed per-rate tables. A pole/zero analysis of those tables shows each air setting is a first-order high-pass summed with the dry signal, whose pole is `exp(−2π·fc/fs)` with fc = 1989, 3979, 7958, 16,931 and 36,172 Hz for the settings labelled 2.5, 5, 10, 20 and 40 kHz (computed from [Luftikus coeffcreator.h](https://github.com/lkjbdsp/lkjb-plugins/blob/master/Luftikus/Source/dsp/coeffcreator.h)). That pole rule is valid for any fc, which the bilinear transform is not. A matched one-pole shelf reproduces the curve at any sample rate: with the corner at 40 kHz and fs = 48 kHz, a +10 dB shelf stays within 0.16 dB (Vicanek one-pole) or 0.35 dB (Ivantsov, uncorrected warp) of the analog shelf (computed). The audible effect is the lower skirt of a 6 dB/octave shelf that is still rising at 20 kHz: an analog +10 dB shelf at 40 kHz lifts only +0.19 dB at 5 kHz but +2.20 dB at 20 kHz, so most of the boost lands above the 5–8 kHz sibilance band. Sound On Sound heard the hardware "enhance the breathiness and detail, but without adding any hint of harshness" ([SOS Maag EQ4M review](https://www.soundonsound.com/reviews/maag-audio-eq4m)). The band must therefore be first-order, boost-only, and never forced flat at Nyquist. Luftikus sums its bands in parallel with the dry path, which raises the whole spectrum as the hardware does; a series shelf with unity DC gain is the safer default ahead of a compressor (synthesis).

**The Pultec low end reduces exactly to one biquad.** The GPL-3.0 wave-digital model EQP-WDF-1A gives the component values, and a researcher derived closed forms from its topology that match a direct impedance evaluation to 4e-9 dB (computed from [EQP1A.h](https://github.com/ABSounds/EQP-WDF-1A/blob/main/Source/EQP1A.h) and [EQP1A.cpp](https://github.com/ABSounds/EQP-WDF-1A/blob/main/Source/EQP1A.cpp)):

```
LF boost + attenuate:  Rb = boost·8.2k ; Rc = atten·110k
  C2 = 2.2µF (20 Hz), 1.1µF (30), 560nF (60), 330nF (100) ; C1 = C2/30 ; τ1 = C1·Rc ; τ2 = C2·Rb
  N(s) = 1e7·τ1τ2·s² + (1e7·(τ1+τ2) + Rb·12e3·τ1)·s + (1e7 + Rb·(12e3 + Rc))
  D(s) = 155e6·τ1τ2·s² + (155e6·(τ1+τ2) + 13e3·Rc·τ2 + Rb·12e3·τ1)·s + (155e6 + 13e3·Rc + Rb·(12e3 + Rc))
  H(s) = 15.4882·N(s)/D(s)            → bilinear transform (all poles and zeros are real, below ~1.5 kHz)
HF boost: Z0 = 3464.1 Ω ; Rq = 390 + bandwidth·3900 ; Rh = boost·12000 ; Rs = (1−boost)·12000 + 916.67
  Qz = Z0/(Rq + Rh) ; Qp = Z0/(Rq + Rs·Rh/(Rs+Rh)) ; peaking biquad with Q = Qp, G = Qp/Qz
HF attenuate: first-order ; at full cut a one-pole low-pass at 692 / 1384 / 2748 Hz for the 5k / 10k / 20k settings
```

With boost and attenuation both at maximum, the model gives a low shelf of about +15.6 dB plus a dip of −6.5 dB at 554 Hz on the 60 Hz setting, and the high boost at maximum is +20 dB at Q ≈ 2.8 sharp, falling to +10 dB at Q ≈ 0.6 broad. Both agree with Sound On Sound's measurements of "a low-frequency boost with a cut about an octave higher" and a 9 dB gain difference between narrow and broad ([SOS Pultec EQP-1A review](https://www.soundonsound.com/reviews/pulse-techniques-eqp-1a)). The model has no tube or transformer saturation and no roll-off below 20 Hz.

**No open circuit model of a Neve, API or SSL EQ exists.** The only open 1073-style source is EQ1979, a GPL-3.0 curve-fit of about 30 RBJ sections. Its useful constants are a bell Q that rises with gain (`Q = 0.22 + |g|/60` for the lower positions, steeper for the top two), top centres that slide down with gain, and a "12 kHz" shelf modelled as a Q 0.35 shelf centred at 2 kHz with a compensating peak at 820 Hz ([EQ1979 jsfx](https://github.com/D4p0up/eq1979/blob/main/bellesondes_eq1979.jsfx)). dusk-audio's "British" mode is similar heuristics, and its "AnalogMatchedBiquad" still lists "H(Nyquist) = 0 dB" in its own comment, so it corrects bandwidth warping only ([dusk AnalogMatchedBiquad.h](https://github.com/dusk-audio/dusk-audio-plugins/blob/main/plugins/multi-q/AnalogMatchedBiquad.h)). Ship these as "console-style" characters, not as verified hardware models.

### Dynamics: one gain computer; character comes from where the smoothing sits

The dynamics notes end before their design section and before any source-level treatment of de-essers, gates and limiters. What they do contain is enough to build the compressors with confidence. Open code shows that character comes from four choices: feed-forward versus feedback detection; whether smoothing acts on the level, on the dB gain reduction or on the linear gain; whether time constants depend on the amount of gain reduction; and the shape of the static curve.

The static curve is the Giannoulis-Massberg-Reiss soft knee, coded identically by three independent projects that cite the paper. With overshoot `o = x_dB − T`, knee width `W` and slope `s = 1/R − 1`, the gain reduction is 0 for `o ≤ −W/2`, `s·(o + W/2)²/(2W)` inside the knee, and `s·o` above it ([CTAGDRC GainComputer.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/GainComputer.cpp); [Squeezer side_chain.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/side_chain.cpp)). The one-pole coefficient is `α = exp(−1/(τ·fs))`. Two detectors smooth it. The branching detector uses the attack coefficient when the control signal moves toward more reduction and the release coefficient otherwise. The decoupled detector computes `y1 = max(c, αR·y1 + (1−αR)·c)` and then `y = αA·y + (1−αA)·y1`, so the attack filter also smooths release ripple ([CTAGDRC LevelDetector.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/LevelDetector.cpp)). CTAGDRC's author places the smoothing after the gain computer so the filter "does not have to operate on the whole dynamic range of the input signal" ([CTAGDRC README](https://github.com/p-hlp/CTAGDRC/blob/HEAD/README.md)).

ZL Compressor's four styles, read for the idea only because the code is AGPL, show how cheaply one code path becomes four compressors: Clean is feed-forward with the follower on dB reduction; Classic is feedback, taking its detector input from the previous output sample; Optical is feed-forward with the follower on the linear level before the dB conversion; Vocal is feedback with the follower on linear gain ([ZL styles](https://github.com/ZL-Audio/ZLCompressor/tree/HEAD/source/dsp/compressor/styles)). Squeezer switches topology the same way, by taking the side-chain sample from the input or from the previous output ([Squeezer compressor.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/compressor.cpp)).

**FET (1176-style).** No open, licensed, circuit-level 1176 model was found; Squeezer's "FET" stage is a pass-through and Julius Smith's Faust preset is a plain feed-forward compressor with 1176 numbers ([Squeezer gain_stage_fet.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/gain_stage_fet.cpp); [Faust compressors.lib](https://github.com/grame-cncm/faustlibraries/blob/HEAD/compressors.lib)). The behaviour to copy is documented by Universal Audio: attack from 20 to 800 microseconds, release from 50 ms to 1.1 s, ratios 4, 8, 12 and 20, and an Input knob that "simultaneously sets the threshold level ... as well as the amount of signal entering" ([UA 1176 tips](https://www.uaudio.com/blogs/ua/1176-collection-tips)). The aggression follows from feedback detection plus an attack shorter than one audio cycle plus fast release: UA says of the fastest settings that "minute level fluctuations sound like distortion". A researcher derived the digital loop mathematics (computed, not from a source): with a one-sample-delayed feedback detector the loop pole is `1 − (1−α)·R`, so the loop is stable only if `(1−α)·R < 2` and free of ringing only if `(1−α)·R ≤ 1`, and the effective attack is R times faster than the nominal time constant. At 48 kHz one sample is 20.8 µs, so the 1176's fastest attack is one sample, and a 20 µs nominal attack at 20:1 is unstable unless the coefficient is divided by R. The harmonic colour of a FET stage is not specified by any verified constant in the notes.

**Opto (LA-2A-style).** UA documents a ratio of "roughly 3:1", an attack of 10 ms, and a release of "about 60 milliseconds for 50% of the release, and anywhere from 1 to 15 seconds for the rest" ([UA LA-2A tips](https://www.uaudio.com/blog/la-2a-collection-tips-tricks/)); UA's product specification gives "0.5 to 5 seconds for complete release", and the two ranges conflict ([UA LA-2A product page](https://www.uaudio.com/products/teletronix-la-2a-classic-leveling-amplifier)). The open model is Squeezer's optical stage (GPL-3.0-or-later), a second branching one-pole on the dB gain reduction whose time constants depend on the current reduction: `resistance = 480/(3 + GR_dB)`, `attack_ms = resistance/10`, `release_ms = resistance`, with coefficients `exp(ln(0.27)/(t·fs))`. That gives 16/160 ms at 0 dB of reduction and 3/32 ms at 12 dB, so release is fast while reduction is deep and slows as it approaches zero ([Squeezer gain_stage_optical.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/gain_stage_optical.cpp)). A first stage that halves in 60 ms has τ ≈ 87 ms; a two-state version with a slow "memory" envelope matches the described behaviour more literally (synthesis). The LA-2A's Emphasis control is the analog precedent for a side-chain high-pass.

**Leveller and vari-mu.** x42 darc (GPL-2.0-or-later) is a zero-latency RMS leveller with an infinitely soft knee and built-in loudness-stable make-up:

```
v = (g_in·x)²                       p_thr = 0.5·10^(T_dB/10)
za1 += w_att·(p_thr + v − za1)      w_att = 0.5/(fs·attack_s)
zr1 = (zr1 < za1) ? za1 : zr1 − w_rel·zr1          w_rel = 3.5/(fs·release_s)
zr2 = (zr2 < za1) ? za1 : zr2 + w_rel·(zr1 − zr2)
gain = g_in·exp(−r·ln(20·zr2))      r = 0.5·(1 − 1/R)
```

Because the threshold power is added to the signal power before the logarithm, the curve has no branch. Make-up is built in: the README says it is set "to retain equal loudness at −10 dBFS/RMS", and from the code the gain is exactly 0 dB whenever threshold power plus signal power equals 0.05 (computed). Its hold option freezes release while the signal is under threshold, which "prevents modulation of the noise-floor" ([darc lv2.c](https://github.com/x42/darc.lv2/blob/HEAD/src/lv2.c); [darc README](https://github.com/x42/darc.lv2/blob/HEAD/README.md)). Airwindows Pressure4 (MIT), which its author calls "the golden ear favorite", is the character alternative. Two gain cells update on alternate samples; above threshold `coef = (coef·(att − 1) + target)/att` with `target = max(threshold/|x|, threshold)`; the ballistics slow as level rises through `speed = (speed·(speed − 1) + |x|·release + fastest)/speed`; and the "mewiness" control blends `coef` toward `coef²`, which steepens the ratio as reduction deepens, the vari-mu behaviour. A sine soft clip finishes it ([Pressure4Proc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/Pressure4/Pressure4Proc.cpp)).

**Auto make-up** should be static. CTAGDRC averages the actual gain reduction and its author warns that this "may introduce unwanted volume changes", which in headphones raises breaths and noise during pauses. Squeezer applies half of the static reduction a full-scale signal would get, and chowdsp applies all of it at a target level ([Squeezer side_chain.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/side_chain.cpp); [chowdsp_GainComputerImpls.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/HEAD/modules/dsp/chowdsp_compressor/Compressor/chowdsp_GainComputerImpls.h)). The researchers' recommended law for a single amount knob (synthesis) is `makeup_dB = k·GR_static(L_pivot)` with a pivot near −12 dBFS peak and k starting at 0.7, smoothed over 20–50 ms and never driven by programme content.

**Time constants do not port between code bases.** The same "10 ms" means the time to 63 % in CTAGDRC, chowdsp, Faust and ZamComp; to 90 % in Squeezer (τ = t/2.303); to 70.7 % in LSP (τ = t/1.228); 2π·τ in ZL (τ = t/6.283); and about 4τ in Calf's stereo compressor. Store every time as a true τ in seconds and convert ported presets. Code with hard-wired per-sample constants is not rate-independent: the stmlib limiter uses fixed slopes of 0.05 up and 0.00002 down, and CTAGDRC's make-up smoothing is per block ([stmlib limiter.h](https://github.com/pichenettes/stmlib/blob/HEAD/dsp/limiter.h); [LSP Compressor.cpp](https://github.com/lsp-plugins/lsp-dsp-units/blob/HEAD/src/main/dynamics/Compressor.cpp)).

**Low-frequency distortion without look-ahead** is controlled four ways, all present in open code: a 2nd-order side-chain high-pass (Squeezer, Q 0.707), decoupled or two-stage release smoothing, power detection, and hold. UA states the mechanism: "If a cycle at 100 Hz lasts 10 ms, then a 1 ms attack time will have time to alter the waveform" ([UA compression basics](https://www.uaudio.com/blogs/ua/audio-compression-basics)). The researchers' recipe (synthesis) is a side-chain high-pass at 100–150 Hz on by default, decoupled smoothing, a release floor of 30 ms in clean modes, and a 5–10 ms hold on the gain-reduction peak; shorter values are allowed only in the FET character, where the distortion is the point.

**De-esser, gate and limiter** are covered only in fragments. For de-essing, Airwindows DeEss "works by tracking slew rates, not by filtering and frequencies", but slew detectors scale with sample rate and the code compensates only partly ([Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/HEAD/Airwindopedia.txt); [DeEssProc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/DeEss/DeEssProc.cpp)). A band-energy de-esser is rate-independent by construction, and Sound On Sound gives its recipe: sibilance is "usually focused somewhere in a region from 4-10kHz", the side-chain is high-passed "at around 4kHz", and most de-essers are "a single band of dynamic EQ" ([SOS: vocal de-essing](https://www.soundonsound.com/techniques/techniques-vocal-de-essing)). For gating, LSP re-arms a hold counter on every new envelope peak, and ZamGate uses a linear ramp instead of an exponential ([LSP Compressor.cpp](https://github.com/lsp-plugins/lsp-dsp-units/blob/HEAD/src/main/dynamics/Compressor.cpp); [ZamGatePlugin.cpp](https://github.com/zamaudio/zam-plugins/blob/HEAD/plugins/ZamGate/ZamGatePlugin.cpp)). For limiting, the zero-latency candidates are Nathan Ho's public-domain safety limiter, which holds its gain for 100 ms after each peak and then releases over 100 ms with `k = 0.001^(1/(t·fs))`, and the stmlib limiter; x42 dpl and the Faust `limiter_lad` are look-ahead designs and do not qualify ([safety_limiter.hpp](https://github.com/nhthn/safety-limiter/blob/HEAD/safety_limiter.hpp); [x42 dpl](https://github.com/x42/dpl.lv2)). Airwindows ClipOnly2 adds one sample of latency at 44.1 and 48 kHz ([ClipOnly2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/ClipOnly2/ClipOnly2Proc.cpp)).

### Colour: short chains of filter, curve and memory, run through a 0.07 ms oversampler

Each analog character in open code is a short chain of a filter, a memoryless curve and a small amount of memory such as slew or hysteresis. Airwindows is the lowest-risk source to port because it is MIT and written as plain per-sample C++ with no framework. The researchers found no trustworthy ranking of these on vocals. The one explicit vocal statement is Chris Johnson's that Weave "became the default saturation in my video-making vocal chain", and Weave's code was not read ([Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)).

**Harmonics decide the names.** A researcher drove a 220 Hz sine through each static curve exactly as coded and measured the harmonics (computed). Every symmetric curve (tanh, Airwindows Spiral, Mojo, TapeHack, the unbiased Jiles-Atherton solver) produces odd harmonics only. Even-order "warmth" appears only when the curve is asymmetric.

| Curve at −18 / −12 / −6 dBFS input | 2nd harmonic | 3rd harmonic |
|---|---|---|
| tanh(2x)/2 (reference) | none | −45.7 / −34.1 / −23.5 dB |
| Airwindows Spiral, `sin(x·abs(x))/abs(x)` (Channel9) | none | −89.8 / −65.8 / −41.8 dB |
| Airwindows Tube2 asymmetric stage, Tube = 1.0 | −44.7 / −35.4 / −25.9 dB | −45.2 / −39.0 / −32.5 dB |
| TAP TubeWarmth as ported in Calf, "tube" blend | −30.8 / −25.7 / −21.1 dB | −40.4 / −35.8 / −31.9 dB |
| CHOW Tape Jiles-Atherton, drive 0.5 | none | −44.7 / −39.3 / −31.7 dB |

Spiral is essentially clean until pushed, which is why Channel9 sounds clean until driven. The tape solver's third harmonic rises only 5–8 dB per 6 dB of input, against about 11 dB for tanh, with nearly constant fundamental gain: distortion that is present at low level and grows gently, the "soft compression" signature. The TAP row assumes the unread macro `D(x)` is `sqrt(|x|)`.

**Tube.** Airwindows Tube2 runs an asymmetric stage that "flattens the bottom and points the top", then the Tube polynomial, then a slew-dependent stage ([Tube2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Tube2/Tube2Proc.cpp)):

```
powerfactor = int(9·(1−B)) + 1 ; gainscaling = 1/(powerfactor+1) ; outputscaling = 1 + 1/powerfactor
x = clamp(x·A, −1, 1) ; x /= powerfactor
s = −x ; s = (s > 0) ? 1 + sqrt(s) : 1 − sqrt(−s) ; x −= x·|x|·s·0.25 ; x *= powerfactor      // even harmonics
factor = x^(powerfactor+1), made odd-symmetric ; x = (x − factor·gainscaling)·outputscaling    // Tube curve
slew = prev − x ; prev = x ; slew = (slew > 0) ? 1 + sqrt(slew)·0.5 : 1 − sqrt(−slew)·0.5
x −= x·|x|·slew·gainscaling ; x = clamp(x, −0.52, 0.52)·1.923076923076923
```

A plain bias offset into tanh gives a much stronger second harmonic (−27 dB already at −18 dBFS) and a DC shift, so any asymmetric curve needs a DC blocker after it. The physical alternative is a static 12AX7 table from the Koren equation with Guitarix's parameters (mu 100, kx 1.4, kg1 1060, kp 600, kvb 300), under GPL-2.0-or-later ([Guitarix tube_transfer.py](https://github.com/brummer10/guitarix/blob/master/trunk/tools/tube_transfer.py)).

**Console.** Airwindows Channel9 is a signal-modulated high-pass, a curve that morphs with one knob, and a slew clamp, between two ultrasonic low-passes ([Channel9Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Channel9/Channel9Proc.cpp)):

| Voicing | High-pass coefficient @ 44.1 kHz | Slew threshold per sample | Ultrasonic low-pass |
|---|---|---|---|
| Neve | 0.005832 | 0.33362176 | 28,811 Hz |
| API | 0.004096 | 0.59969536 | 27,216 Hz |
| SSL | 0.004913 | 0.84934656 | 23,011 Hz |
| Teac | 0.009216 | 0.149 | 18,544 Hz |
| Mackie | 0.011449 | 0.092 | 19,748 Hz |

```
x = lowpassA(x)                                  // Q 1.618, skipped when cutoff/fs ≥ 0.5
scale = |1 − x/nonLin| , nonLin = 5 − density    // "dielectric" high-pass: coefficient follows the signal
iir = iir·(1 − c·scale) + x·c·scale ; x −= iir   // c = coefficient/(fs/44100), two states on alternate samples
dry = x ; x = clamp(x, −1, 1) ; phat = sin(x·π/2)
x *= 1.2533141373155 ; spiral = sin(x·|x|)/|x|
out = dry·(1−density) + spiral·density           // Drive 0…50 %: density = 2·Drive
out = out·(1−phattity) + phat·phattity           // Drive 50…100 %: phattity = 2·Drive − 1
golden-ratio three-point slew clamp at the voicing threshold ; lowpassB (Q 0.618)
```

The knob changes the curve shape and never the input gain, which makes Channel9 the most level-stable design read; it needs only a fixed trim. The researchers computed (approximately) that the Neve voicing's slew clamp begins acting on a full-scale sine above about 2.5 kHz at 48 kHz, against 4.6 kHz for API and 6.5 kHz for SSL, so "Neve" rounds loud sibilance earliest. The slew threshold is per sample and is not rate-scaled in Channel8 or 9, so inside a 2× oversampler it should be halved; whether that reproduces the 48 kHz sound exactly is untested. No open, measured model of a Neve or API transformer was found. Airwindows Coils2 distorts everything outside a clean 600 Hz band and ToTape8 saturates its low band with `sin()`; both are stylised ([Coils2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Coils2/Coils2Proc.cpp)).

**Tape.** The lightweight route is the ToTape6/8 core without its flutter delay line and without ClipOnly2 ([ToTape6Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/ToTape6/ToTape6Proc.cpp); [ToTape8Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/ToTape8/ToTape8Proc.cpp)):

```
mid = onepole_lowpass(x) ; Highs = x − mid ; Lows = mid
Highs −= sgn(Highs)·(1 − cos(min(|Highs|·π/2, π/2)))        // HF self-compression: bites only on loud sibilance
Lows  = sin(clamp(Lows, −π/2, π/2))
hb += Lows·headBumpDrive ; hb −= hb³·(0.0618/sqrt(fs/44100)) // head-bump integrator
bump = bandpassB(bandpassA(hb))                              // Q 0.618, fA = H²·175 + 25 Hz (68.75 Hz default), fB = 0.9375·fA
out = Lows + Highs + bump·headBumpMix
```

The high-band term is quadratic at low level, so it works as a built-in de-esser. The physical route is CHOW Tape's Jiles-Atherton hysteresis: `M_s = 0.5 + 1.5·(1 − sat)`, `a = M_s/(0.01 + 6·drive)`, `c = sqrt(1 − width) − 0.01`, `k = 0.47875`, `alpha = 1.6e-3`, solved per sample by RK2 at 2× oversampling, with make-up `(1 + 0.6·width)/(0.5 + 1.5·(1 − sat))` and a 35 Hz DC blocker ([HysteresisOps.h](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Hysteresis/HysteresisOps.h); [HysteresisProcessor.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Hysteresis/HysteresisProcessor.cpp)). CHOW's play-head loss filter is a linear-phase FIR with a latency of half its order, so it cannot sit in a monitoring path; use the head-bump peak filter and a minimum-phase shelf instead ([LossFilter.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Loss_Effects/LossFilter.cpp)).

**Exciter.** Surge's Exciter (GPL-3.0-or-later) is the Aphex topology: a 2-pole high-pass at `500·20^tone` Hz, a diode-rectifier level detector `r = 5·(exp((0.05/0.0259)·x) − 1)` with one-pole attack and release, then `tanh(x)·level`, added to an untouched dry path with `drive = 8·knob^1.5·0.2^(1 − tone)` ([Surge ExciterEffect.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/ExciterEffect.cpp)). Airwindows Focus is the MIT alternative: a band-pass fixed at 3515.775 Hz, boosted up to 12 dB and shaped, with the rest of the signal passed clean ([FocusProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Focus/FocusProc.cpp)). The cleanest colour of all is Airwindows PurestDrive, `s = sin(x); apply = |prevS + s|/2·intensity; y = x·(1 − apply) + s·apply`, which saturates less on bright, quiet and alternating-polarity content and needs no oversampler ([PurestDriveProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/PurestDrive/PurestDriveProc.cpp)).

**Anti-aliasing.** The right tool under a live constraint is 2× or 4× oversampling with minimum-phase polyphase half-band IIR filters in the HIIR design (WTFPL). Each coefficient is a first-order allpass `y[n] = a·(x[n] − y[n−1]) + x[n−1]` at the low rate; even-indexed coefficients form one path and odd-indexed the other ([HIIR mirror](https://github.com/unevens/hiir)). A researcher compiled the HIIR designer and generated coefficients for a 48 kHz base rate flat to 20 kHz (computed):

| Stage | Coefficients | Stop band | Round-trip delay at 1 / 10 kHz |
|---|---|---|---|
| 48↔96 kHz, n = 5 | 0.061090700071086, 0.221065199762536, 0.430463831503146, 0.650964800633457, 0.876656677083713 | 80.6 dB | 56 / 69 µs |
| 48↔96 kHz, n = 6 | 0.044181909085212, 0.164188859726300, 0.330744161707643, 0.515086942508888, 0.702052852077365, 0.894889642203568 | 96.4 dB | 67 / 81 µs |
| 96↔192 kHz, n = 2 | 0.126620435698744, 0.565795715233128 | 70.9 dB | 16 / 17 µs |
| 96↔192 kHz, n = 3 | 0.063787836824299, 0.266780962497159, 0.668548793183610 | 101.7 dB | 22 / 23 µs |

A complete 4× chain (n = 6 then 3) delays 89 µs at 1 kHz, about 4.3 samples. In the researcher's worst test, a 5 kHz sine at −6 dBFS with 18 dB of drive into tanh, aliasing measured −25 dB with no protection, −58 dB at 2×, −78 dB at 2× with first-order ADAA inside, and −110 dB at 4×. At vocal-level drive even the naive curve is 66 dB or more down, so 2× suffices for the gentle characters and the extra belongs on the exciter. First-order antiderivative anti-aliasing, `y = (F1(x[n]) − F1(x[n−1]))/(x[n] − x[n−1])` with `F1 = ln cosh x` for tanh, adds half a sample of delay and a droop of about −2.6 dB at 20 kHz when run at 48 kHz, so it belongs inside the 2× stage; the second-order form "will always add exactly one sample of latency" ([ADAA1.h](https://github.com/jatinchowdhury18/ADAA/blob/master/src/ADAA/ADAA1.h); [chowdsp_ADAAWaveshaper.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_waveshapers/Waveshapers/chowdsp_ADAAWaveshaper.h)). Stateful stages such as the tape solver and slew clamps cannot use it at all. Any dry/wet blend must happen inside the oversampled domain, or an undelayed dry copy combs against the wet path near 8.9 kHz (computed).

A researcher's scalar C++ benchmark on a 2.1 GHz virtual-machine core gives the order of cost per sample at 48 kHz (computed): 2× HIIR plus tanh 38 ns (0.18 % of a core), 4× plus tanh 79 ns (0.38 %), and 2× plus the Jiles-Atherton RK2 solver 316 ns (1.5 %). A 64-sample period is 1333 µs.

### Pitch: only a zita-at1 port fits a monitoring chain, and only as an option

The open, purpose-built vocal tuners are zita-at1, read through x42's fat1.lv2, and Autotalent with its refactor TalentedHack; all are GPL-2.0-or-later. zita's detector takes 2048 base-rate samples under a Hann window, forms an FFT autocorrelation with a 3 kHz roll-off applied to the power spectrum, normalises out the window's own autocorrelation, accepts lags for 60–1200 Hz, requires a normalised peak above 0.8 and refines parabolically. It estimates every 512 samples (10.7 ms at 48 kHz). Its retuner resamples the input at the required ratio with 4-point cubic interpolation and, at each 128-sample fragment boundary, jumps forward or back by a whole number of pitch periods with a raised-cosine crossfade. The correction error is smoothed by a one-pole (`_corrfilt = (4·_frsize)/(v·fs)`, v = 0.02–0.5 s) and jumps on a note change; a 12-bit note mask selects the scale, and a bias term gives about 0.46 semitone of hysteresis toward the previous note ([fat1 retuner.cc](https://github.com/x42/fat1.lv2/blob/master/src/retuner.cc); [fat1 retuner.h](https://github.com/x42/fat1.lv2/blob/master/src/retuner.h)).

| Engine at 48 kHz | Added latency | Formants |
|---|---|---|
| zita-at1 / fat1, normal | 1056 samples = 22.0 ms | Shift with pitch |
| fat1 "Fast" mode | 160 samples = 3.33 ms nominal | Shift with pitch |
| Autotalent / TalentedHack | 2047 samples = 42.6 ms | Optional lattice corrector; TalentedHack's README says "The formant corrector is broken" |
| Rubber Band live shifter | "50ms or more" | Preserved option |
| Signalsmith Stretch (MIT) | 120 ms default block | Compensation "not a sharp as monophonic algorithms" |

Sources: [fat1.cc](https://github.com/x42/fat1.lv2/blob/master/src/fat1.cc), [autotalent.c](https://github.com/ederwander/PyAutoTune/blob/master/autotalent.c), [TalentedHack readme](https://github.com/jeremysalwen/TalentedHack/blob/master/readme.md), [RubberBandLiveShifter.h](https://github.com/breakfastquay/rubberband/blob/default/rubberband/RubberBandLiveShifter.h), [signalsmith-stretch](https://github.com/Signalsmith-Audio/signalsmith-stretch). Fast mode outputs the signal before the pitch has been computed, "resulting in a lower latency at the cost of a small delay between the correction and the pitch analysis". From the jump logic the researcher derived (computed, not measured) that the real delay wanders by up to one pitch period while a correction is active, roughly 1.3–6.3 ms for a 200 Hz note and 1.3–13.8 ms for an 80 Hz note, and that the pitch decision still trails the voice by about 20–30 ms. That matches Sound On Sound's report that Waves Tune Real-Time's latency "varies between 0 and 4 ms depending on the frequency of the current note" ([SOS: Waves Tune Real-Time](https://www.soundonsound.com/reviews/waves-tune-real-time)). No detector can respond to a new low note faster than about two periods, 25 ms at 80 Hz. Formant-preserving shifts and harmonies have no open method near zero latency. The port is about 500 lines of C++ plus one 2048-point FFT; write a new 2× upsampler instead of copying the embedded resampler, whose licence header was not inspected.

## The chain to build: fixed order, a handful of types, tempo-aware presets

Everything in this section is synthesis: a design assembled from the cited sources, not a tested product.

### Module order and where mono becomes stereo

Open strips, commercial suites and documented engineer chains agree on a stable pattern: level and clean-up first, then pitch, de-essing, corrective EQ, one or two compressors, tonal EQ, saturation, and time-based effects on parallel sends. Sound On Sound's reference chain is gate → de-esser → compressor → compressor → EQ → tube distortion, on the grounds that "compression tends to emphasise frequencies that already dominate a sound", so "it's best to place [the de-esser] before any standard compressor" ([SOS: Vocal Processing](https://www.soundonsound.com/techniques/vocal-processing)). A hip-hop engineer's chain boosts the top first and de-esses the result ([SOS Inside Track](https://www.soundonsound.com/techniques/inside-track-future-draco)). iZotope Nectar 4 puts its Auto-Level module "at the start of the signal chain" ([SOS: Nectar 4 review](https://www.soundonsound.com/node/4931710)), and −18 dBFS is the common internal reference level ([iZotope: gain staging](https://www.izotope.com/en/learn/gain-staging-what-it-is-and-how-to-do-it.html)). The strip should fix this order and not expose routing. The earlier research in this project placed the de-esser between the two compressors and a preamp colour stage first; the newer notes win, so the de-esser moves ahead of compression and colour sits after the tone EQ.

| # | Module | What it is built from | Default | Added latency |
|---|---|---|---|---|
| 1 | Input trim + auto-level | Slow gated RMS rider to −18 dBFS, limited range, frozen below a noise floor | On, ±6 dB | 0 |
| 2 | High-pass | Simper state-variable filter, 12 dB/oct (18 dB/oct in Console character) | 80 Hz | 0 |
| 3 | Expander | Downward expander with open/close hysteresis and hold | −50 dBFS, 1:2, range 10 dB | 0 |
| 4 | Tune (optional) | zita-at1 retuner port, Fast mode, key-driven note mask | Off | 160 samples (3.33 ms) nominal when on |
| 5 | De-esser A | Band-energy split-band design | 6–7 kHz, light | 0 |
| 6 | Corrective EQ | Mud bell (state-variable below 1 kHz) | −2 dB at 300 Hz | 0 |
| 7 | Compressor A | FET character | 4:1, 3–5 dB on peaks | 0 |
| 8 | Compressor B | Opto character | about 3:1, 2–3 dB | 0 |
| 9 | Tone EQ (+ optional light De-esser B) | Low shelf, matched presence bell, first-order air shelf, tilt | Flat | 0 |
| 10 | Colour | Clean / Tube / Console / Tape / Exciter, with parallel mix | Clean, low | 0 (Clean) or about 3–4 samples (oversampled) |
| 11 | Width | Micro-pitch / Juno chorus / ADT, wet-only | Off | 0 on the dry voice |
| 12 | Sends | Delay → Reverb, returns filtered and ducked from the dry vocal | Plate, low | 0 on the dry voice |
| 13 | Output | Static make-up, safety limiter, soft clip | Ceiling −1 dBFS | 0 |

The six EQ controls appear to the singer as one panel but sit at two positions: the high-pass and mud bell before compression, and the low shelf, presence bell, air shelf and tilt after it. That resolves the EQ-before-or-after debate structurally, since corrective cuts belong before and tonal boosts after. The signal stays mono through module 10 and becomes stereo at module 11: width voices, delay taps and reverb outputs are stereo, and the dry voice stays in the centre with no delay. Effect sends are taken after the de-esser because "De-essing is a threshold-based effect" that fails when level changes ahead of it (secondary) ([SOS Mix Rescue: Mixing Metal](https://www.soundonsound.com/techniques/mix-rescue-mixing-metal)). The delay return also feeds the reverb, a routing documented in two engineer sources ([UA: Pure Plate vocal preset](https://www.uaudio.com/blogs/ua/peter-mokran-vocal-preset-uad-pure-plate)).

The latency budget is honest but not literally zero. Comparable Scarlett interfaces measure about 6–7 ms round trip at 48 kHz with a 32-sample buffer ([MusicTech](https://musictech.com/reviews/studio-recording-gear/focusrite-scarlett-3rd-gen/)). The chain has no look-ahead anywhere. A 2× oversampled colour adds about 3.2 samples (67 µs) and a 4× exciter about 4.3 samples; choosing the Clean colour makes the chain exactly zero samples. The tuner is the only module with real latency, so it is off by default and labelled with its delay when on. When it is on, the monitor path must be fully wet and hardware direct monitoring must be off, because tuned and direct signals comb.

### The selectable types

**Reverb: five types from four engines.**

| Type | Engine and source | What defines it | Vocal starting point |
|---|---|---|---|
| Plate (default) | Dattorro tank (freeverb3 `strev`, Plateau, the paper) | No early reflections, instant density, HF-only damping | Decay 0.6–1.2 s live, 1.2–1.8 s playback; pre-delay 0–20 ms live, 60–80 ms playback; input high-pass 100–200 Hz; damping 7–10 kHz |
| Room | freeverb3 `progenitor2` + early taps (Dragonfly Room) | Signed early taps, nested allpasses, bass lift | Size 8–15 m, decay 0.3–1.0 s, pre-delay 0–4 ms, late damping 5–6.4 kHz, low boost 20–30 % at 400 Hz |
| Hall | freeverb3 `zrev2` + early taps (Dragonfly Hall) | Eight long lines, three-band decay, spin and wander | Size 24–40 m, decay 1.2–2.4 s, pre-delay 4–12 ms, high cut about 6 kHz, RT×1.25–2.25 below 500–700 Hz, RT×0.30–0.40 above about 5 kHz, modulation 10 % |
| Chamber | Hall engine, early taps off or low | Fast density, flatter decay, no distinct pattern | Size 16–20 m, decay 0.8–1.0 s, low multiplier 1.1–1.3, high multiplier 0.25–0.35 |
| Spring | chowdsp spring (Surge XT) | 32 allpass stages per loop trip, `tanh` input | Decay 1.5–2 s, damping toward 4 kHz; indie, lo-fi and rockabilly presets |

The vocal starting points are Dragonfly's own preset values ([hall presets](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-hall-reverb/DistrhoPluginInfo.h); [room presets](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-room-reverb/DistrhoPluginInfo.h); [plate presets](https://github.com/michaelwillis/dragonfly-reverb/blob/master/plugins/dragonfly-plate-reverb/DistrhoPluginInfo.h)). A sixth type, "Vintage plate" from Airwindows kPlateA, is worth adding once its right channel and its siblings have been read. Build the plate first, then the hall (which also yields Chamber), then the room and the spring. Reverb CPU was never measured; structurally the plate is about a dozen delay and allpass operations per sample, and the hall adds 20 input allpasses and 16 shelving biquads, which is small against a 1333 µs period but must be confirmed in the app. Every return gets a high-pass (200–600 Hz), a low-pass (5–10 kHz) and a ducker of about 3 dB keyed from the dry vocal, following Sound On Sound's advice that "It's probably only necessary to duck the reverb level by 3dB or so" with times of 250–500 ms ([SOS: Advanced Reverberation, Part 2](https://www.soundonsound.com/advanced-reverberation-0)). A shimmer option is not available from the research: no open pitch-shifter-in-the-loop reverb was read.

**Delay: six types on the one core.** This palette comes complete from the delay notes.

| Type | Loop recipe | Use |
|---|---|---|
| Clean digital | Crossfade retime (Surge clean mode); in-loop high-pass about 150 Hz and low-pass about 8 kHz, 2-pole; no saturation; wet ducking on | Pop, EDM, worship throws |
| Tape echo | Slewed read head (about 100 ms lag); CHOW wow about 0.45 Hz plus three-harmonic flutter at small depth; per-repeat low-pass 6 kHz plus wide band-pass 4.5 kHz; Spiral or tanh saturation in the loop | Rock, indie, soul, dub |
| Analog (bucket-brigade) | Holters-Parker line with 2048–4096 stages, or the cheap tracking-filter version; feedback through a 50 Hz high-pass; 40–600 ms | Ballads, lo-fi, 1980s |
| Slapback | One repeat at 80–120 ms (20–60 ms for modern rap), feedback 0–10 %, tape tone | Rockabilly, country, rap ad-libs |
| Ping-pong / dual | Mono in to one side with cross gain only, or left dotted-1/8 against right 1/4 with `gR = g^(tR/tL)`; width on wet only | Pop, EDM, ambient |
| Diffused | 4–8 short allpasses inside the loop, slow opposite-sign time modulation, long feedback, heavy ducking | Ambient, cinematic |

A self-limiting feedback path makes high feedback safe in headphones; Airwindows PitchDelay's `feedback = B·(3 − |2·sin(tap)|)`, mda's in-loop limiter and Surge's in-loop clippers are the three precedents ([PitchDelayProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/PitchDelay/PitchDelayProc.cpp)). Sound On Sound's ducked-delay recipe is a 2:1 compressor on the return keyed from the dry vocal with a release of about 150 ms ([SOS: dynamics processing with reverb/delay](https://www.soundonsound.com/techniques/logic-dynamics-processing-reverbdelay)).

**Width: three types.** Micro-pitch runs the two-tap shifter at −9 cents left and +9 cents right (range 0–25), with a window of 1024–2048 samples and optional 0–30 ms pre-delays, 6–12 dB under the dry voice. Juno chorus offers modes I, II and I+II with the measured numbers above. ADT is one or two 15–40 ms taps on the tape core, each with its own random wow and a polarity and level control to manage bass build-up in mono.

**EQ: six controls, three characters.**

| Control | Range and default | Clean | Console | Tube / Passive |
|---|---|---|---|---|

No sibilance band is included, on the advice of both iZotope and Sound On Sound that static cuts leave the vocal "dull and lifeless" and a de-esser does the job better ([iZotope: How to EQ vocals](https://www.izotope.com/en/learn/how-to-eq-vocals.html)). The same guide limits presence moves to "no more than 1 or 2 dB", so a fine knob law over the central travel is worth more than the ±12 dB range. The Console and Tube constants rest on one curve-fit and one circuit model; name them by style, and note that the trademark question of hardware names was not examined.

**Compressor: four characters over one gain computer.** This table is this report's synthesis in place of the missing design section.

| Character | Topology and smoothing | Fixed behaviour | Source to port or re-derive |
|---|---|---|---|
| Clean | Feed-forward; peak → dB → soft knee (6 dB) → decoupled smoothing of dB reduction | Ratio 2–4, attack τ 5–20 ms, release τ 100–250 ms, side-chain high-pass 100–150 Hz | CTAGDRC (GPL-3.0-or-later) |
| FET | Feedback from the previous output sample; smoothing of dB reduction with the guard `(1−α)·R ≤ 1`; fixed threshold, input drive | Ratios 4 / 8 / 12 / 20, attack 20–800 µs (one sample at the fastest), release 50 ms–1.1 s | UA figures; Squeezer's feedback switch (GPL-3.0-or-later) |

| Glue (vari-mu) | Additive-power law with two cascaded release stages and hold; or Pressure4's cell | Ratio rises with level, no knee branch, loudness held near −10 dBFS RMS | x42 darc (GPL-2.0-or-later); Pressure4 (MIT) |

Slot A defaults to FET and slot B to Opto, following UA's reasoning that "The 1176 goes first because its fast 'grab' catches peaks before they get out of hand" ([UA: LA-2A and 1176](https://www.uaudio.com/blogs/ua/how-to-use-the-la-2a-and-1176-in-your-mix)), and Sound On Sound's two-stage example of a 4:1 soft-knee stage doing "about 6dB maximum gain-reduction" followed by an 8:1 stage that catches only peaks ([SOS: Vocal Processing](https://www.soundonsound.com/techniques/vocal-processing)). One "Compress" macro lowers both thresholds relative to the auto-levelled −18 dBFS and shows total gain reduction; make-up follows the static pivot law. The de-esser is a band-pass detector around 4–10 kHz compared with full-band level, acting on a split band, with a Listen switch; the expander uses hysteresis and a hold of about one pitch period; the output is the public-domain hold-and-release safety limiter followed by a sine soft clip. Those three designs come from the earlier research in this project and the fragments cited above, not from finished notes.

**Colour: five models, one amount knob.** This set comes complete from the colour notes.

The amount law is `drive_dB = D_max·a^p` with p between 1.5 and 2, and output gain `1/(g0·drive^c)` with c about 0.6–0.8, where g0 is the curve's measured small-signal gain (Spiral +1.96 dB, Mojo +3.8 dB, Tube at full +7.2 dB). Calibrate c so speech-shaped noise at −18 dBFS RMS reads the same loudness at amounts 0, 0.5 and 1. Smooth every derived gain over about 10 ms.

**Pitch: three tiers.** The default monitoring path has no pitch processing. An opt-in "Tuned monitoring" toggle runs the zita port in Fast mode and exposes Amount, Speed (0.02–0.5 s, plus a zero setting for hard-tune) and the song's key as the note mask. An offline "Tune take" pass on recorded audio uses the retuner in its time-aligned normal mode with a long-window detector and look-ahead, which can correct a note from its first cycle; the MIT/Apache `pitch-detection` Rust crate supplies McLeod and YIN detectors for that pass ([pitch-detection](https://github.com/alesgenova/pitch-detection)). Practice supports the split: a hip-hop engineer tracks with the artist "hearing himself with Auto-Tune, and a quarter-note delay, and the reverb" while recording dry, whereas conventional advice is that tuned monitoring "will completely undermine their ability to control their pitching" ([SOS Inside Track](https://www.soundonsound.com/techniques/inside-track-future-draco); [SOS Vocal Masterclass](https://www.soundonsound.com/techniques/vocal-recording-production-masterclass)).

Two sample-rate cautions apply across the list. Airwindows and Freeverb tables are raw 44.1 kHz sample counts that run unscaled at 48 kHz, so a faithful port sounds about 8 % smaller than the same plugin at 44.1 kHz unless the tables are scaled by fs/44,100 and re-rounded to primes. And slew- or difference-based detectors (Airwindows DeEss and DeBess, Channel9's clamp) change behaviour with sample rate and with oversampling factor.

## Conclusion

The research changes the build plan in one important way: the vocal chain does not need invention so much as careful assembly. Outside pitch, every "analog" behaviour the brief asks for already exists as a few dozen lines of readable, legally portable code, and the same small set of ideas recurs across authors. Character lives in where a smoother sits, in whether a curve is symmetric, in how decay varies with frequency, and in what happens inside a feedback loop. That makes a shared-core architecture natural: one gain computer with four detector placements, one delay loop with six skins, one hall engine that is also the chamber, one oversampler shared by five colours.

The weak point is evidence of quality, not availability of code. Nothing here has been heard in this configuration, the notes that would have ranked the options stopped early, and the genre table is mostly interpolation. The sensible sequence is therefore to build the smallest verified core first (auto-level, state-variable and matched EQ, the Giannoulis compressor with FET and opto characters, Channel9 and PurestDrive colour, the Dattorro plate, the Surge-style delay), measure its latency and CPU on the real interface, and let listening decide which of the second-tier ports (the freeverb3 room and hall, tape hysteresis, the bucket-brigade line, the zita retuner) earn their place.
