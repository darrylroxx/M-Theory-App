## 2. How "tape" character is produced (wow/flutter, loss filters, saturation, interpolation)

### Takeaway
Two families exist in open source: (a) **physical**: ChowTape = Jiles–Atherton hysteresis + FIR loss filter + head-bump peak + Lagrange-3 modulated delay with a cosine + Ornstein–Uhlenbeck wow and a 3-harmonic flutter — but it is NOT a delay; (b) **pragmatic echo**: Airwindows TapeDelay2 (fixed 2-s loop read at variable speed, band-pass in the regen path, amplitude-keyed flutter), Cocoa Delay (Hermite read, slewed read head, random-walk drift, Airwindows-style drive in the loop), Surge Delay (12-tap sinc read, LP/HP + selectable clipper in the loop), Calf (LP 6 kHz + BP 4.5 kHz), VCV Delay (resampled history). No repository read here places the hysteresis model inside a feedback echo loop.

### Cited Findings
**CHOW Tape Model — wow & flutter** (`Plugin/Source/Processors/Timing_Effects/`):
- Delay line: `chowdsp::DelayLine<float, DelayLineInterpolationTypes::Lagrange3rd> delay { HISTORY_SIZE }`, `HISTORY_SIZE = 1 << 21`; delay set per sample; followed by a DC blocker at 15 Hz [V]. — [WowFlutterProcessor.h](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/WowFlutterProcessor.h), [WowFlutterProcessor.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/WowFlutterProcessor.cpp)
- Parameter mapping (all knobs 0..1): `curDepthWow = wowDepth^3`; `wowFreq = 4.5^wowRate − 1` Hz (0…3.5 Hz; default rate 0.25 → ≈0.456 Hz); `curDepthFlutter = sqrt(flutterDepth^3 · 81/625)` (max 0.36); `flutterFreq = 0.1 · 1000^flutterRate` Hz (0.1…100 Hz; default rate 0.3 → ≈0.79 Hz). Defaults: both depths 0, wow variance 0, wow drift 0 [V]. — [WowFlutterProcessor.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/WowFlutterProcessor.cpp)
- Wow LFO: `amp = 1000·1000/fs`; output = `depth·amp·(cos(phase) + OH(n))`, plus an equal DC offset `depth·amp`; delay in samples = `(wow + flutter + flutterOffset + wowOffset)·fs/1000` → wow amplitude is **1000 samples × depth** (≈20.8 ms at 48 kHz at full depth; it is fixed in samples, not ms). Per block the rate is jittered: `freq·(1 + rand^1.25 · wowDrift)`. Depth smoothed multiplicatively over 0.05 s, floor 0.001 [V]. — [WowProcess.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/WowProcess.cpp), [WowProcess.h](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/WowProcess.h)
- Wow randomness = Ornstein–Uhlenbeck process: `y += sqrt(1/fs)·N(0,1)·(1/2.33)·amt; y += damping·(mean − y)/fs`, with `amt = var^1.25`, `damping = 20·amt + 1`, `mean = amt`, then SVF low-pass at 10 Hz (code credited to mhampton/ZetaCarinaeModules, GPLv3) [V]. — [OHProcess.h](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/OHProcess.h)
- Flutter LFO: three harmonically related cosines at f, 2f, 3f with amplitudes `amp1 = −230`, `amp2 = −80`, `amp3 = −99` (×1000/fs, i.e. −230/−80/−99 **samples**), phase offsets `0`, `13π/4`, `−π/10`, and a constant `dcOffset = 350` samples; scaled by `curDepthFlutter` (≤0.36 → ≤ ≈147 samples peak) [V]. — [FlutterProcess.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/FlutterProcess.cpp), [FlutterProcess.h](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Timing_Effects/FlutterProcess.h)

**CHOW Tape Model — loss filter & head bump** (`Loss_Effects/LossFilter.cpp`):
- Linear-phase FIR of order `64 · fs/44100` (latency = order/2 samples) built by frequency sampling: for bin frequency f, `k = 2π·max(f,20)/(speed_ips·0.0254)`; `H = exp(−k·spacing) · (1 − exp(−k·thickness))/(k·thickness) · sin(k·gap/2)/(k·gap/2)` (spacing/thickness/gap in µm ×1e-6). Coefficient changes crossfade over `max(1024, blockSize)` samples [V]. — [LossFilter.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Loss_Effects/LossFilter.cpp)
- Parameter ranges/defaults: speed 1–50 ips (default 30), spacing 0.1–20 µm (default 0.1), thickness 0.1–50 µm (default 0.1), gap 1–50 µm (default 1), azimuth −75…75 (default 0) [V]. — [LossFilter.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Loss_Effects/LossFilter.cpp)
- Head bump: `bumpFreq = speed_ips·0.0254/(gap_m·500)`, `gain = max(1.5·(1000 − |bumpFreq − 100|)/1000, 1.0)`, JUCE `makePeakFilter(fs, bumpFreq, Q = 2.0, gain)` [V]. — [LossFilter.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Loss_Effects/LossFilter.cpp)

**CHOW Tape Model — hysteresis (saturation)** (`Hysteresis/`):
- Jiles–Atherton state: `M_s = 0.5 + 1.5·(1 − sat)`, `a = M_s/(0.01 + 6·drive)`, `c = sqrt(1 − width) − 0.01`, `k = 0.47875`, `alpha = 1.6e-3`, `upperLim = 20`; derivative by "alpha transform" with `dAlpha = 0.75`; Langevin `L(Q) = coth(Q) − 1/Q` (Q/3 near zero), `Q = (H + alpha·M)/a`. Legacy "V1": `k = 27e3`, `c = 0.17`, `M_s·50000`, `a = M_s/(0.01 + 40·drive)`, `upperLim = 100000` [V]. — [HysteresisProcessing.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Hysteresis/HysteresisProcessing.cpp), [HysteresisOps.h](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Hysteresis/HysteresisOps.h)
- Solver choices "RK2, RK4, NR4, NR8, STN (neural), V1", default RK2; default drive/saturation/bias = 0.5 each; default oversampling 2x minimum-phase; input hard-clipped to ±8/±10/±12.5/±20 depending on solver "to avoid unstable hysteresis"; bias signal at `fs·OS/2`; DC blocker after [V]. — [HysteresisProcessor.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Hysteresis/HysteresisProcessor.cpp)
- Surge XT's "Tape" effect is this model ported (defaults: drive 0.85, saturation 0.5, bias 0.5, speed 30 ips, spacing 0.1, gap 1.0, thickness 0.1, degrade 0) [V]. — [TapeEffect.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/TapeEffect.cpp)

**ChowMatrix delay node (how Chowdhury builds an echo)** (`src/dsp/Delay/`):
- Loop order per sample: `input = inGain·x; input = procs(input + state); delay.push(input); y = delay.pop(); state = y·feedback; return y` — i.e. LPF → HPF → diffusion → distortion → reverser → pitch-shift all sit **before the delay write, inside the loop** (chain enum order lpf, hpf, diffusion, distortion, reverser, pitch) [V]. — [DelayProc.cpp](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Delay/DelayProc.cpp), [DelayProc.h](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Delay/DelayProc.h)
- Mappings: `fb = min(feedback, 0.95)^0.9`; if feedback ≥ 0.99 → freeze (input gain 0, fb 1); distortion gain `19.5·d² + 0.5` into `tanh` with 2nd-order antiderivative anti-aliasing (LUT of 2^17 points over ±10); LPF/HPF are **first-order** (LPF 200–20000 Hz default 20000; HPF 20–2000 Hz default 20); delay 0–1500 ms (skew centre 200 ms, default 200); mod sine 0–5 Hz, `modDepth = p^2.5`, max mod depth = 0.25 s; pitch ±12 st; diffusion = up to 100 cascaded first-order all-passes at 200 Hz; smoothing: delay 0.15 s, feedback 0.05 s [V]. — [DelayProc.cpp](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Delay/DelayProc.cpp), [ParamHelpers.h](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Parameters/ParamHelpers.h), [Diffusion.cpp](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Delay/Diffusion.cpp), [LookupTables.cpp](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Distortion/LookupTables.cpp)
- Selectable delay interpolation: None, Linear, Lagrange 3rd (default), Lagrange 5th, Sinc16, Sinc32, BBD short (4096 stages), BBD long (16384 stages), BBD "alien" (8192) [V]. — [VariableDelay.h](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Delay/VariableDelay.h)

**Airwindows TapeDelay2** (`TapeDelay2Proc.cpp`; params Time A=1.0, Regen B=0.0, Freq C=0.5, Reso D=0.0, Flutter E=0.0, Dry/Wet F=1.0):
- Fixed 88200-sample loop; the write/read position moves by `speed` cells per (undersampled) step: `baseSpeed = A^4·25 + 1` (1…26) → delay ≈ 88200/speed base-rate samples (≈2.0 s down to ≈77 ms at 44.1/48k base). Writing fills skipped cells by **linear interpolation between previous and new sample** (`increment = (new − prev)/speed`), reading takes the cell at `floor(delay)` — i.e. varispeed tape, so time changes pitch-bend [V]. — [TapeDelay2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/TapeDelay2/TapeDelay2Proc.cpp)
- `feedback = B²`. Regen path: biquad **band-pass** on (input + feedback) before writing, `freq = C³·0.4 + 0.0001` (fraction of the internal sample rate; C=0.5 → 0.0501 ≈ 2.2 kHz at 44.1k), `Q = D² + 0.01`; a second band-pass at the same frequency with `Q·1.618033988749894848` on the output [V]. — [TapeDelay2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/TapeDelay2/TapeDelay2Proc.cpp)
- Flutter: `vibSpeed = E^5·baseSpeed·(freq·0.09 + 0.025)`; `speed = baseSpeed + vibSpeed·(sin(sweep) + 1)`; the LFO phase advances by `0.05·x²` per step (x = input sample) — flutter keyed to signal amplitude, separate L/R sweeps [V]. — [TapeDelay2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/TapeDelay2/TapeDelay2Proc.cpp)
- Undersampling: `cycleEnd = floor(fs/44100)` clamped 1…4; the echo runs every cycleEnd-th sample, with linear up-interpolation + cascaded 2-point averaging on output; dry/wet: `wet = F·2`, `dry = 2 − wet`, both clamped to 1 [V]. — [TapeDelay2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/TapeDelay2/TapeDelay2Proc.cpp)
- No saturation stage is present in TapeDelay2's loop (only band-passes) [V]; author: "It's no longer trying to do the 'Iron Oxide' style tone shaping the original one did" [V, author text]. — [Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)

**Airwindows Flutter2** (stand-alone tape flutter; defaults A=B=0.5, wet 1.0):
- `flutDepth = A^4·overallscale·90` samples (cap 498; A=0.5 → ≈5.6 samples at 44.1k); `flutFrequency = 0.02·B³/overallscale` rad/sample; each LFO cycle the rate is re-randomised: `sweep += nextmax·flutFrequency`, `nextmax = 0.24 + rand·0.74` (B=0.5 → ≈4.2–17 Hz at 44.1k); offset = `depth + depth·sin(sweep)`; 1000-sample buffer [V]. — [Flutter2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Flutter2/Flutter2Proc.cpp)

**Cocoa Delay** (`source/CocoaDelay.cpp`):
- Read head slewing: `readPos += (target − readPos)·10·dt` per sample (≈100 ms time constant) → pitch glides on time changes; read interpolation = 4-point 3rd-order Hermite (x-form, from musicdsp) [V]. — [CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp), [Util.h](https://github.com/tesselode/cocoa-delay/blob/master/source/Util.h)
- Modulation is applied as an exponent on time: `time = time^(1 + lfoAmount·sin(2π·lfoPhase))` (lfoAmount 0–0.5 default 0; lfoFrequency 0.1–10 Hz default 2.0) and `time = time^(1 + driftAmount·sin(driftPhase))` (driftAmount 0–0.05 default 0.001; driftSpeed 0.1–10 default 1.0). Drift phase is a damped random walk: `v += rand(−1..1)·10000·speed·dt; v −= v·2·sqrt(speed)·dt; phase += v·dt` [V]. — [CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp)
- In-loop chain on the tap output before write-back: LP (cutoff 0.01–1.0 normalised, default 0.75) → HP (default 0.001) with selectable 1-pole/2-pole/4-pole/state-variable modes → "StatefulDrive" (`driven = sin(x²)/x`; `mix = |prev + driven|·0.5·amount`; out = `x·(1−mix) + driven·mix`; documented as Airwindows PurestDrive behaviour + Spiral curve; applied as `drive(x·gain)/gain`, gain 0–10 default 0.1, 1–16 iterations, each followed by a drive low-pass) [V]. — [CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp), [StatefulDrive.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/StatefulDrive.cpp)
- Defaults: delay 0.2 s (range 0.001–2.0 s), feedback 0.5 (range −1…1), dry 1.0, wet 0.5 [V]. — [CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp)

**Surge XT "Dual Delay"** (`sst-effects/include/sst/effects/Delay.h`):
- Buffer `max_delay_length = 1 << 18` per channel; read = **12-tap windowed-sinc FIR** (`FIRipol_N = 12`) with `FIRipol_M = 256` fractional phases (table lookup, SSE dot product); two line modes: "tape" (time is lagged, `SurgeLag` rate 0.0001 → pitch glides) and "clean" (time jumps are done by **crossfading two taps**; fade length = 0.5 × delay, clamped to 10 ms … 0.5 s) [V]. — [Delay.h](https://github.com/surge-synthesizer/sst-effects/blob/main/include/sst/effects/Delay.h), [SurgeStorage.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/SurgeStorage.h)
- Feedback path on the tap output, in order: optional polarity flip → clipper (off / soft / tanh / hard / hard +18 dB) → 2-pole low-pass `coeff_LP2B(…, 0.707)` → high-pass `coeff_HP(…, 0.707)` → `write = panned_input + feedback·tap + crossfeed·tap_other`. Feedback and crossfeed gains are **cubed** (`amp_to_linear(x) = x³`). Defaults: mix 0.5, crossfeed 0, low cut −60 (semitones re 440 Hz ≈ 13.75 Hz), high cut +70 (≈ 25 kHz) [V]. — [Delay.h](https://github.com/surge-synthesizer/sst-effects/blob/main/include/sst/effects/Delay.h)
- Time modulation: triangle-like LFO through a leaky integrator (`LFOval = 0.99·LFOval ± (2^(depth/12) − 1)·blockSize`), depth parameter 0–2 semitone units displayed as cents (×100), extendable ×6; applied `+LFOval` to left and `−LFOval` to right [V]. — [Delay.h](https://github.com/surge-synthesizer/sst-effects/blob/main/include/sst/effects/Delay.h)

**Calf Vintage Delay "Tape" medium**: `biquad_left[0].set_lp_rbj(6000, 0.707, srate)` then `biquad_left[1].set_bp_rbj(4500, 0.250, srate)`; comment: "parameters are heavily influenced by gordonjcp and his tape delay unit"; media = Plain / Tape / Old Tape (default Tape) [V]. — [modules_delay.cpp](https://github.com/calf-studio-gear/calf/blob/master/src/modules_delay.cpp), [metadata.cpp](https://github.com/calf-studio-gear/calf/blob/master/src/metadata.cpp)

**VCV Fundamental Delay**: changes of delay time are absorbed by resampling the history buffer with libsamplerate `SRC_SINC_FASTEST`, ratio `4^clamp(consume/10000, −1, 1)` (tape-like pitch slew); "Tone" tilts filters on the wet/feedback signal: `colorFreq = 100^(2·color − 1)`, low-pass `clamp(20000·colorFreq, 20, 20000)` Hz, high-pass `clamp(20·colorFreq, 20, 20000)` Hz; feedback 0–1 default 0.5; wet clamped to ±100 [V]. — [Delay.cpp](https://github.com/VCVRack/Fundamental/blob/v2/src/Delay.cpp)

**mda DubDelay**: linear-interpolated read; delay target smoothed every 100 samples (`db += 0.01·(del − db − mod − mod·sin(phi))`); `mod = 0.049·p·del`; LFO `dphi = 628.31853·10^(3p − 2)/fs` per 100-sample step (0.01–10 Hz); feedback `|2.2·p − 1.1|`; in-loop one-pole LP/HP tone blend with corner `10^(2.2 + 4.5·fil)` Hz; in-loop peak limiter (release coefficient 0.9997 "limit" or 0.8 "clip") [V]. — [mdaDubDelayProcessor.cpp](https://github.com/studiorack/mda/blob/master/source/mdaDubDelayProcessor.cpp)

**Interpolation theory (secondary)**: J.O. Smith's summary: linear and first-order allpass cost the same but only linear supports random access; allpass has no gain error so "may be preferred inside a feedback loop" for slowly varying delay; for Lagrange, HF attenuation is greatest at a half-sample fractional delay [S]. — [JOS, Delay-Line Interpolation Summary](https://ccrma.stanford.edu/~jos/pasp/Delay_Line_Interpolation_Summary.html)

### Inferences
- Interpolators actually chosen by respected code for *modulated* lines: Lagrange-3 (ChowTape, ChowMatrix default), 4-pt Hermite (Cocoa), 12-tap sinc (Surge), 3-point custom with HF "air" pre-emphasis (Airwindows Chorus family), linear (mda, TAL, junox, Mutable). For a vocal tape echo in Rust, 4-point Hermite/Lagrange-3 is the common sweet spot; Surge-style 12-tap sinc is the high-quality option; first-order allpass is unsuitable for fast modulation (per the JOS caveat).
- Zipper noise is avoided everywhere by per-sample smoothing of delay time (one-pole/lag) or by crossfading two taps ("clean" mode in Surge) rather than by the interpolator.
- Rate/depth conventions worth copying for "tape": wow 0–3.5 Hz with random drift + OU noise low-passed at 10 Hz; flutter as fundamental + 2nd + 3rd harmonic with fixed phase offsets; or Airwindows' per-cycle random rate (0.24–0.98 × nominal).
- A ChowTape-style FIR loss filter adds order/2 samples of latency (32 samples at 44.1k) — acceptable only inside the wet path; a cheap alternative per repeat is Calf's LP 6 kHz + wide BP 4.5 kHz or Airwindows' wide band-pass.

## 3. How "analog / BBD" character is produced (filters, clocking, companding, stages)

### Takeaway
Open-source BBD = the Holters & Parker (DAFx 2018) model: input anti-alias filter and output reconstruction filter expressed as parallel one-pole (pole/residue) sections evaluated at the exact fractional clock-tick times, with a plain array of N "buckets" clocked at `2·N/delay`. Two independent implementations exist (chowdsp_utils GPLv3; string-machine BSL-1.0), both using Juno-60 filter poles. Companding and clock noise are not modelled in the code paths read; Surge adds a WDF diode-based saturator and feedback.

### Cited Findings
- chowdsp BBD header comment: "Bucket-Bridage Device emulation, as derived by Martin Holters and Julian Parker: http://dafx2018.web.ua.pt/papers/DAFx2018_paper_12.pdf" and "Anti-aliasing/reconstruction filters used by JUNO-60 chorus. Root/Pole analysis borrowed from the above paper" [V]. — [chowdsp_BBDFilterBank.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_dsp_utils/Delay/BBD/chowdsp_BBDFilterBank.h)
- chowdsp constants: `inputFilterOriginalCutoff = 9900.0f`, `outputFilterOriginalCutoff = 9500.0f`; input poles `{-55482 ± 25082j, -26292 ± 59437j}`, input "roots" (residues) `{-10329.2715 ± 329.848j, 366.990557 ± 1811.4318j}`; output poles `{-51468 ± 21437j, -26276 ± 59699j}`, output "roots" `{-11256 ± 99566j, -13802 ± 24606j}` (4 complex terms each = one SIMD register). Filter cutoff is rescaled by `freq/originalCutoff` multiplying poles and roots [V]. — [chowdsp_BBDFilterBank.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_dsp_utils/Delay/BBD/chowdsp_BBDFilterBank.h)
- string-machine constants (namespace `j60`, 5 terms each): `R_in = {251589, -130428 ∓ 4165j, 4634 ∓ 22873j}`, `P_in = {-46580, -55482 ± 25082j, -26292 ∓ 59437j}`; `R_out = {5092, 11256 ∓ 99566j, -13802 ∓ 24606j}`, `P_out = {-176261, -51468 ± 21437j, -26276 ∓ 59699j}`; G-coefficient table interpolated over `interp_size = 128` fractional steps [V]. — [bbd_filter.cpp](https://github.com/jpcima/string-machine/blob/master/sources/bbd/bbd_filter.cpp), [bbd_line.cpp](https://github.com/jpcima/string-machine/blob/master/sources/bbd/bbd_line.cpp)
- **Discrepancy to resolve before porting**: the two code bases share the complex pole pairs, but chowdsp omits the real poles (−46580 in, −176261 out) and its input residues differ numerically from string-machine's, and the sign of the first output residue pair differs (−11256 vs +11256) [V both files]. The paper's own table could not be opened. — [chowdsp_BBDFilterBank.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_dsp_utils/Delay/BBD/chowdsp_BBDFilterBank.h), [bbd_filter.cpp](https://github.com/jpcima/string-machine/blob/master/sources/bbd/bbd_filter.cpp)
- Clocking (chowdsp `BBDDelayLine<STAGES>`): `clock_rate_hz = 2·STAGES/delaySec`; `Ts_bbd = 1/clock_rate` (floored at `0.01·Ts`); per audio sample: `while (tn < Ts) { if even tick: bucket[ptr++] = Σ real(Gin·x_in) (write, ptr wraps at STAGES); else: y = bucket[ptr]; delta = y − y_old; y_old = y; xOutAccum += Gout·delta; toggle; tn += Ts_bbd } tn −= Ts;` then input filter states `x = pole_corr·x + u`, output states `x = pole_corr·x + xOutAccum`, output `H0·y_old + Σ real(xOut)`; buffer is `std::array<float, STAGES+1>` [V]. — [chowdsp_BBDDelayLine.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_dsp_utils/Delay/BBD/chowdsp_BBDDelayLine.h)
- Usage constants in ChowMatrix: BBD short = 4096 stages, filter 2000 Hz, make-up gain 0.85; BBD long = 16384 stages, filter 9000 Hz, make-up 0.65; "alien" = 8192 stages with filter freq ×0.2 and a deliberately wrong time base [V]. — [VariableDelay.cpp](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Delay/VariableDelay.cpp)
- string-machine "Solina" analog chorus: three BBD lines of `NumAnalogBBDStages = 185` ("the TCA-350-Y IC"), `avgDelay = 5e-3`, `varDelay = 1e-3` (clock swept between the rates for 4 ms and 6 ms), Juno-60 in/out filter specs; stereo matrix `L = l1 + l2 − l3`, `R = l1 − l2 − l3` [V]. — [Delay3Phase.cpp](https://github.com/jpcima/string-machine/blob/master/sources/dsp/Delay3Phase.cpp)
- Surge XT Ensemble (BBD): selectable 128/256/512/1024/2048/4096 stages or a "sinc" clean line; clock-rate parameter 1.5–100 (kHz), default 40; `delayCenterMs = numStages/(2·clock_rate)`; default type index 2 = 256 stages (→ ≈3.2 ms centre); input ×0.75 → soft waveshaper(input + feedback) → 4 BBD lines (L1,L2,R1,R2) → `bbd_saturation_sse` (WDF "FastDiode" network; component values in file include Rgk 2.7 kΩ, Cgk 1.6 pF, Cgp 1.7 pF, Cpk 0.33 pF, alpha 0.4) → sum; feedback gain `0.49·sqrt(0.2·fb)` for BBD (`0.49·sqrt(fb)` for sinc), through a 4th-order Butterworth 50 Hz high-pass (Q = 1/0.7654 and 1/1.8478); output reconstruction 2-pole LP (Q 0.7071) default "6 kHz"; BBD filter updated every 4th block; a `BBDCompander.h` file exists in the tree but `BBDEnsembleEffect.cpp/.h` contain no reference to it (grep) [V]. — [BBDEnsembleEffect.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/BBDEnsembleEffect.cpp), [BBDNonlin.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/bbd_utils/BBDNonlin.h), [Parameter.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/Parameter.cpp)
- Surge anti-alias cutoff tracking: `freq = 2π·400·note_to_pitch(param); freq_adjust = freq·(clock_rate·0.01)^0.75; min(freq_adjust, 25000)` — i.e. cutoff scales with clock^0.75 [V]. — [BBDEnsembleEffect.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/BBDEnsembleEffect.cpp)
- BYOD chorus (BBD "Lo-Fi" option): BBD filter 10 kHz, extra AA filter 12 kHz, DC blocker 60 Hz, input `tanh(0.75·x − feedbackState)`, feedback `sqrt(fb)·0.4` (lo-fi) or `·0.5` (clean) [V]. — [Chorus.cpp](https://github.com/Chowdhury-DSP/BYOD/blob/main/src/processors/modulation/Chorus.cpp)
- Juno-60 hardware facts (MIT analysis repo): 2 × 256-stage BBD lines, "chips are effectively sampling at about 70kHz", a 12 dB low-pass before the BBD (per a KVR thread), no compander visible in the schematics, visible non-linearity [V as text of that README; the underlying claims are that author's]. — [Juno60 Chorus README](https://github.com/pendragon-andyh/Juno60/blob/master/Chorus/README.md)
- MN3009 datasheet delay range 0.64–12.8 ms [S]. — [Eventide page (search snippet)](https://www.eventideaudio.com/?p=154476)
- Dimension D hardware: two BBD lines "with companders … and pre/de-emphasis", "1024 stages for each channel", sweep direction opposite on the two channels, no rate control [S]. — [Muzines review](https://www.muzines.co.uk/articles/roland-dimension-d/4054), [UA WebZine](https://www.uaudio.com/webzine/2004/september/text/content4.html)
- Later literature: a DAFx-25 paper describes Holters & Parker as the model "that combines fractional read and write" [S]. — [DAFx25 paper 29](https://dafx25.dii.univpm.it/wp-content/uploads/2025/09/DAFx25_paper_29.pdf)

### Inferences
- In the H–P model "delay time vs filter" is automatic: longer delay → lower clock → more aliasing unless the in/out cutoffs are lowered; ChowMatrix simply fixes 2 kHz (4096 stages) and 9 kHz (16384 stages); Surge scales cutoff ∝ clock^0.75. For a vocal BBD echo (e.g. 4096 stages, 300 ms → clock ≈ 27.3 kHz; buckets are written on every other tick, so the effective BBD sampling rate is `STAGES/delay` ≈ 13.65 kHz, Nyquist ≈ 6.8 kHz) a cutoff of roughly 2.5–3.5 kHz at long delay times is the physically consistent choice (my arithmetic from `clock = 2N/delay`, not a sourced figure).
- A cheaper "BBD-flavoured" delay for live use = ordinary interpolated delay + 2–4 pole LP in and out whose cutoff tracks delay time + soft saturation + optional 2:1 compander emulation; this loses clock-aliasing artefacts but costs a fraction of the CPU.
- Companding and clock/hiss noise must be designed from scratch; none of the open code read implements them in a delay.

- Raffel & Smith BBD paper not read. No open-source Memory Man / DM-2 circuit model found or read.
- Surge BBDCompander.h content not read.

## 4. Feedback structures: ping-pong, cross-feedback, dual L/R, tempo sync, ducking

### Takeaway
All studied delays filter (and optionally saturate) inside the loop and build stereo behaviour from a 2×2 feedback matrix (direct + cross gains) or a channel swap at the write point. Exactly one studied open-source delay (Cocoa) implements vocal-style ducking, with a simple attack/release follower on the dry input scaling the wet output.

### Cited Findings
- Surge Dual Delay matrix: `wL = inL + fb·tapL + cf·tapR; wR = inR + fb·tapR + cf·tapL` (feedback and crossfeed each `x³`; crossfeed extendable to ×2/−1 range; feedback extendable to bipolar), input "Channel" pan (−100 % left … +100 % right) lets a mono source enter one side for ping-pong; separate L/R times, right can be linked; stereo width applied to wet only [V]. — [Delay.h](https://github.com/surge-synthesizer/sst-effects/blob/main/include/sst/effects/Delay.h)
- Surge Delay has **no ducking**: an `envf` member exists and is zeroed in `initialize()` but nothing else uses it in the file [V]. — [Delay.h](https://github.com/surge-synthesizer/sst-effects/blob/main/include/sst/effects/Delay.h)
- Cocoa ping-pong: at the write point `bufferL[w] = writeR; bufferR[w] = writeL` (channels swapped each pass), input first rotated by `stationaryPan·0.5`; "circular" mode applies a rotation matrix `[c −s; s c]` to the tap inside the loop; stereo offset: `timeL = base^(1 + off/2)`, `timeR = base^(1 − off/2)`, off ∈ [−0.5, 0.5]; mode switches fade the loop gain at `100·dt` per sample [V]. — [CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp)
- Cocoa ducking: `follower += (|inL + inR| − follower)·speed·dt` with `speed = attack` when rising else `release` (both 0.1–100, default 10 → ≈100 ms time constants); `duck = min(1, duckAmount·follower)` (duckAmount 0–10, default 0); `wet *= 1 − duck`; ducking acts on the **output wet gain only**, not on the feedback [V]. — [CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp)
- Calf Vintage Delay: mix modes Stereo / Ping-Pong / "L then R" / "R then L" (default Ping-Pong); times in integer beat subdivisions `unit = 60·fs/(bpm·subdiv)`, `time_l`/`time_r` 1–16 units (defaults subdiv 4, L 3, R 5 → 3/16 and 5/16 notes); in Stereo mode `fb_right = fb^(time_r/time_l)` so both sides decay at the same rate; in L-then-R mode the second tap level is `amount·fb^(deltime_r/(deltime_l + deltime_r))`; defaults feedback 0.5, wet 0.25, dry 1.0, width 1.0 [V]. — [modules_delay.cpp](https://github.com/calf-studio-gear/calf/blob/master/src/modules_delay.cpp), [metadata.cpp](https://github.com/calf-studio-gear/calf/blob/master/src/metadata.cpp)
- Airwindows Doublelay feedback: `feedbackDirect = D·0.618033988749894848`, `feedbackCross = D·(1 − 0.618…)`; `inL += fbL·direct + fbR·cross` (and mirrored) [V]. — [DoublelayProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Doublelay/DoublelayProc.cpp)
- Airwindows PitchDelay regen: `feedback = B·(3 − |regenSample·2|)` with `regenSample = sin(tap)` — a self-limiting (level-dependent) feedback gain [V]. — [PitchDelayProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/PitchDelay/PitchDelayProc.cpp)
- Tempo-sync tables. ChowMatrix (factor × beat length `60/bpm`): 1/32 = 0.125, 1/32D = 0.1875, 1/16T = 1/6, 1/16 = 0.25, 1/16D = 0.375, 1/8T = 1/3, 1/8 = 0.5, 1/8D = 0.75, 1/4T = 2/3, 1/4 = 1, 1/4D = 1.5, 1/2T = 4/3, 1/2 = 2, 1/2D = 3, 1/1T = 8/3, 1/1 = 4, 1/1D = 6, 2/1T = 16/3, 2/1 = 8 [V]. Cocoa uses the same ratios down to 1/64 (1/64 = 1/16 beat, 1/64T = 1/24, 1/64D = 3/32) [V]. — [TempoSyncUtils.h](https://github.com/Chowdhury-DSP/ChowMatrix/blob/main/src/dsp/Delay/TempoSyncUtils.h), [CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp)
- Vital delay parameter defaults (not DSP-read): dry/wet 0.3334, feedback 0.5 (range −1…1), style 0–3, filter cutoff 60 (MIDI note), filter spread 1.0, separate "aux" frequency/tempo for the second channel [V]. — [synth_parameters.cpp](https://github.com/mtytel/vital/blob/main/src/common/synth_parameters.cpp)
- Mixing practice (secondary, snippet-level, pages not opened): rockabilly slapback "sits at 80-120ms", "modern trap and pop vocal slapback is much shorter: 20-60ms"; "1/8 or dotted-eighth with low feedback. Sidechain-duck from the lead so repeats bloom in gaps"; low-pass delays around 3–4 kHz (others 4–8 kHz) and high-pass anywhere from 150–200 Hz to 400–600 Hz [S; the search tool did not attribute each quote to a specific page]. — [Slapback Delay Guide](https://delay-calculator.pages.dev/slapback-delay), [Lewitt: 5 tips for vocal delay](https://lewitt-audio.com/blog/5-tips-for-vocal-delay), [Nail The Mix: delay on vocals](https://nailthemix.com/how-to-use-delay-on-vocals), [Violet Recording: delay on vocals](https://violetrecording.com/how-to-use-delay-on-vocals/)

### Inferences
- A single generic stereo core covers every requested routing: two lines with times tL, tR; write `wL = a·in + g·(d·fL + c·fR)`, `wR = b·in + g·(d·fR + c·fL)` where fL/fR are the filtered/saturated taps. Stereo/dual: d=1, c=0, a=b; ping-pong from mono: a=1, b=0, d=0, c=1; cross-feedback blends: d=0.618, c=0.382 (Airwindows' choice). For unequal L/R note values, equalise decay with Calf's `g_R = g^(tR/tL)`.
- Ducking for vocals: Cocoa's wet-only ducking with ~100 ms follower is the only source-backed design; a typical refinement (dB-domain gain computer with fast attack ≈5–10 ms, release ≈150–300 ms) is engineering judgement, not from any source read here.
- Put the HP/LP inside the loop (all sources do) so each repeat gets darker/thinner; Surge's 2-pole Butterworth pair is the cleanest reference.
- Self-limiting feedback (Airwindows `B·(3 − |2·sin(tap)|)`, mda's in-loop limiter, Surge's in-loop clippers) is the common way to allow feedback ≥ 1 safely on a live chain.

### Gaps
- No second open-source ducking implementation was read (the MIT "Strata" repo found by search claims ducking but is unvetted, 0 stars, not read).
- Vital's delay styles (mono/stereo/ping-pong/mid ping-pong) DSP not read; LSP art-delay routing not read.
- Vocal-practice numbers are snippet-level; primary articles could not be opened.

## 5. Doublers / wideners: delay offsets, detune, modulation, mono compatibility, two-tap pitch-shifting delay lines

### Takeaway
Open-source micro-pitch wideners all use the same structure: one circular buffer, two read taps half a window apart moving at rate (1 − ratio), crossfaded by a triangular/Hann/raised-cosine window; left is shifted down and right up by a few cents to ~20 cents. ADT-style code (Airwindows ADT) is simply two static short taps with polarity control plus saturation. Mono compatibility is addressed by polarity/level choices, not by any decorrelation trick, in the code read.

### Cited Findings
**Two-tap crossfaded pitch-shifting delay lines:**
- Mutable Clouds `PitchShifter`: per sample `phase += (1 − ratio)/size` (wrapped to [0,1]); `tri = 2·(phase ≥ 0.5 ? 1 − phase : phase)`; taps at `phase·size` and `phase·size + size/2` (wrapped), mixed `tri` and `1 − tri`; linear-interpolated reads; window `size = 128 + (2047 − 128)·s³` samples (one-pole smoothed, coefficient 0.05); 16-bit delay memory of 4096 samples for stereo [V]. — [pitch_shifter.h](https://github.com/pichenettes/eurorack/blob/master/clouds/dsp/fx/pitch_shifter.h), [fx_engine.h](https://github.com/pichenettes/eurorack/blob/master/rings/dsp/fx/fx_engine.h)
- mda Detune: mono sum `w·(a + b)` written to buffer; left read pointer decremented by `dpos1 = 1/ratio`, right by `dpos2 = ratio = 1.0594631^semi`, `semi = 3·p³` semitones (0–300 cents; default p = 0.40 → 19.2 cents, i.e. L ≈ −19 c, R ≈ +19 c); each side reads two linear-interpolated taps 180° apart (`+buflen/2`) and crossfades with a **Hann** window `0.5 − 0.5·cos(2π·i/buflen)` indexed by the read-to-write distance; `buflen = 1 << (8 + int(4.9·p))` → 256…4096 samples (default 1024); default mix 0.40 [V]. — [mdaDetuneProcessor.cpp](https://github.com/studiorack/mda/blob/master/source/mdaDetuneProcessor.cpp)
- chowdsp `PitchShifter`: double ring buffer, read pointer advances by `shift` per sample, second tap at ± half buffer, linear crossfade over `crossfadeOverlap = 256` samples near the write pointer; reference credited to YetAnotherElectronicsChannel/STM32_DSP_PitchShift [V]. — [chowdsp_PitchShift.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_dsp_utils/Delay/chowdsp_PitchShift.h)
- Airwindows PitchDelay: two taps π apart on a sweep phase; `sweep += 0.0001·vibSpeed`, `vibSpeed = (E − 0.5)·61.8`, `vibDepth = |vibSpeed|·20·baseSpeed + 1`; tap positions `delay − sweep·vibDepth` and `delay − (sweep + π)·vibDepth`; tap gains `(sin(sweep + 1.5π) + 1)·0.25` (raised cosine); no interpolation on read (`floor`) [V]. — [PitchDelayProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/PitchDelay/PitchDelayProc.cpp)

**Doublers / ADT:**
- Airwindows Doublelay (defaults Detune A=0.2, Delay L B=0.1, Delay R C=0.2, Feedback D=0.0, Dry/Wet E=0.6): `trim = ((2A − 1)·|2A − 1|)/40`; `speedL = 1 + trim`, `speedR = 1 − trim` (default trim = −0.009 → L ×0.991 ≈ −15.7 cents, R ×1.009 ≈ +15.5 cents; maximum ±0.025 ≈ ±43 cents); delays `B·48000` and `C·48000` samples scaled to give "exactly one second max delay"; GlitchShifter-style splicer with `width = 2300` samples, `adjust = 1100`, 8 staggered splice positions (0, w/3, 2w/3, w/5, 2w/5, 3w/5, 4w/5, w/2); "air" HF pre-compensation before the delay; undersampled above 48 kHz [V]. — [DoublelayProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Doublelay/DoublelayProc.cpp), [Doublelay.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Doublelay/Doublelay.cpp)
- Airwindows ADT (all six params default 0.5): two static taps `targetA = B⁴·4790` and `targetB = D⁴·4790` samples (default 0.5 → ≈299 samples ≈ 6.8 ms at 44.1k; max 4790 ≈ 109 ms; no sample-rate scaling in the lines read); tap gains `C − 0.5`, `E − 0.5` (±0.5, negative = inverted); tap position chases target `offset = (offset·999 + target)/1000`; input saturation `sin(x·|x|)/|x|` clipped at ±1.2533141373155, output `asin()` after clamp to ±1; `gain = A·1.272`, `output = F·2`. There is **no LFO/varispeed** in this ADT [V]. — [ADTProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/ADT/ADTProc.cpp)
- Airwindows shared 3-point modulated-tap interpolation (ADT, Chorus, ChorusEnsemble): `y = d[n]·(1 − frac) + d[n+1] + d[n+2]·frac − ((d[n] − d[n+1]) − (d[n+1] − d[n+2]))/50`, then ×0.5 [V]. — [ChorusProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Chorus/ChorusProc.cpp)
- Airwindows TripleSpread description: "split a track into three, pan one hard left and pitch it down a few cents, pan another hard right and pitch it up a few cents … subtly pitch shifted, or nearly a semitone out if you crank it"; as dry/wet rises "it also fades out the mid content of the added stereo stuff" [V, author text; DSP not read]. — [Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)
- Mono/comb-filter guidance from the ADT author: an in-phase short tap reinforces bass and comb-filters; an inverted tap "the shorter the delay and the closer to the volume of the dry signal, the more it'll cancel out the bass"; two inverted taps cut bass "while averaging out the comb-filter effects" [V, author text]. — [Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)
- H3000 reference values (secondary): a Mix Online review says the Micro Pitch Shift preset shifts one side up and the other down by 9 cents with a slight delay on one side; Eventide calls preset #519 a way to "fatten up or widen a sound without adding any color"; another article cites 7 cents; exact delay ms not found [S]. — [Mix Online H3000 Factory review](https://www.mixonline.com/technology/eventide-h3000-factory-plug-in-a-real-world-review), [Eventide MicroPitch Delay](https://www.eventideaudio.com/micropitchdelay)
- ADT history (secondary): developed 1966 at Abbey Road by Ken Townsend using tape delay with an oscillator-driven varispeed [S]. — [Wikipedia: Automatic double tracking](https://en.wikipedia.org/wiki/Automatic_double_tracking), [Abbey Road: Inside ADT](https://www.abbeyroad.com/news/inside-abbey-road-artificial-double-tracking-2530)

### Inferences
- Micro-pitch widener recipe consistent with the sources: mono in → one buffer → L voice ratio 2^(−c/1200), R voice 2^(+c/1200), c ≈ 5–20 cents (H3000 ≈ 9, mda default ≈ 19, Doublelay default ≈ 15.6); window 1024–2048 samples (≈21–43 ms at 48 kHz) with Hann/triangular two-tap crossfade; optional extra static pre-delays (Doublelay exposes up to 1 s per side). The splice period is `window/|1 − ratio|` samples (at 9 cents and 2047 samples ≈ 8 s), so splice artefacts are rare at vocal-widening settings (arithmetic from the Clouds formula).
- Latency: the pitch voices inherently add ≈ window/2 mean delay to the wet signal only; the dry path stays at zero latency, which is exactly the classic effect.
- Mono safety: L −c / R +c voices summed in mono beat at `f·(2^(c/1200) − 2^(−c/1200))` (≈10 Hz at 1 kHz for ±9 c) — i.e. the mono sum turns into a slow chorus rather than a static comb; keeping wet ≥6 dB below dry and unequal L/R pre-delays (e.g. 10–30 ms apart) limits it. This is reasoning, not sourced.
- A true Abbey-Road-style ADT (single 20–40 ms tap whose delay is wobbled by a slow random LFO) is not what Airwindows ADT implements; build it from the tape-delay core (§2) with ChowTape-style OU wow.

### Gaps
- No open-source H3000 MicroPitch clone was read; H3000 delay values unverified.
- Airwindows StereoDoubler / TripleSpread / GlitchShifter splice logic read only partially (first 125 lines of Doublelay); Wider/Srsly not read.
- sst-effects voice `Widener.h` not read. No source on decorrelation-based (allpass/velvet-noise) wideners examined.
- Abbey Road ADT delay range and wobble depth: no numeric source found.

## 6. Chorus: Juno-60 modes, Dimension D, and other open implementations (exact numbers)

### Takeaway
Measured Juno-60 values (MIT-licensed analysis): one triangle LFO, two 256-stage BBDs with inverted modulation L/R; mode I 0.513 Hz, mode II 0.863 Hz (both 1.66–5.35 ms, stereo), I+II 9.75 Hz (3.3–3.7 ms, mono). ### Inferences
- A faithful, licence-clean "Juno" chorus for vocals: mono in; pre-LP ≈7.2 kHz (or the H–P BBD with 256 stages); L delay = 3.345 ms ± 1.805 ms, R = 3.455 ms ± 1.945 ms driven by one triangle LFO with opposite sign (from junox's min/max pairs); post-LP ≈10.6 kHz; mix 44 % dry / 56 % wet per side; mode I 0.513 Hz, II 0.863 Hz, I+II 9.75 Hz with ±0.17 ms and same-sign modulation (mono vibrato-chorus). Mono-sum behaviour: because L and R wet are complementary around the same centre, the mono sum is a two-voice chorus (no cancellation of dry).
- The Juno delays (1.7–5.4 ms) are in flanger territory, which is why it reads as "wide and glossy" rather than "detuned"; for a thicker vocal chorus the Surge (15.6 ms, 4 voices, 0.25 Hz) or Rings (17–25 ms, 0.20/0.26 Hz quadrature) settings are the better starting points.
- A "Dimension-style" mode can only be approximated from secondary facts: two 1024-stage BBD-like lines swept in opposite directions by a slow fixed-rate LFO, compander, reduced chorus in the bass (high-passed wet); numbers must be tuned by ear — no open reference exists.
- Ensemble-type (tri-phase, 0.18–0.75 Hz slow + 5.5–6.6 Hz fast at ~10–60 % of slow depth) is consistently encoded by Surge, Rings and string-machine; on vocals this is a special effect rather than a default.

- Dimension D rates/delays/cross-mix: no numeric source; no open implementation verified.
- Clouds' native sample rate (commonly stated as 32 kHz) was not verified in source; ms figures for the Clouds pitch shifter therefore not given.
- Airwindows StereoChorus/StereoEnsemble, Surge Flanger, sst voice Chorus, jpcima ensemble-chorus numbers not read.
- Vital parameter scaling (log2 seconds / Hz) inferred, not traced through the code.

## 7. CPU cost for real time at 48 kHz, 64-sample buffers

### Takeaway
No benchmark numbers were obtained; only structural cost can be stated. Everything except the ODE-solved hysteresis model and short-delay, many-stage BBD lines is trivially cheap for one mono-in/stereo-out vocal chain.

### Cited Findings
- Surge's WDF BBD saturator carries the only in-source CPU note found: "2.7% w/ spikes up to 3.2% / After SSE: 1.8% +/- 0.2%" (machine and context unspecified) [V]. — [BBDNonlin.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/bbd_utils/BBDNonlin.h)
- H–P BBD cost scales with clock ticks per sample: `clock_rate_hz = 2·STAGES/delaySec`, each tick doing a 4-lane complex multiply-accumulate plus `calcG` rotation [V]. — [chowdsp_BBDDelayLine.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_dsp_utils/Delay/BBD/chowdsp_BBDDelayLine.h)
- Surge delay/chorus read cost: 12 multiplies (3 SSE mul-adds) per tap per sample; Surge processes in fixed internal blocks with per-block coefficient updates [V]. — [Delay.h](https://github.com/surge-synthesizer/sst-effects/blob/main/include/sst/effects/Delay.h)
- ChowTape hysteresis runs oversampled (default 2x) with double-precision SIMD and iterative NR4/NR8 or RK2/RK4 solvers; loss filter is a 64-tap (at 44.1 kHz) FIR with order/2 latency [V]. — [HysteresisProcessor.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Hysteresis/HysteresisProcessor.cpp), [LossFilter.cpp](https://github.com/jatinchowdhury18/AnalogTapeModel/blob/master/Plugin/Source/Processors/Loss_Effects/LossFilter.cpp)
- Airwindows keeps cost flat at high sample rates by undersampling the echo (`cycleEnd = floor(fs/44100)`); author: StarChild2 runs "at more or less the same CPU load of the 44.1/48k version" at 96/192 k [V]. — [TapeDelay2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/TapeDelay2/TapeDelay2Proc.cpp), [Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)
- Heap use in the reference code that must NOT be copied to a real-time Rust path: chowdsp BBD `prepare()` uses `std::make_unique` for the filter banks; YK Chorus allocates delay lines with `new` in constructors; Cocoa uses `std::vector<double>` sized `fs·tapeLength` in `Reset()`; all allocations are at prepare time, none per sample [V]. — [chowdsp_BBDDelayLine.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/master/modules/dsp/chowdsp_dsp_utils/Delay/BBD/chowdsp_BBDDelayLine.h), [CocoaDelay.cpp](https://github.com/tesselode/cocoa-delay/blob/master/source/CocoaDelay.cpp)

### Inferences
- Tick-rate arithmetic at 48 kHz (from `clock = 2N/delay`): Juno chorus line (256 stages, 3.2 ms) → 160 kHz ≈ 3.3 ticks/sample; BBD echo 4096 stages at 300 ms → 27.3 kHz ≈ 0.57 ticks/sample, at 50 ms → 164 kHz ≈ 3.4 ticks/sample, at 10 ms → 819 kHz ≈ 17 ticks/sample. So choose stage count by delay range (e.g. 1024–4096 for echoes ≥ 40 ms) and BBD stays cheap.
- Estimated per-sample work for one instance (order of magnitude, not measured): clean/tape/ping-pong delay with Hermite read + 2 biquads + tanh ≈ 30–60 flops per channel; 4-voice sinc chorus ≈ 50 multiplies + filters; micro-pitch widener (4 linear taps + windows) ≈ 20–30 flops; all are far below 1 % of a modern core at 48 kHz. ChowTape-style hysteresis at 2x OS with NR iterations is the only block that could reach whole-percent CPU; a memoryless `tanh`/Airwindows-Spiral curve in the loop is the live-safe substitute.
- 64-sample buffers impose no structural constraint: every algorithm above is sample-by-sample with at most block-rate coefficient updates (Surge uses small fixed blocks; chowdsp recommends refreshing BBD filter coefficients "every block … or every few blocks").

### Gaps
- No measured CPU figures for any plugin at 48 kHz / 64 samples; no Rust benchmarks. Numbers above are estimates and must be measured in the target app.

## 8. Recommended palette: 5–6 delay types and 2–3 modulation types for vocals

### Takeaway
A single stereo delay core (pre-allocated buffer, smoothed time, 4-point Hermite/Lagrange read, in-loop HP/LP + soft saturation, 2×2 feedback matrix, tempo-sync table, wet ducking) can be skinned into six vocal delays; three modulation effects (micro-pitch widener, Juno-style chorus, tape-style ADT doubler) complete the palette. Each choice below maps to verified source constants.

### Cited Findings
- Clean digital reference design: Surge "clean" line mode — retime by crossfading two taps (fade = 0.5 × delay, 10 ms…0.5 s), 2-pole Butterworth HP/LP in loop, cubed feedback law, clipper off [V]. — [Delay.h](https://github.com/surge-synthesizer/sst-effects/blob/main/include/sst/effects/Delay.h)

### Inferences
Proposed delay palette (all on one core; defaults are my synthesis of the cited constants):
1. **Clean digital** — crossfade retime (Surge clean mode), in-loop HP ≈150 Hz / LP ≈8 kHz 2-pole, no saturation; sync 1/4, 1/8, 1/8D, triplets; wet ducking on. Genre-neutral pop/EDM/worship throw.
2. **Tape echo** — slewed read head (≈100 ms lag, Cocoa) so time changes glide; ChowTape wow (≈0.45 Hz, OU variance) + 3-harmonic flutter at small depth; per-repeat LP ≈6 kHz + wide BP ≈4.5 kHz (Calf) or Airwindows wide band-pass ≈2.2 kHz; in-loop soft saturation (Spiral `sin(x·|x|)/|x|` or tanh with ADAA). Rock/indie/soul/dub.
3. **Analog BBD** — H–P line with 2048–4096 stages (or cheap emulation: tracking 2–3 kHz LPs + saturation), feedback through 50 Hz HP; dark, short-to-medium (40–600 ms). Ballads, lo-fi, 80s.
4. **Slapback** — single repeat 80–120 ms (or 20–60 ms), feedback 0–10 %, tape tone, mono-centred or slight L/R offset (Cocoa stereo-offset law). Rockabilly/country/rap ad-libs.
5. **Ping-pong / dual (dotted)** — mono in to one side, cross gain only (write-swap), or dual L = 1/8D, R = 1/4 with `g_R = g^(tR/tL)`; width control on wet only. Pop/EDM/ambient.
6. **Diffused "ambient" delay** — all-pass diffusion (e.g. 4–8 short all-passes rather than ChowMatrix's up-to-100) inside the loop + slow ±few-cent time modulation (Surge: opposite sign L/R); long feedback, heavy ducking. Ambient/cinematic/worship.

Proposed modulation palette:
A. **Micro-pitch widener (H3000-style)** — two-tap Hann/triangular shifter, L −9 c / R +9 c default (range 0–25 c), window ≈1024–2048 samples, optional 0–30 ms pre-delays; wet −6…−12 dB under an untouched, zero-latency dry.
B. **Juno-style chorus (I / II / I+II)** — numbers in §6; mono-safe, instant "polish" for pop/R&B backing and lead.
C. **ADT doubler** — one or two 15–40 ms taps on the tape core with independent random (OU) wow per tap, optional polarity/level per tap (Airwindows ADT's attenuverter idea) to control bass build-up in mono; classic rock/indie double.
(Optional D: 4-voice "lush" chorus à la Surge/Rings for effect use.)

Why this set: it spans every routing/tonal axis found in the respected sources (clean vs. tape vs. BBD colour; mono slap vs. stereo ping-pong/dual; dry echo vs. diffused), each has a permissively or GPL-3-compatibly licensed reference with concrete constants, and none requires look-ahead or adds latency to the dry vocal.
