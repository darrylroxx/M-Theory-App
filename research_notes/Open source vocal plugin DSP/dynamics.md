## 2. Concrete algorithm for each compressor character (detector, time constants and program dependence, knee and ratio, colour, typical vocal settings)

### Takeaway
Open code shows that "character" comes mostly from four choices: (a) feed-forward vs feedback detection, (b) whether smoothing is done on the level, on the dB gain reduction, or on linear gain, (c) whether the time constants depend on the amount of gain reduction, and (d) the shape of the static curve (hard knee, quadratic soft knee, or a continuous "ratio rises with level" law). The 1176 is a feedback FET design with 20–800 µs attack and 50 ms–1.1 s release; the LA-2A has fixed ~3:1 ratio, ~10 ms attack and a two-stage release (60 ms for the first half, then seconds). Each of these has a compact, readable open implementation that can be ported to Rust with zero latency.

### Cited Findings

#### 2.1 Reference digital design (Giannoulis, Massberg & Reiss, JAES 60(6), 2012) — as implemented in open code
- The paper exists at AES (vol. 60, no. 6, pp. 399–408, July 2012); I could not open it `[SEC]` — [AES e-library](https://www.aes.org/e-lib/browse.cfm?elib=16354).
- Static curve with soft knee, in dB, as coded by three independent projects that cite the paper `[SRC]`: with overshoot `o = x_dB − T`, knee width `W`, slope `s = 1/R − 1`:
  - `o ≤ −W/2` → gain reduction `g = 0`
  - `|o| ≤ W/2` → `g = s · (o + W/2)² / (2W)`
  - `o > W/2` → `g = s · o`
  — [CTAGDRC GainComputer.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/GainComputer.cpp); same formula in [Squeezer side_chain.cpp `queryGainComputer`](https://github.com/mzuther/Squeezer/blob/HEAD/Source/side_chain.cpp) and in [dasp-pytorch `compressor`](https://github.com/csteinmetz1/dasp-pytorch/blob/HEAD/dasp_pytorch/functional.py), which writes it as `y = x + (1/R − 1)(x − T + W/2)²/(2W)` in the knee and `y = T + (x − T)/R` above.
- One-pole coefficient: `α = exp(−1/(τ·fs))`, where τ is the time to reach 1 − 1/e = 63 % `[SRC]` — [CTAGDRC LevelDetector.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/LevelDetector.cpp), [CTAGDRC README](https://github.com/p-hlp/CTAGDRC/blob/HEAD/README.md).
- Smooth branching detector (applied to the dB gain-reduction signal `c`, which is ≤ 0 in CTAGDRC): `if c < y: y = αA·y + (1−αA)·c else y = αR·y + (1−αR)·c` `[SRC]` — [CTAGDRC LevelDetector.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/LevelDetector.cpp).
- Smooth decoupled detector (for a positive control signal `c`): `y1 = max(c, αR·y1 + (1−αR)·c)`; `yL = αA·yL + (1−αA)·y1` `[SRC]` — same file; identical structure in [Squeezer `applyCurveLogSmoothDecoupled`](https://github.com/mzuther/Squeezer/blob/HEAD/Source/side_chain.cpp) and in Calf's mono compressor (`y1 = max(xl, αR·y1 + (1−αR)·xl); yl = αA·yl + (1−αA)·y1`, with `xl = xg − yg` the dB overshoot) — [Calf `gain_reduction2_audio_module::process`](https://github.com/calf-studio-gear/calf/blob/HEAD/src/modules_comp.cpp).
- Topology choice as stated by an implementer of the paper: "Most modern compressors use a feedforward topology due to limitations of the feedback topology such as the inability to allow a lookahead functionality as well as to work as a limiter due to infinite negative amplification needed"; and "the smooth branching peak detector was placed behind the gain computer to smooth the calculated attenuations. Due to the placement, the detector does not have to operate on the whole dynamic range of the input signal" `[SRC]` — [CTAGDRC README](https://github.com/p-hlp/CTAGDRC/blob/HEAD/README.md).
- CTAGDRC signal flow: `|x|` (max of L/R) → dB (floor 1e-6) → gain computer → branching smoothing in dB → + make-up → `10^(dB/20)` → multiply; defaults threshold −20 dB, ratio 2, knee 6 dB; parameter ranges ratio 1–24 (≥ 23.9 treated as ∞), knee 0–24 dB, attack 0–100 ms, release 5–1500 ms `[SRC]` — [Compressor.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/Compressor.cpp), [Constants.h](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/util/include/Constants.h).
- Program-dependent ("auto") time constants from crest factor, CTAGDRC `[SRC]`: peak² and mean-square trackers share one 200 ms coefficient `a = exp(−1/(0.2·fs))`: `peak² = max(x², a·peak² + (1−a)·x²)`, `rms² = a·rms² + (1−a)·x²`, `c² = peak²/rms²`; then `attack = 2·0.08/c²` s and `release = 2·1.0/c² − attack` s (constants `maxAttackTime{0.08}`, `maxReleaseTime{1.0}`), averaged per block — [CrestFactor.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/CrestFactor.cpp), [CrestFactor.h](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/include/CrestFactor.h). (The header comment says "8ms" but the constant is 0.08 s.)
- Squeezer offers three release behaviours over the same gain computer `[SRC]`: "Linear" (log attack, constant-rate release of `10 dB per release-time`: `coef = 10/(t·fs)` dB per sample), "Smooth" (decoupled) and "Logarithmic" (branching, the default) — [side_chain.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/side_chain.cpp). Its optional RMS stage squares-averages-roots the *gain-reduction* signal with a default 10 ms window before the ballistics.
- Squeezer switches between feed-forward and feedback by taking the side-chain sample either from the input or from the *previous output sample* (`SideChainSample = OutputSamples[ch]`) `[SRC]` — [compressor.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/compressor.cpp).
- chowdsp gain computers, linear-domain form `[SRC]`: feed-forward `g = (|x|/T)^(1/R − 1)` above the knee, knee `g_dB = −a_FF·(x_dB − T_dB + W/2)²` with `a_FF = (1 − 1/R)/(2W)`; feedback `g = (|y|/T)^(1 − R)` with `a_FB = (R − 1)/(2W)` — [chowdsp_GainComputerImpls.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/HEAD/modules/dsp/chowdsp_compressor/Compressor/chowdsp_GainComputerImpls.h). Its detectors are a return-to-zero peak follower, a "return-to-threshold" peak follower (releases toward the threshold instead of zero) and an RMS follower (`z = a1·z + b0·x²`, then sqrt) — [chowdsp_LevelDetectorImpls.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/HEAD/modules/dsp/chowdsp_compressor/Compressor/chowdsp_LevelDetectorImpls.h).
- Julius Smith's Faust compressor `[SRC]`: `compression_gain_mono(ratio,thresh,att,rel) = amp_follower_ar(att,rel) : linear2db : outminusindb : si.smooth(tau2pole(att/2)) : db2linear`, with `outminusindb = max(level − thresh, 0)·(1/ratio − 1)`; i.e. linear-domain attack/release peak follower, hard-knee gain computer, then an extra dB-domain one-pole with τ = att/2 that "installs a knee" — [compressors.lib](https://github.com/grame-cncm/faustlibraries/blob/HEAD/compressors.lib).
- Bart Brouns' Faust design (read for the idea; GPL-3.0-only) `[SRC]`: one function with a `prePost` switch that puts the attack/release filter either before the gain computer on `|x|` ("linear return-to-zero detector") or after it on the dB gain ("log domain return-to-threshold detector"); `strength = 1 − 1/ratio`; a feedback/feed-forward cross-fade `FBFF`, where the feedback branch uses `strength × 3` — [compressors.lib](https://github.com/grame-cncm/faustlibraries/blob/HEAD/compressors.lib).
- ZL Compressor's four styles (AGPL, read for the idea) `[SRC]` — [styles/](https://github.com/ZL-Audio/ZLCompressor/tree/HEAD/source/dsp/compressor/styles):
  - Clean: feed-forward; `|x|` → dB → gain computer → follower on dB reduction.
  - Classic: **feedback**; the detector input is the previous *output* sample (`x0_ = in·gain`), follower on dB reduction.
  - Optical: feed-forward; the follower runs on the **linear level before** the dB conversion and gain computer.
  - Vocal: **feedback**, and the follower runs on the **linear gain** (`decibelsToGain(computer.eval(...))`) instead of on dB.
  Its follower blends branching and decoupled smoothing with a "smooth" amount, and has "punch/pump" modes that low-pass the *slope* of the envelope — [ps_follower.hpp](https://github.com/ZL-Audio/ZLCompressor/blob/HEAD/source/dsp/compressor/follower/ps_follower.hpp).
- LSP compressor `[SRC]`: linear-domain envelope `e += τ·(s − e)` with attack τ when rising; when falling it uses the release τ only while `e > release_threshold`, otherwise the attack τ; an optional **hold** counter freezes the envelope after each new peak; the curve is evaluated in the natural-log domain with a quadratic Hermite knee between `T·k` and `T/k` — [Compressor.cpp](https://github.com/lsp-plugins/lsp-dsp-units/blob/HEAD/src/main/dynamics/Compressor.cpp). Its sidechain pre-processor offers Peak, RMS (true sliding-window sum of squares over "reactivity" samples), LPF and Uniform modes — [Sidechain.cpp](https://github.com/lsp-plugins/lsp-dsp-units/blob/HEAD/src/main/util/Sidechain.cpp).
- Calf stereo compressor `[SRC]`: one linear-domain follower `s += (a − s)·coef` on `|x|` (peak) or `x²` (RMS, the default), then gain from a log-domain curve with a cubic-Hermite knee between `T/√knee` and `T·√knee`; defaults threshold 0.125 (−18 dBFS), ratio 2, attack 20 ms, release 250 ms, knee 2.83 (≈ 9 dB) — [modules_comp.cpp](https://github.com/calf-studio-gear/calf/blob/HEAD/src/modules_comp.cpp), [metadata.cpp](https://github.com/calf-studio-gear/calf/blob/HEAD/src/metadata.cpp).
- ZamComp `[SRC]`: Giannoulis-style dB gain computer (knee width `6·knee + 0.01` dB) with branching smoothing of the overshoot, plus an attack "slew" tweak near the threshold (`attack + 2·(slewfactor − 1)` ms when within 1.8 dB of threshold and rising) — [ZamCompPlugin.cpp](https://github.com/zamaudio/zam-plugins/blob/HEAD/plugins/ZamComp/ZamCompPlugin.cpp).

#### 2.2 FET / UREI 1176
- Attack "from a lightning-fast, 20 microsecond attack time to a fast 800 microseconds"; release "from 50 milliseconds at the fastest setting, to 1.1 seconds at the slowest"; ratios 4:1 and 8:1 "for compression", 12:1 and 20:1 "for limiting"; the 1176AE adds 2:1 ("a smooth, soft-knee compression that's perfect for vocals") and a fixed 10 ms "Slo" attack `[WEB]` — [UA 1176 Collection Tips & Tricks](https://www.uaudio.com/blogs/ua/1176-collection-tips).
- "The 1176's Input knob simultaneously sets the threshold level … as well as the amount of signal entering the 1176" — i.e. fixed threshold, variable drive `[WEB]` — same page.
- All-buttons ("British") mode: "compression distortion increases radically"; used "for putting vocals 'in your face'"; "only the 'outside' ratios are relevant to the multi button combinations' sound" `[WEB]` — same page. UA's manual reportedly says the ratio then moves between 12:1 and 20:1 and bias points shift, with a lag on the attack of initial transients `[SEC]` — [UA 1176 manual](https://help.uaudio.com/hc/en-us/articles/34530260482324-1176-Classic-FET-Compressor-Manual).
- Fastest attack plus fastest release: "the attack and release are happening so fast that minute level fluctuations sound like distortion … This trick also sounds great on screaming lead vocals" `[WEB]` — [UA 1176 tips](https://www.uaudio.com/blogs/ua/1176-collection-tips).
- Topology: a FET used as a voltage-controlled resistor; the sidechain taps the signal *after* the FET and feeds the control voltage back to its gate (feedback); higher ratios also raise the threshold; attack and release knobs get *faster* clockwise `[SEC]` — [UA 1176 manual](https://help.uaudio.com/hc/en-us/articles/34530260482324-1176-Classic-FET-Compressor-Manual).
- Julius Smith's Faust 1176-flavoured preset `[SRC]`: `limiter_1176_R4_mono = compressor_mono(4, −6, 0.0008, 0.5)` — ratio 4, threshold −6 dB, attack 800 µs, release 0.5 s — with the comments "att: 800 MICROseconds (Note: scaled by ratio in the 1176). The 1176 range is said to be 20–800 microseconds. Faster attack gives 'more bite' (e.g. on vocals)", "rel: 0.5 s (Note: scaled by ratio in the 1176). The 1176 range is said to be 50–1100 ms", "Mike Shipley likes this (lowest) setting on the 1176", "The 1176 also has a 'bright, clear eq effect'" (not implemented). Ratio guide in the same file: "4 is moderate compression, 8 is strong compression, 12 is mild limiting, and 20 is pretty hard limiting" — [compressors.lib](https://github.com/grame-cncm/faustlibraries/blob/HEAD/compressors.lib). This is a plain feed-forward compressor with 1176 numbers, not a circuit model.
- Squeezer's "FET" gain stage is a pass-through (`dGainReduction = dGainReductionNew`): its FET mode is simply the unmodified detector, not a FET model `[SRC]` — [gain_stage_fet.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/gain_stage_fet.cpp).
- UA's engineers have written that the 1176 being a feedback compressor with a very fast attack is a central difficulty in emulating it at normal sample rates `[SEC]` — [UA WebZine April 2003](https://uaudio.com/webzine/2003/april/text/content2.html) (page returned HTTP 429 to me; only the search summary was seen).
- Typical vocal starting point: the "Dr. Pepper" setting — attack knob at 10 o'clock, release at 2 o'clock, ratio 4:1, then set input and output to taste `[WEB]` — [UA 1176 tips](https://www.uaudio.com/blogs/ua/1176-collection-tips).

#### 2.3 Optical / Teletronix LA-2A, LA-3A
- "The average compression ratio is always set at roughly 3:1, while the average Attack time is 10 milliseconds, and the Release time is about 60 milliseconds for 50% of the release, and anywhere from 1 to 15 seconds for the rest. … this is a program and frequency dependent compressor" `[WEB]` — [UA LA-2A Collection Tips & Tricks](https://www.uaudio.com/blog/la-2a-collection-tips-tricks/). Other spec sheets reportedly give "0.5 to 5 seconds for complete release" `[SEC]` — [UA LA-2A history](https://www.uaudio.com/blog/la-2a-analog-obsession). The two ranges conflict; UA's own article gives both in different places.
- T4 mechanism: "As the input signal increases, the light panel in the T4 cell gets brighter. As the light gets brighter, the photo resistor's impedance [changes], which reduces the gain"; two controls only, Gain (up to +40 dB make-up) and Peak Reduction (acts as threshold) `[WEB]` — [UA LA-2A tips](https://www.uaudio.com/blog/la-2a-collection-tips-tricks/).
- Emphasis (R37): "controls a shelf filter circuit in the compressor's sidechain input … gradually reduces the lower frequency content of the sidechain signal, resulting in compression that is less sensitive to those frequencies, and more sensitive to high frequency content"; fully clockwise = flat `[WEB]` — same page.
- Variants by speed: Silver = "faster time constant", Gray = "medium-speed … lead and background vocals", LA-2 = "slowest response … legato vocals" `[WEB]` — same page.
- LA-3A: UA's manual reportedly lists attack "1.5 ms or less", release 60 ms for 50 % then 0.5–5 s, same T4 elements as the LA-2A; an older UREI catalogue reportedly lists attack < 250 µs–0.5 ms and release 0.5–5 s `[SEC]` — [UA LA-3A specifications](https://www.manualsdir.com/manuals/293297/universal-audio-la-3a.html?page=6), [UREI LA-3A catalogue](https://www.steampoweredradio.com/pdf/urei/catalogs/UREI%20Model%20LA-3A%20Leveling%20Amplifier%20Catalog.pdf). The attack figures conflict.
- Open optical model, Squeezer `GainStageOptical` (GPL-3.0-or-later) `[SRC]` — [gain_stage_optical.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/gain_stage_optical.cpp):
  - It post-processes the already-smoothed dB gain reduction `GR` with a second branching one-pole whose time constants depend on the current gain reduction: `resistance = 480 / (3 + GR_dB)`; `attack_ms = resistance / 10`; `release_ms = resistance`; coefficients `exp(ln(0.27)/(t·fs))` (time to 73 %). Table in the source: 0 dB → 16 ms / 160 ms; 6 dB → 5 / 53 ms; 12 dB → 3 / 32 ms; 18 dB → 2 / 23 ms; 24 dB → 2 / 18 ms. Coefficients are precomputed for 0–36.5 dB in 0.5 dB steps.
  - So the release is fast while gain reduction is deep and slows as it approaches zero — a continuous version of the two-stage release.
  - "Saturation of optical element": if the smoothed `GR` lags below the ideal (unsmoothed) `GR_ideal`, the shortfall `d = GR_ideal − GR` is soft-limited: `d' = 24 − 24/(1 + d/24)` and the stage returns `GR_ideal − d'`.
- Open grey-box LA-2A model (structure only; repo unlicensed) `[SRC]`: static hard- or soft-knee curve in dB → one-pole gain smoothing, with a "TimeVaryOP" variant whose time constant varies → make-up; trained on the SignalTrain LA-2A dataset — [GreyBoxDRC README](https://github.com/Alec-Wright/GreyBoxDRC), [GainSmooth.py](https://github.com/Alec-Wright/GreyBoxDRC/blob/HEAD/Model/GainSmooth.py). No fitted parameter values are stored in the repository.
- A 2025 arXiv paper fits a feed-forward digital compressor to an LA-2A by Newton–Raphson and lists a feedback design and the two-stage release as future work `[SEC]` — [arXiv 2509.10706](https://arxiv.org/abs/2509.10706).

#### 2.4 VCA / dbx 160 and SSL bus compressor
- dbx 160-family "Auto" behaviour: RMS level detector; program-dependent attack "typically 15 ms for 10 dB, 5 ms for 20 dB, 3 ms for 30 dB"; release "typically 120 dB/sec" (160XT manual: 125 dB/s); the 160SL manual says its Auto mode gives "the same attack and release characteristics as dbx Models 160, 161, 162, 163 and 164"; hard knee or OverEasy selectable on later models `[SEC]` — [dbx 160SL manual p.13](https://www.manualsdir.com/manuals/288622/dbx-160sl.html?page=13), [dbx 160XT manual](https://www.manualslib.com/manual/1392726/Dbx-160xt.html?page=18).
- SSL G-series bus compressor: ratios 2:1, 4:1, 10:1; attack 0.1, 0.3, 1, 3, 10, 30 ms; release 0.1, 0.3, 0.6, 1.2 s or Auto; VCA type `[SEC]` — [SOS SSL XLogic G-Series review](https://www.soundonsound.com/reviews/ssl-xlogic-g-series-compressor), [Waves SSL bus compressor guide](https://www.waves.com/how-to-use-ssl-bus-compressor-classic-mix-glue).
- x42 darc — an open, zero-latency, RMS-sensing leveller with automatic make-up (GPL-2.0-or-later) `[SRC]` — [lv2.c](https://github.com/x42/darc.lv2/blob/HEAD/src/lv2.c):
  - Detector works on power: `v = (g_in·x)²` (mean over channels).
  - Threshold as power: `p_thr = 0.5·10^(T_dB/10)`.
  - Attack: `za1 += w_att·(p_thr + v − za1)` with `w_att = 0.5/(fs·attack_s)`.
  - Two cascaded release stages: `if zr1 < za1: zr1 = za1 else zr1 −= w_rel·zr1`; `if zr2 < za1: zr2 = za1 else zr2 += w_rel·(zr1 − zr2)`, with `w_rel = 3.5/(fs·release_s)`.
  - Hold option: releases are frozen while `za1 < 2·p_thr` ("Retain current attenuation when the signal subceeds the threshold. This prevents modulation of the noise-floor and can counter-act 'pumping'").
  - Gain: `gain = g_in · exp(−r·ln(20·zr2))`, `r = 0.5·ratio_param`, where `ratio_param ∈ [0,1]` means 1 − 1/R (scale points: 0.5 = 1:2, 0.666 = 1:3, 0.75 = 1:4, 0.8 = 1:5, 0.9 = 1:10, 1.0 = limiter).
  - Defaults/ranges: threshold −30 dB (−50…−10), attack 10 ms (1–100 ms), release 300 ms (30 ms–3 s) — [darc.ports.ttl.in](https://github.com/x42/darc.lv2/blob/HEAD/lv2ttl/darc.ports.ttl.in).
  - Because the threshold power is *added* to the signal power before the log, the curve is an infinitely soft knee with no branch.

#### 2.5 Vari-mu / Fairchild 670 and Airwindows "mu" compressors
- Fairchild 670 time-constant positions, as reproduced by UA from a Fairchild bulletin: 1 = 0.2 ms attack / 0.3 s release; 2 = 0.2 ms / 0.8 s; 3 = 0.4 ms / 2 s; 4 = 0.8 ms / 5 s; 5 = 0.4 ms / 2–10 s program-dependent; 6 = 0.2 ms / 0.3–10–25 s program-dependent. Other vendors list position 4 as 0.4 ms `[SEC]` — [UA Fairchild help article](https://help.uaudio.com/hc/en-us/articles/13293388042900), [Thomann Fairchild 670](https://www.thomann.co.uk/fairchild_670.htm). Sources conflict on positions 4–6.
- Open WDF model of the 670 (Raffensperger, DAFx-12, "Toward a Wave Digital Filter Model of the Fairchild 670 Limiter"), level time-constant network component values per position, `{C1, C2, C3, R1, R2, R3}` `[SRC]` — [wavechild670.cpp](https://github.com/zamaudio/zam-plugins/blob/HEAD/plugins/ZamChild670/wavechild670.cpp):
  - 1: 2 µF, 8 µF, 20 µF, 51.9 kΩ, open, open
  - 2: 2 µF, 8 µF, 20 µF, 149.9 kΩ, open, open
  - 3: 4 µF, 8 µF, 20 µF, 220 kΩ, open, open
  - 4: 8 µF, 8 µF, 20 µF, 220 kΩ, open, open
  - 5: 4 µF, 8 µF, 20 µF, 220 kΩ, 100 kΩ, open
  - 6: 2 µF, 8 µF, 20 µF, 220 kΩ, 100 kΩ, 100 kΩ
  ("open" is coded as 10 GΩ.) R1·C1 gives 0.104 s, 0.30 s, 0.88 s, 1.76 s for positions 1–4; positions 5 and 6 switch in extra R–C branches (C2 = 8 µF, C3 = 20 µF) that create the slower, program-dependent second and third release stages.
- Airwindows Pressure4 (MIT) — complete algorithm `[SRC]` — [Pressure4Proc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/Pressure4/Pressure4Proc.cpp):
  - Controls A (pressure), B (speed), C (mewiness), D (output). `overallscale = fs/44100`.
  - `threshold = 1 − 0.95·A`; the input is first multiplied by `1/threshold` (so "pressure" is drive plus threshold together).
  - `release = (1.28 − B)^5 · 32768 / overallscale`; `fastest = sqrt(release)`.
  - Two identical gain cells A and B are updated on alternate samples (`flip`).
  - Above threshold (`|x| > threshold`): `target = max(threshold/|x|, threshold)`; `att = sqrt(|speed|)`; `coef = (coef·(att − 1) + target)/att`.
  - Below threshold: `coef = (coef·(speed² − 1) + 1)/speed²` (recovery toward unity, much slower than attack).
  - Speed adapts to the signal every sample: `speed = (speed·(speed − 1) + |x|·release + fastest)/speed` — louder input → larger `speed` → slower ballistics (program dependence).
  - Applied gain: with mewiness `m = 2C − 1`: if `m ≥ 0` gain = `m·coef² + (1 − m)·coef`; if `m < 0` gain = `|m|·sqrt(coef) + (1 − |m|)·coef`. Squaring the coefficient steepens the ratio as reduction deepens (the vari-mu behaviour).
  - Output: `× D`, then a sine soft-clipper `y = sin(x)` for `|x| ≤ π/2`, else ±1.
- Airwindows Pop2 uses the same cell with separate attack and release: `threshold = 1 − (1 − (1−A)²)·0.9`; `attack = (B⁴·100000 + 10)·overallscale`; `release = (C⁵·2000000 + 20)·overallscale`; release speed capped at `4·release`; gain is always `coef²`; pre-gain `1/threshold`, make-up `sqrt(1/threshold)·D`; ClipOnly2 on the output `[SRC]` — [Pop2Proc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/Pop2/Pop2Proc.cpp).
- Airwindows ButterComp2: `inputgain = 10^(A·14/20)`; `compfactor = 0.012·(A/135)`; separate compressors for the positive and negative half-waves, each tracking `(x ± 1)²` with a one-pole whose rate is `compfactor/(1 + |lastOutput|)/overallscale` ("slowing compressor recovery while output waveforms were high"), gain `(1/target)²` `[SRC]` — [ButterComp2Proc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/ButterComp2/ButterComp2Proc.cpp).
- Airwindows curve — a one-state feedback leveller with no controls `[SRC]`: `x *= 0.5; gain = clamp(gain, 0.0078125, 1); x *= gain; gain += sin(min(|4x|, 4))·x⁴; x *= 2` — [curveProc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/curve/curveProc.cpp). Since `sin(4) < 0`, loud output pulls the gain down, quiet output pushes it up; the excerpt has no sample-rate scaling.
- Molot Lite (skimmed only) `[SRC]`: a pre-envelope whose attack/release is chosen from the main attack setting (1 ms / 50 ms when attack ≤ 9.5 ms; 10 ms / 50 ms when ≤ 24.5 ms; else 25 ms / 50 ms), a power-law transfer `y = (x/T)^(1/R)·T` computed with anti-aliased polynomial tables, a soft knee over `(1 − 0.95·knee)·T`, and an attack/release filter containing a polynomial "diode"; two attack modes: "Sigma: accentuates the transients", "Alpha: is smoother" — [moloteng.cpp](https://github.com/magnetophon/molot-lite/blob/HEAD/Molot_Mono_Lite/moloteng.cpp), [README](https://github.com/magnetophon/molot-lite/blob/HEAD/README.md).

#### 2.6 Typical vocal settings and the serial chain
- Generic starting point from UA: ratio between 2:1 and 5:1, medium-fast attack, medium release, raise compression "until you're getting somewhere around 5 dB of gain reduction", match the output level, then "speed up your attack time gradually until it gets noticeable and then back it off slightly" `[WEB]` — [UA Audio Compression Basics](https://www.uaudio.com/blogs/ua/audio-compression-basics).
- Ratio vocabulary: "around 3:1 is considered moderate compression, 5:1 would be medium compression, 8:1 starts getting into strong compression and 20:1 thru ∞:1 would be considered 'limiting'" `[WEB]` — same page.
- Serial 1176 → LA-2A: Sound On Sound reportedly recommends the 1176 first with fairly fast action and a fairly high ratio (8:1 up to all-buttons) so the LA-2A receives a more manageable signal, and notes the order can be reversed `[SEC]` — [SOS Multi-stage compression](https://www.soundonsound.com/techniques/multi-stage-compression). A UA article reportedly lists a faster-release 4:1 1176 setting for album vocals and "light to moderate" LA-2A gain reduction `[SEC]` — [UA: How to use LA-2A and 1176 in your mix](https://www.uaudio.com/blogs/ua/how-to-use-the-la-2a-and-1176-in-your-mix).

### Inferences
- **Why the 1176 sounds aggressive.** Three verified facts combine: feedback detection, attack shorter than one audio cycle (20–800 µs), and fast release (down to 50 ms). The gain then follows the waveform itself, which is distortion; UA says exactly this about the fastest settings.
- **Digital feedback loop maths (derived, not from a source).** With a one-sample-delayed feedback detector, dB-domain one-pole smoothing coefficient α and a hard-knee feedback gain law `c = −(R − 1)·max(0, y_dB − T)`, the gain reduction obeys `g[n] = (1 − (1−α)·R)·g[n−1] − (1−α)(R−1)(x_dB − T)`. Steady state is `−(1 − 1/R)(x − T)`, i.e. the true ratio R. The loop pole is `1 − (1−α)·R`: the loop is stable only if `(1−α)·R < 2` and non-ringing only if `(1−α)·R ≤ 1`. Consequences: (i) the effective attack is R times faster than the nominal time constant — consistent with Julius Smith's note that 1176 times are "scaled by ratio"; (ii) at 48 kHz a 20 µs nominal attack (`1−α ≈ 0.65`) with R = 20 is unstable, so a Rust FET model must set `1−α = (1−α_wanted)/R`, or solve the one-sample loop implicitly, or oversample the side-chain.
- **Where the smoothing sits decides the release shape.** Smoothing dB gain reduction (Clean, CTAGDRC) gives a release that is linear in dB per unit time constant; smoothing the linear level before the log (ZL "Optical", Calf, LSP, Faust `amp_follower_ar`) makes release slower in dB terms after loud passages and fast for small overshoots; smoothing linear gain (ZL "Vocal") recovers quickly at first from deep reduction. These three placements are a cheap way to get three audibly different compressors from one code path.
- **LA-2A two-stage release from "60 ms for 50 %".** A first-stage exponential that halves in 60 ms has τ = 60/ln 2 ≈ 87 ms. The second stage needs τ of roughly 1–3 s to match "0.5–5 s" (or "1–15 s") for the remainder. Squeezer's `480/(3 + GR)` law is a single-state approximation; a two-state version (fast envelope plus a slow "memory" envelope that charges with the duration and depth of compression) matches the described memory effect more literally.
- **Vari-mu "ratio rises with level"** can be had without a tube model either by a very wide quadratic knee (20–30 dB) or by darc's additive-power law, or by Pressure4's `coef²` blend.

### Gaps
- The JAES paper itself was not readable, so I cannot quote its own recommendation sentence, its exact equation numbering, or its measured artefact figures. The claim that it recommends a feed-forward, log-domain, smooth decoupled/branching detector after the gain computer is supported here only by what implementers (CTAGDRC README) say.
- No open, licensed, circuit-level 1176 model was found. I found no DAFx paper on the 1176 through search; a known AES-convention paper on the 1176LN (Gerat, Sierra, Zölzer) could not be checked from here.
- No source I could open gives the 1176's program-dependent release mechanism, FET distortion spectrum, or the exact threshold shift per ratio button. The harmonic colour of a FET/optical/vari-mu mode is therefore not specified by any verified constant in these notes.
- I could not verify whether the LA-2A's side-chain is taken before or after the T4 attenuator (feed-forward vs feedback); no schematic was readable.
- The often-quoted vocal targets "3–7 dB on the 1176, 3–5 dB on the LA-2A" were not found in any source I could open; only "around 5 dB" (UA basics) and "light to moderate" (UA, secondary).
- dbx 160 "thump" and its true-RMS detector time constant: nothing readable.
- Molot's engine was only skimmed; Logical4, Pressure5/6, Pop3, Dynamics, SurgeTide, Thunder, BrassRider, VariMu and Pyewacket source were not read line by line.

## 3. How should auto make-up gain be computed so level stays consistent as the user turns one "amount" knob?

### Takeaway
Open code uses four different laws: (1) a fixed fraction of the static gain reduction at a reference level (Squeezer: half of the reduction a full-scale signal would get; chowdsp: all of the reduction at a chosen target level), (2) a slow running average of the actual gain reduction (CTAGDRC), (3) a curve built so that one pivot level always has unity gain (x42 darc: −10 dBFS RMS), and (4) "drive into a fixed threshold" where the amount knob is input gain and output is trimmed by its square root (Airwindows Pop2). For a single amount knob, the pivot law is the most predictable because it is static and has no time-varying side effects.

### Cited Findings
- Squeezer `[SRC]`: internal levels are offset by `CrestFactor = 20` dB (`SideChainLevel = dB(|x|) + CrestFactor`), and `dGainCompensation = queryGainComputer(dCrestFactorAutoGain) / 2.0` with `dCrestFactorAutoGain = 20.0`. So auto make-up = **half of the static gain reduction that a 0 dBFS peak would receive**, recomputed whenever threshold, ratio or knee changes — [side_chain.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/side_chain.cpp), [compressor.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/compressor.cpp).
- chowdsp `[SRC]`: feed-forward make-up (linear) = `(target/T)^(1 − 1/R)`, i.e. `makeup_dB = (target_dB − T_dB)·(1 − 1/R)` = the **full** static reduction at the target level (default target 0 dB); feedback version uses exponent `(R − 1)` — [chowdsp_GainComputerImpls.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/HEAD/modules/dsp/chowdsp_compressor/Compressor/chowdsp_GainComputerImpls.h), [chowdsp_MonoCompressor.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/HEAD/modules/dsp/chowdsp_compressor/Compressor/chowdsp_MonoCompressor.h).
- CTAGDRC `[SRC]`: `autoMakeup = −mean(smoothed gain reduction in dB over the block)`, passed through a one-pole with per-block coefficient 0.03 (`state = 0.03·new + 0.97·state`) — [Compressor.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/Compressor.cpp). The author warns: "This is a time-varying effect and may introduce unwanted volume changes to the output signal" — [README](https://github.com/p-hlp/CTAGDRC/blob/HEAD/README.md). The per-block coefficient makes its speed depend on buffer size.
- x42 darc `[SRC]`: "Makeup gain is automatically set to retain equal loudness at −10 dBFS/RMS with a soft knee. This maintains perceived loudness over a wide range of thresholds and ratio settings" — [README](https://github.com/x42/darc.lv2/blob/HEAD/README.md). From the code, `gain_dB = −ρ·10·log10(20·(p_thr + P))` with `ρ = 1 − 1/R`, `p_thr = 0.5·10^(T/10)`, `P` = smoothed signal power: gain is exactly 0 dB whenever `p_thr + P = 0.05`, and the low-level boost is `−ρ·(10 + T_dB)` dB (e.g. T = −30 dB, 4:1 → +15 dB) — derived from [lv2.c](https://github.com/x42/darc.lv2/blob/HEAD/src/lv2.c).
- Airwindows `[SRC]`: Pressure4 applies `1/threshold` as *pre*-gain and leaves output trim to the user; Pop2 applies pre-gain `1/threshold` and make-up `sqrt(1/threshold)·D` — [Pressure4Proc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/Pressure4/Pressure4Proc.cpp), [Pop2Proc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/Pop2/Pop2Proc.cpp). Airwindows Pop3 deliberately has none: "It doesn't use makeup gain, so you use it to restrain the sound" — [Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/HEAD/Airwindopedia.txt).
- LA-2A / 1176 practice: make-up is a manual output knob matched by ear against bypass `[WEB]` — [UA 1176 tips](https://www.uaudio.com/blogs/ua/1176-collection-tips).

### Inferences
- **Recommended law for one "amount" knob (derived).** Pick a pivot level `L_p` that represents the singer's loud passages (for a peak detector, about −12 dBFS peak; let the app calibrate it from the input meter). Map amount `a ∈ [0,1]` to threshold `T(a)` (and optionally ratio `R(a)`), and set `makeup_dB(a) = k · GR_static(L_p; T(a), R(a), W)` where `GR_static` is the soft-knee formula of §2.1 and `k` is between 0.5 (Squeezer) and 1.0 (chowdsp). With `k = 1` the pivot level is held exactly constant as the knob turns; with `k = 0.5–0.7` perceived loudness stays more constant because average vocal level sits below the peaks. Start at `k = 0.7`.
- The make-up must be smoothed (20–50 ms one-pole on the dB value) when the knob moves, never driven by programme content, so it cannot pump.
- A programme-adaptive make-up (CTAGDRC style) should not be used in a live monitoring chain: it raises the noise floor and breaths during pauses and changes level while the singer listens.
- For the feedback (FET) character the same static formula applies, because the steady-state curve of the feedback loop is the ratio-R curve (see §2 inference).
- For a drive-style FET mode, Pop2's `sqrt(1/threshold)` trim (half the drive in dB) is the same idea as Squeezer's "half the reduction".

### Gaps
- No source measured which make-up law keeps *loudness* (LUFS) most constant on vocals; the choice of `k` is a judgement to be tuned by ear.
- I could not read how ZL Compressor, LSP or commercial units compute auto-gain.

## 4. Sample-rate independence of time constants: issues and how good open code handles them

### Takeaway
Every well-behaved project derives the one-pole coefficient from the sample rate with an exponential, but they disagree on what "attack time" means — the same "10 ms" is a different time constant in each code base (63 %, 70.7 %, 73 %, 90 %, 10–90 %, or 2π·τ). Ported presets must therefore be converted to a common τ. Code that hard-wires per-sample coefficients (stmlib limiter, Airwindows curve) or per-block coefficients (CTAGDRC auto make-up) is not rate-independent and must be rescaled.

### Cited Findings
| Project | Coefficient formula as written | Meaning of the user's "time" t | Equivalent τ (63 %) |
|---|---|---|---|
| CTAGDRC, chowdsp, Faust `tau2pole`, Calf mono, ZamComp | `α = exp(−1/(t·fs))` | time to 63 % | τ = t |
| Squeezer (attack, release, RMS window) | `exp(ln(0.10)/(t·fs))` — "reaches 90 % of the final reading" | time to 90 % | τ = t/2.303 |
| Squeezer optical stage | `exp(ln(0.27)/(t·fs))` — "reach 73 %" | time to 73 % | τ = t/1.309 |
| LSP Compressor / Gate / Expander | `1 − exp(ln(1 − 1/√2)/N)`, `N = millis_to_samples` | time to 70.7 % | τ = t/1.228 |

### Inferences
- Store every time in seconds as a true τ and compute `α = exp(−1/(τ·fs))` in `f64` at prepare/parameter-change time; never per sample. Convert ported presets with the table above.
- At 48 kHz one sample is 20.8 µs, so the 1176's 20 µs attack is one sample: the fastest FET setting is "instant" at 44.1/48 kHz and only becomes a real time constant at 96 kHz. Sub-sample attacks therefore sound different at different rates unless the side-chain is oversampled — which is the difficulty UA described (secondary).
- Slew- and sample-difference-based detectors (Airwindows DeEss/DeBess) are inherently rate-dependent because a first difference scales with 1/fs and their squared products with higher powers; the `8192/overallscale` factor only partly compensates. A band-energy de-esser is rate-independent by construction.
- Feedback compressors add a one-sample loop delay whose effect on stability scales with fs (§2 inference); the `(1−α)·R ≤ 1` guard handles all rates.
- Hold times, RMS windows and ClipOnly-style spacing must be converted from seconds to samples at prepare time, with buffers pre-allocated for the highest supported rate (no per-sample allocation).

### Gaps
- I did not measure any of these implementations at 44.1/48/96 kHz; the statements about rate (in)dependence are read from code only.
- How Airwindows intends DeBess to behave at 96 kHz is not documented in the source I read.

## 5. Avoiding distortion from fast attack/release at low frequencies (detector ripple) without look-ahead

### Takeaway
With no look-ahead, ripple is controlled by (a) keeping low frequencies out of the detector with a side-chain high-pass, (b) smoothing the control signal with a decoupled (release-then-attack) or two-stage release filter instead of a single branching one-pole, (c) RMS/power detection with a short window, and (d) hold. All four exist in readable open code.

### Cited Findings
- The mechanism: "Fast attack times may create distortion by modifying inherently slow-moving low frequency waveforms (Ex. If a cycle at 100 Hz lasts 10 ms, then a 1 ms attack time will have time to alter the waveform, which will generate distortion)"; and release "should be set as short as possible without producing a 'pumping' effect" `[WEB]` — [UA Audio Compression Basics](https://www.uaudio.com/blogs/ua/audio-compression-basics).
- Side-chain high-pass: Squeezer has a 2nd-order high-pass (Q 0.707) and low-pass in the side-chain, enabled when the HPF cutoff is above 20 Hz or the LPF below 15 kHz `[SRC]` — [compressor.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/compressor.cpp). The LA-2A's Emphasis control is the analog precedent (reduces lows in the side-chain) `[WEB]` — [UA LA-2A tips](https://www.uaudio.com/blog/la-2a-collection-tips-tricks/). Calf's side-chain compressor offers RBJ high-pass/low-pass/shelf/peak side-chain filters at Q 0.707 `[SRC]` — [modules_comp.cpp](https://github.com/calf-studio-gear/calf/blob/HEAD/src/modules_comp.cpp).
- Decoupled smoothing: `y1 = max(c, αR·y1 + (1−αR)·c)` then `y = αA·y + (1−αA)·y1` — the attack filter also smooths the release ripple `[SRC]` — [CTAGDRC LevelDetector.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/LevelDetector.cpp), [Calf mono compressor](https://github.com/calf-studio-gear/calf/blob/HEAD/src/modules_comp.cpp). ZL exposes a continuous blend between branching and decoupled ("smooth") `[SRC]` — [ps_follower.hpp](https://github.com/ZL-Audio/ZLCompressor/blob/HEAD/source/dsp/compressor/follower/ps_follower.hpp).
- Smoothing after the gain computer in the log domain, so the filter "does not have to operate on the whole dynamic range of the input signal" `[SRC]` — [CTAGDRC README](https://github.com/p-hlp/CTAGDRC/blob/HEAD/README.md).
- Two cascaded release stages (darc `zr1 → zr2`) give an S-shaped release start, and darc detects power (`x²`) rather than `|x|` `[SRC]` — [lv2.c](https://github.com/x42/darc.lv2/blob/HEAD/src/lv2.c).
- RMS windows: Squeezer default 10 ms (exponential, on the gain-reduction signal) — [side_chain.cpp](https://github.com/mzuther/Squeezer/blob/HEAD/Source/side_chain.cpp); LSP true sliding-window RMS over "reactivity" samples — [Sidechain.cpp](https://github.com/lsp-plugins/lsp-dsp-units/blob/HEAD/src/main/util/Sidechain.cpp); Faust `ba.slidingRMS` in `RMS_compression_gain_mono_db` — [compressors.lib](https://github.com/grame-cncm/faustlibraries/blob/HEAD/compressors.lib); chowdsp RMS follower — [chowdsp_LevelDetectorImpls.h](https://github.com/Chowdhury-DSP/chowdsp_utils/blob/HEAD/modules/dsp/chowdsp_compressor/Compressor/chowdsp_LevelDetectorImpls.h). CTAGDRC's author chose peak detection because "rms detection introduces a significant delay" (in reaction, not latency) — [README](https://github.com/p-hlp/CTAGDRC/blob/HEAD/README.md).
- Hold: LSP compressor/gate/expander re-arm a hold counter on every new envelope peak and freeze the envelope while it counts down — [Compressor.cpp](https://github.com/lsp-plugins/lsp-dsp-units/blob/HEAD/src/main/dynamics/Compressor.cpp); the public-domain safety limiter holds its gain for 100 ms after each peak before a 100 ms release — [safety_limiter.hpp](https://github.com/nhthn/safety-limiter/blob/HEAD/safety_limiter.hpp); darc freezes release below threshold — [lv2.c](https://github.com/x42/darc.lv2/blob/HEAD/src/lv2.c).
- Programme-dependent release that lengthens on sustained material: CTAGDRC crest-factor automation (release up to 1 s for low crest factor) — [CrestFactor.cpp](https://github.com/p-hlp/CTAGDRC/blob/HEAD/Source/dsp/CrestFactor.cpp); Airwindows Pressure4 slows with level, ButterComp2 slows release "while output waveforms were high" — [Pressure4Proc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/Pressure4/Pressure4Proc.cpp), [ButterComp2Proc.cpp](https://github.com/airwindows/airwindows/blob/HEAD/plugins/LinuxVST/src/ButterComp2/ButterComp2Proc.cpp).
- Alternating two gain cells on odd/even samples (Airwindows `flip`) halves each cell's update rate; it is used in Pressure4, Pop2, DeEss, Gatelope `[SRC]` — files as cited above.
- Gain smoothing in the slope domain: ZL "punch/pump" low-passes the per-sample change of the envelope `[SRC]` — [ps_follower.hpp](https://github.com/ZL-Audio/ZLCompressor/blob/HEAD/source/dsp/compressor/follower/ps_follower.hpp).

### Inferences
- For a voice, the lowest fundamental is roughly 80–100 Hz (period 10–12.5 ms). A release τ shorter than about two periods (≈ 25 ms) will follow the waveform; the 1176's fastest release (50 ms) sits just above that, which is why it is "aggressive but usable", and why fastest-attack-plus-fastest-release is described as distortion.
- A practical zero-latency recipe: side-chain 2nd-order Butterworth high-pass at 100–150 Hz (default on for vocals); `|x|` → dB → gain computer → **decoupled** smoothing; floor release τ at 30 ms in "clean" modes; add a 5–10 ms hold on the gain-reduction peak in the clean and limiter modes; allow shorter values only in the FET mode where the distortion is the point.
- Hold is the cheapest ripple killer that adds no latency: a hold of one period of the lowest expected fundamental (≈ 10–12 ms) makes the release start from a flat top instead of a sawtooth.
- Power (x²) detection halves the ripple frequency content problem for sines (x² has a DC term plus 2f), and combined with a 5–10 ms one-pole gives a usable "RMS" mode without a window buffer.

### Gaps
- No readable source quantified THD versus attack/release for these designs; the safety-limiter README claims "low THD tested on sine tones" without numbers.
- The Giannoulis paper's own artefact comparison (which detector gives least ripple) could not be read.
