### smplr (danigb/smplr) v1.2.0, last commit 2026-11-07 - read 2026-11-18
- [SRC] package.json "license": "MIT" (no LICENSE file at repo root). https://github.com/danigb/smplr
- [SRC] README: instruments SplendidGrandPiano ("Sampled Steinway grand, 4 velocity layers"), ElectricPiano (CP80, PianetT, WurlitzerEP200, TX81Z; samples from sfzinstruments/GregSullivan.E-Pianos; "Includes a (basic) tremolo effect"), DrumMachine, Mallet (VCSL), Soundfont, Sampler, Mellotron, Smolken, Versilian, Reverb, Sequencer.
- [SRC] smplr API: start({note, velocity, time, duration}) returns stop fn; setCC(64,127) sustain pedal; notesToLoad {notes, velocityRange, fallback:"nearest"} loads a subset and pitch-shifts the nearest loaded sample; formats default ["ogg","m4a"]; decayTime default 0.5 s release; storage: HttpStorage default or CacheStorage() which uses the Cache API and "only works in secure environments that run over https"; shared SampleLoader for buffer reuse; renderOffline(cb, {duration, sampleRate:48000, channels:2}) uses OfflineAudioContext and result.toWav() encodes 32-bit float WAV. https://github.com/danigb/smplr/blob/main/README.md

- [SRC] smplr internals (src/smplr/voice.ts): one AudioBufferSourceNode per voice; pitch shift via source.detune (cents) with playbackRate = 2^(cents/1200) fallback for Safari; optional loop (loopAuto ratios or loopStart/loopEnd); lowpass BiquadFilter only inserted when cutoff < 20 kHz or modulated; velocity gain = midiVelToGain(vel) x dB volume; DAHDS amp envelope + release scheduled from the actual level at note-off (adsrValueAt) so no click; voice stealing (voice-manager.ts) with 10 ms linear fade, prefers releasing then oldest voices over maxVoices. https://github.com/danigb/smplr/blob/main/src/smplr/voice.ts , .../voice-manager.ts
- [SRC] smplr sustain pedal: setCC(64, v) only changes the CC state used for region matching ("Affects region matching for groups/regions that have ccRange constraints (e.g. CC64 sustain pedal)") - it does NOT hold notes after note-off. A damper/hold behaviour must be implemented by the app (defer stop() while pedal is down). Region types support seqPosition/seqLength round robin, offBy groups, trigger "first" | "legato" - no release-triggered regions (so Salamander's hammer-release and string-resonance release samples would need custom code). https://github.com/danigb/smplr/blob/main/src/smplr/smplr.ts , .../types.ts , .../region-matcher.ts
- [SRC] smplr format pick (src/smplr/load-audio.ts): uses audio.canPlayType("audio/<fmt>"); "Safari reports it can play OGG but decodeAudioData fails on many samples" so OGG is skipped on Safari and the m4a/AAC fallback is used. Buffers decoded with context.decodeAudioData. CacheStorage backend (src/storage.ts) = caches.open(name), cache.match, cache.put(response.clone()). https://github.com/danigb/smplr/blob/main/src/smplr/load-audio.ts , https://github.com/danigb/smplr/blob/main/src/storage.ts
- Licence verdict smplr: MIT -> PORT (MIT code can be included in GPL-3.0-or-later; keep MIT notice).

### Codec experiment (my measurement) on Salamander C4v8.flac (16.19 s, 48 kHz/24-bit stereo, 1733 KiB FLAC)
- [CALC] ffmpeg 6.1.1 encodes (libopus, libvorbis, libmp3lame, ffmpeg native aac); sizes for this one 16.2 s stereo note: FLAC 24-bit 1733 KiB; FLAC 16-bit 469 KiB; Opus 64k 154 KiB; Opus 96k 240 KiB; Opus 128k 314 KiB; Vorbis q4 196 KiB; Vorbis q6 282 KiB; MP3 V2 198 KiB; MP3 128k CBR 254 KiB; AAC 128k 256 KiB; AAC 192k 381 KiB; Opus 64k mono 143 KiB. Opus 96k is 7.2x smaller than the 24-bit FLAC and 2.0x smaller than 16-bit FLAC.
- [CALC] Crude objective error vs reference (log-spectral distance over bins within 50 dB of each frame's peak, frames within 45 dB of loudest; and waveform frame SNR): Opus64 LSD 2.26 dB / median SNR 26.3 dB; Opus96 1.47 / 29.2; Opus128 1.12 / 30.3; Vorbis q4 1.97 / 31.4; Vorbis q6 1.36 / 34.7; MP3 V2 0.90 / 37.3; AAC128 (ffmpeg native) 1.12 / 32.0; FLAC16 0.21 / 51.0. Caveat: waveform SNR and LSD are NOT perceptual quality measures (Opus/CELT preserves band energy rather than waveform), so these only show that all lossy codecs at >= 96 kb/s keep the spectral envelope within ~1-1.5 dB on audible bins; a listening test is still needed. Script: scratchpad codecq2.py.
- [CALC] Note: no codec here showed any loss of the 16-20 kHz band for this note (its 16-20 kHz energy share is -77.6 dB of total, i.e. negligible for a mid-range piano note), so lowpass behaviour of codecs is irrelevant for piano.
