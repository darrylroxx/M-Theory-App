## RAW LOG 3 — Musly (MPL-2.0 → PORT, keep MPL notice on ported files) timbre similarity, read from source
- [SRC] Licence: "The source code is released under the MPL 2.0" (README), COPYING = Mozilla Public License 2.0. — https://github.com/dominikschnitzer/musly/blob/master/README.md
- [SRC] `timbre` method (Musly's default, priority 1): sample_rate 22050, window 1024 (Hann), hop 0.5 (50 %), analyses only the central 60 s (`max_pcmlength = 60*sample_rate`; start = (length − 60 s)/2), 36 mel bins, 25 MFCCs, single full-covariance Gaussian; similarity = Jensen–Shannon divergence between Gaussians, then normalised with Mutual Proximity (about(): "D. Schnitzer et al.: Using mutual proximity to improve content-based audio similarity. ISMIR 2011"). — https://github.com/dominikschnitzer/musly/blob/master/libmusly/methods/timbre.cpp
- [SRC] `mandelellis` method: same front end but 20 MFCCs and symmetrised Kullback–Leibler divergence ("M. Mandel and D. Ellis … Song-level features and support vector machines for music classification. ISMIR 2005"). — https://github.com/dominikschnitzer/musly/blob/master/libmusly/methods/mandelellis.cpp
- [SRC] Front end: mel filters from 20 Hz to sr/2, `mel = 1127.01048·ln(1 + f/700)`, triangular filters equally spaced in mel (melspectrum.cpp); MFCC = DCT-II of `log(1 + mel_power)` (mfcc.cpp `dct.compress((1.0f + mel.array()).log())`), DCT matrix `1/sqrt(n/2)·cos(...·π/2/n)` with row 0 × √2/2 (discretecosinetransform.cpp). — https://github.com/dominikschnitzer/musly/tree/master/libmusly
- [SRC] Gaussian estimation: sample mean; sample covariance /(N−1); `covar.diagonal() += 1e-4` "to avoid singular covariance matrices in case the input data was silence"; stores upper triangle + log|Σ| (FullPivHouseholderQR). — https://github.com/dominikschnitzer/musly/blob/master/libmusly/gaussianstatistics.cpp
- [SRC] Jensen–Shannon distance as coded: `jsd = −¼(log|Σ0| + log|Σ1|) + ½ log|Σm|` where merged Gaussian has `Σm = ½(Σ0 + Σ1) + δδᵀ`, `δ = ½(μ0 − μ1)` (½log|Σm| computed as Σ log of Cholesky diagonal); returns `sqrt(max(0, jsd))`. — same file
- [SRC] Mutual Proximity: for each track keep mean μ and std σ of its distances to a reference set ("music style" tracks); `p1 = 1 − Φ((d − μ_seed)/σ_seed)`, `p2 = 1 − Φ((d − μ_other)/σ_other)`, normalised distance `1 − p1·p2`; Φ by Abramowitz–Stegun 7.1.26. Purpose: reduce "hubs" (songs that are near everything). — https://github.com/dominikschnitzer/musly/blob/master/libmusly/mutualproximity.cpp
- [CALC] Size of the timbre fingerprint: 25 means + 25·26/2 = 325 covariance terms + 1 logdet = 351 floats (1.4 kB). Live cost: one 1024-pt FFT per 512 samples at 22.05 kHz ≈ 43 frames/s; running mean/covariance updatable incrementally (Welford) per frame.
- [CALC] Note on gain robustness: because MFCC uses log(1 + P) not log(P), a global gain change g shifts c0 by ≈ log g only where P ≫ 1; c0 (and to a lesser degree c1) carries loudness/tilt. Dropping c0 (or z-normalising per track) is the standard fix [SEC]; Musly keeps c0 in its 25 coefficients (as read: DCT row 0 kept).

## RAW LOG 4 — essentia high-level descriptors (AGPL-3.0 → FORMULA only), read at commit 23ae7ba / master
- [SRC] Danceability (Streich & Herrera 2005, DFA): signal cut into 10 ms frames; s(n) = std-dev of samples in each frame; subtract mean; integrate (cumulative sum); for τ from minTau 310 ms to maxTau 8800 ms, multiplied by tauMultiplier 1.1 each step (τ in 10 ms blocks), slide blocks (jump = max(τ/50, 1)), F(τ) = sqrt(mean residual error of a linear fit per block); DFA exponents `α_i = log10(F(τ_{i+1})/F(τ_i)) / log10((τ_{i+1}+3)/(τ_i+3))`; danceability = 1 / mean(α); "values usually range from 0 to 3 (higher values meaning more danceable)". — https://github.com/MTG/essentia/blob/23ae7ba/src/algorithms/highlevel/danceability.cpp ; params in danceability.h
- [SRC] DynamicComplexity (Streich 2007): "average absolute deviation from the global loudness level estimate on the dB scale"; frameSize 0.2 s; "cheap B-curve loudness compensation" = 1-pole high-pass b = {0.98595, −0.98595}, a = {1, −0.9719}; energy smoothed with time constant 35 ms (`c = exp(−1/(0.035·sr))`); per-frame dB; leading/trailing silence removed; global loudness = weighted mean of dB with weights `u_i = 0.9^(−dB_i)` normalised (loud frames dominate); complexity = mean |dB_i − loudness|; comment: half silent/half full scale would give 45 → "safe normalization would be using 45". — https://github.com/MTG/essentia/blob/23ae7ba/src/algorithms/highlevel/dynamiccomplexity.cpp
- [SRC] Intensity (relaxed −1 / moderate 0 / aggressive 1) from spectral complexity, rolloff, spectral peaks, kurtosis: flagged in its own doc as "Quality: outdated (non-reliable, poor accuracy)". — https://github.com/MTG/essentia/blob/23ae7ba/src/algorithms/highlevel/intensity.cpp
- [SRC] SpectralContrast (octave-based spectral contrast, modified): defaults frameSize 2048, sr 22050, numberBands 6, lowFrequencyBound 20 Hz, highFrequencyBound 11000 Hz, neighbourRatio 0.4 (fraction of bins per band used for peak/valley means), staticDistribution 0.15 (share of bins spread equally; the rest spaced logarithmically); per band contrast `sc = −(peak/valley)^(1/ln(bandMean))`, valley output `ln(valley)`. — https://github.com/MTG/essentia/blob/23ae7ba/src/algorithms/spectral/spectralcontrast.cpp , spectralcontrast.h
- [CALC] Contrast is a ratio peak/valley inside a band → invariant to a global gain (both scale equally) and only weakly affected by EQ that is smooth across one band; valleys (log) still shift with gain. So contrast is a good "texture" feature (tonal peaks vs noise floor) robust to mastering loudness.

## RAW LOG 8 — Hertzmann painterly loop (PyPainterly, GPL-3.0 → PORT), fieldplay, spectro
- [SRC] PyPainterly implements "Painterly rendering with curved brush strokes of multiple sizes" (SIGGRAPH 98). `paint(source, R, T=100 (CLI default 20), curved=True, f_g=1)`: for each radius r in R from largest to smallest (e.g. `--r 8 4 2`): reference = Gaussian blur of the source with kernel ≈ r; D = mean |canvas − reference| per pixel; grid = f_g·r; for each grid cell, areaError = mean of D over the cell; if areaError > T place a stroke there (straight variant starts at the cell's max-error pixel); curved stroke: start colour = reference at start; step R pixels along the normal to the Sobel gradient `(dx, dy) = (−gy, gx)`, flip to keep direction, filter with curvature factor fc `d = fc·d + (1 − fc)·d_last`; stop when length > min (2 % of width) and the canvas is already closer to the reference than the stroke colour, or the gradient vanishes, or length reaches max (10 % of width). — https://github.com/pschaldenbrand/PyPainterly/blob/master/painterly.py ; README https://github.com/pschaldenbrand/PyPainterly
- [CALC/DESIGN link] The loop is a coverage controller: it only paints where |target − canvas| exceeds T, coarse-to-fine. Replace "reference image" with a music-driven target field (what each layer wants at each place, e.g. target density/colour) and the same rule gives "paint only as much as the music asks for": quiet music → small target → error stays under T → bare ground remains.
