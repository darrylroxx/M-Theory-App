## 1. Oscillators: PolyBLEP/PolyBLAMP, minBLEP, wavetables, supersaw, PWM, hard sync, ring mod, FM, sub/noise, drift

### Takeaway
Use 2-sample PolyBLEP (saw/pulse) and PolyBLAMP (triangle) for the cheap per-voice path, and a minBLEP (or Signalsmith elliptic BLEP) ring buffer for hard sync and very bright patches; the exact equations and tables are available in GPL-3.0-or-later (VCV), zlib (Tale PolyBLEP), MIT (AMY, elliptic-blep) and STK/LGPL (Faust) code, all portable. The supersaw is 7 saws with Szabo's published detune polynomial, offsets and mix curves, random free-running phases and a high-pass at the fundamental; FM should be phase modulation with the DX-style two-sample feedback average, oversampled 2x only when the index is high.

### Cited Findings
PolyBLEP / PolyBLAMP
- [SRC] Two-sample PolyBLEP residual (t = phase in [0,1), dt = f/fs): `blep(t,dt) = t<dt ? -(t/dt-1)^2 : t>1-dt ? ((t-1)/dt+1)^2 : 0`; saw `t' = frac(t+0.5); y = 2t'-1 - blep(t',dt)`; square `y = (t<0.5?1:-1) + blep(t) - blep(frac(t+0.5))`; variable-width rectangle `t2 = frac(t+1-pw); y = -2pw + (t<pw?2:0) + blep(t) - blep(t2)` (DC-free by construction); the code cites Kleimola, Lazzarini, Timoney, Välimäki, "Phaseshaping Oscillator Algorithms" (SMC 2010). — [PolyBLEP.cpp (Tale, C++ port by M. Finke)](https://github.com/martinfinke/PolyBLEP/blob/master/PolyBLEP.cpp)
- [CALC] Algebra check: `-(x-1)^2 = 2x - x^2 - 1` (x=t/dt) and `(x+1)^2 = x^2 + 2x + 1` (x=(t-1)/dt), identical to the textbook PolyBLEP used by Faust below.
- [SRC] PolyBLAMP (integrated BLEP for slope corners): `blamp = t<dt ? -(1/3)(t/dt-1)^3 : t>1-dt ? (1/3)((t-1)/dt+1)^3 : 0`; triangle = naive folded `4t` triangle `+ 4*dt*(blamp(frac(t+0.25)) - blamp(frac(t+0.75)))`; the same file has BLAMP-corrected trapezoid, half/full-rectified sine and a variable-slope triangle (`dt/(pw - pw^2)` scaling). — [PolyBLEP.cpp](https://github.com/martinfinke/PolyBLEP/blob/master/PolyBLEP.cpp)
- [SRC] That generator falls back to a pure sine when f ≥ fs/4 (`if (getFreqInHz() >= sampleRate/4) return sin();`) — a guard against PolyBLEP's weak alias rejection near Nyquist. — [PolyBLEP.cpp](https://github.com/martinfinke/PolyBLEP/blob/master/PolyBLEP.cpp)
- [SRC] Faust `os.polyblep(Q, phase)` (author Jacek Wieczorek): `L(x) = 2x - x^2 - 1` for phase < Q (x = phase/Q), `R(x) = 2x + x^2 + 1` for phase > 1-Q (x = (phase-1)/Q); `polyblep_saw(freq) = (2*phase-1) - polyblep(freq/SR, phase)`; the library also has DPW `sawN(N,freq)`, `saw2dpw`, `pulsetrainN = diffdel(sawN)`. — [faustlibraries oscillators.lib lines 1148-1731, 3099-3160](https://github.com/grame-cncm/faustlibraries/blob/master/oscillators.lib)
- [SRC] DPW alternative used by the Surge team: near the wrap (p < 3dp or p > 1-3dp) evaluate the integrated cubic `c(x) = (x^2-1)x/6` (x = 2p-1) at p-dp, p, p+dp and output `(c0 + c2 - 2c1)/(4dp^2)`, elsewhere the trivial `2p-1`; pulse = saw(p) - saw(p+pw). — [sst-basic-blocks DPWSawPulseOscillator.h](https://github.com/surge-synthesizer/sst-basic-blocks/blob/main/include/sst/basic-blocks/dsp/DPWSawPulseOscillator.h)
- [SEC] Primary papers (not reachable here): Välimäki & Huovilainen, "Antialiasing oscillators in subtractive synthesis" (IEEE Signal Processing Magazine 2007) for PolyBLEP; Esqueda, Välimäki & Bilbao, "Rounding corners with BLAMP" (DAFx-16) for PolyBLAMP.

minBLEP and elliptic BLEP (for hard sync and high notes)
- [SRC] minBLEP table (Brandt 2001, "Hard Sync Without Aliasing"): windowed sinc with Z zero-crossings per side, oversampled O times, Blackman-Harris window (0.35875, 0.48829, 0.14128, 0.01168), real cepstrum → minimum phase (double positive quefrencies, zero negative), exp, IFFT, integrate, normalise to end at 1; VCV Fundamental uses Z=16, O=16 (512 points); minBLAMP = integral of (minBLEP − 1) minus the ideal ramp. — [VCV Fundamental VCO.cpp lines ~150-252](https://github.com/VCVRack/Fundamental/blob/v2/src/VCO.cpp); [Rack minblep.cpp](https://github.com/VCVRack/Rack/blob/v2/src/dsp/minblep.cpp)
- [SRC] Insertion: residual read with linear interpolation at fractional offset `(1-subsample)*O`, 2Z = 32 samples added into a ring buffer (`MinBlepBuffer<32>`) that is summed with the naive waveform; magnitude = jump size (square wrap +2, pulse edge −2, saw edge −2; triangle slope jump ±8·dφ via minBLAMP); crossing time `p = (threshold - startPhase)/delta`. dφ clamped to [0, 0.49], PW to [0.01, 0.99]; output DC-blocked by a one-pole HPF at 20 Hz (`alpha = w/(1+w), w = 2π·20/fs`); PWM handled by inserting a step when the square state changes because the width moved. — [VCO.cpp lines ~270-620](https://github.com/VCVRack/Fundamental/blob/v2/src/VCO.cpp)
- [SRC] Cheap sine for FM operators/LFOs: `sin_2pi_9(x)`: t = 2x−1, `t(t^2−1)(3.1415211942925003 + t^2(−2.0247734792732333 + t^2(0.51749274223813413 + t^2(−0.063691093590695858))))`, max error 6.5e-6, THD −103.7 dB. — [VCO.cpp lines 6-16](https://github.com/VCVRack/Fundamental/blob/v2/src/VCO.cpp)
- [SRC] OB-Xf (OB-Xd successor) uses a linear-phase BLEP table `B_OVERSAMPLING = 64`, `B_SAMPLES = 16` (32 taps), delays the naive saw 16 samples so the centred BLEP lines up, interpolates between table rows, and has a second table for its 2x-oversampled HQ mode. — [OB-Xf BlepData.h](https://github.com/surge-synthesizer/OB-Xf/blob/main/src/engine/BlepData.h); [SawOsc.h](https://github.com/surge-synthesizer/OB-Xf/blob/main/src/engine/SawOsc.h)
- [SRC] Signalsmith "elliptic-blep" (MIT): BLEP antialiasing based on "an 11th-order continuous-time 20kHz elliptic lowpass" expressed as a sum of one-pole filters; API `add(amount, blepOrder, samplesInPast)` where order 0 = impulse, 1 = step, 2 = slope change; vendored by sst-basic-blocks. — [sst-basic-blocks libs/elliptic-blep/README.md](https://github.com/surge-synthesizer/sst-basic-blocks/blob/main/libs/elliptic-blep/README.md) (upstream: github.com/Signalsmith-Audio/elliptic-blep)

Hard sync
- [SRC] VCV hard sync: sync event when the master signal rises through 0 at `syncSubsample = -lastSync/deltaSync`; process crossings before the sync point, then insert steps `-saw(syncPhase)`, `-tri(syncPhase)` (+ slope fix `8·dφ` if it was on the falling slope), `+2` on the square if phase ≥ pw, `-sin(syncPhase)`; restart from phase 0 for the remaining `(1-syncSubsample)` of the sample. Soft sync reverses direction and inserts slope discontinuities (`-4·dφ` for the saw). — [VCO.cpp lines ~470-590](https://github.com/VCVRack/Fundamental/blob/v2/src/VCO.cpp)
- [SRC] OB-Xf hard sync: the slave checks whether its own wrap happened before the master reset (`x/delta > hardSyncFrac`), and on reset mixes in a BLEP of height `x - delta*hardSyncFrac` at offset `hardSyncFrac`. — [SawOsc.h](https://github.com/surge-synthesizer/OB-Xf/blob/main/src/engine/SawOsc.h)
- [CALC] The same rule works with PolyBLEP: at the reset (fractional position d within the sample) the slave saw jumps from `2·φ_reset − 1` to −1, i.e. a step of `−2·φ_reset`; apply `step × blep residual` on the sample before and after the reset, using the slave's dt.

Wavetables with mip-maps
- [SRC] AMY (MIT) saw tables: 2048 samples up to harmonic 255, then 2048/180, 1024/127, 1024/90, 512/63, 512/44, 256/31, 256/22, 128/15, 128/10, 64/7, 64/5 (half-octave steps, ratio ≈ √2); choose the richest table with `(2*highestHarmonic/size)*(size/period) < 0.9` ("No aliasing, even with a 10% buffer (i.e., 19.8 kHz)"); pulse = saw table minus a second saw table delayed by `duty` cycles, duty clamped to [0.01, 0.99]; AMY also ships a WASM web build. — [AMY saw_lutset_fxpt.h lines 1076-1090](https://github.com/shorepine/amy/blob/main/src/saw_lutset_fxpt.h); [AMY oscillators.c lines 22-61, 587-631](https://github.com/shorepine/amy/blob/main/src/oscillators.c); [AMY docs/synth.md](https://github.com/shorepine/amy/blob/main/docs/synth.md)
- [SRC] Vital: 2048-sample frames (`kWaveformBits = 11`), each stored with its 1025-bin spectrum so the oscillator can band-limit and "spectral morph" in the frequency domain. — [Vital wave_frame.h lines 27-30](https://github.com/mtytel/vital/blob/main/src/synthesis/lookups/wave_frame.h); [wavetable.h lines 31-34](https://github.com/mtytel/vital/blob/main/src/synthesis/lookups/wavetable.h)

- [SRC] `detuneCurve(x) = 10028.7312891634x^11 − 50818.8652045924x^10 + 111363.4808729368x^9 − 138150.6761080548x^8 + 106649.6679158292x^7 − 53046.9642751875x^6 + 17019.9518580080x^5 − 3425.0836591318x^4 + 404.2703938388x^3 − 24.1878824391x^2 + 0.6717417634x + 0.0030115596`. — [same gist](https://gist.github.com/audionerd/fe50790b7601cba65ddd855caffb05ad) (coefficients read one by one through WebFetch)

- [SRC] Chrome's wasm-supersaw demo (Apache-2.0, from Android SynthMark) uses 7 DPW saws with fixed ratios {0.8908, 0.9382, 0.9811, 1, 1.0204, 1.0633, 1.1077} and gains {0.0789, 0.1052, 0.1578, 0.3157, 0.1578, 0.1052, 0.0789}, glide factor 0.01. — [SimpleVoice.h lines 168-180](https://github.com/GoogleChromeLabs/web-audio-samples/blob/main/src/audio-worklet/design-pattern/wasm-supersaw/synth_src/SimpleVoice.h)

FM / PM
- [SRC] MSFA (Dexed's DX7 engine, Apache-2.0): block N = 64 (`LG_N = 6`); operator = phase modulation `y = sin(phase + input) * gain >> 24; phase += freq` (Q24 fixed point), gain linearly ramped per block `dgain = (gain2 − gain1 + N/2) >> 6`; sine table 1024 entries (`SIN_LG_N_SAMPLES 10`). — [fm_op_kernel.cc](https://github.com/asb2m10/dexed/blob/master/source/msfa/fm_op_kernel.cc); [synth.h lines 29-30](https://github.com/asb2m10/dexed/blob/master/source/msfa/synth.h); [sin.h](https://github.com/asb2m10/dexed/blob/master/source/msfa/sin.h)
- [SRC] Self-feedback averages the last two outputs (a 2-tap lowpass in the loop): `scaled_fb = (y0 + y) >> (fb_shift + 1); y0 = y; y = sin(phase + scaled_fb)*gain`, with `fb_shift = feedback ? 8 − feedback : 16` (feedback 0..7). — [fm_op_kernel.cc lines ~113-135](https://github.com/asb2m10/dexed/blob/master/source/msfa/fm_op_kernel.cc); [dx7note.cc lines 29, 205-206](https://github.com/asb2m10/dexed/blob/master/source/msfa/dx7note.cc)
- [SRC] Ratio mode: coarse 0 = ×0.5, 1..31 = integer ratios; fine: ratio × (1 + fine/100) (`logfreq += 24204406.323123*ln(1+0.01*fine)`); detune `0.0209*exp(−0.396*log2f)/7*(detune−7)` relative; fixed mode `(4458616*((coarse&3)*100 + fine)) >> 3` (10^(n/100) Hz). — [dx7note.cc lines ~50-80](https://github.com/asb2m10/dexed/blob/master/source/msfa/dx7note.cc)
- [CALC] Aliasing: by Carson's rule the FM bandwidth ≈ 2(I+1)·f_mod, so index 5 with a 4 kHz modulator spans ±24 kHz around the carrier and folds at 48 kHz; MSFA runs at the host rate with no oversampling (aliasing is part of the DX character). For a clean VA "FM" type: sine operators via `sin_2pi_9`, index scaled down with key, and 2x rendering with a half-band decimator only when index × modulator frequency exceeds ~fs/4.

Ring modulation, sub-oscillator, noise, drift
- [SRC] Odin 2 ships a dedicated RingModulator effect source (GPL-3.0) — [Odin2 FX folder](https://github.com/TheWaveWarden/odin2/tree/master/Source/audio/FX) (contents not analysed).
- [CALC] Ring mod = `osc1 · osc2`; for two band-limited saws the product contains sum frequencies up to h1·f1 + h2·f2, which can exceed Nyquist even when both inputs are clean, so either ring-modulate a sine/triangle carrier, low-pass the inputs to ~fs/4 first, or render the ring-mod voice at 2x.
- [SRC] Surge analogue drift (`DriftLFO`): per sample `last = last*(1−1e-5) + uniform(−1,1)*1e-5; drift = last*316.227766` (= 1/√1e-5), scaled by the user drift amount; `UnisonSetup`: detune of voice v of N = `(2/(N−1))·v − 1`, output gain 1/√N, alternating pan `d = |v−mid|/mid` (sign flipped on odd voices), panL = 1−d, panR = 1+d. — [OscillatorDriftUnisonCharacter.h](https://github.com/surge-synthesizer/sst-basic-blocks/blob/main/include/sst/basic-blocks/dsp/OscillatorDriftUnisonCharacter.h)
- [CALC] The drift one-pole corner is fs·1e-5/(2π) ≈ 0.076 Hz at 48 kHz, i.e. a slow random wander.
- [SRC] OB-Xf "slop": each voice draws uniform(−0.5, 0.5) offsets at init for level, amp-env time, filter-env time, cutoff and portamento time; envelope times scaled by `1 + slop·d`; cutoff jittered by white noise ×3.365. — [Voice.h lines ~200-220, 429-430](https://github.com/surge-synthesizer/OB-Xf/blob/main/src/engine/Voice.h); [VoiceControlQuad.h ~386-395](https://github.com/surge-synthesizer/OB-Xf/blob/main/src/engine/VoiceControlQuad.h)
- [SRC] Surge oscillator "character" filter: warm = one-pole LP with `filt = (1 − 2·5000/fs)^2; y = filt·y1 + (1−filt)·x`; bright = matching one-zero shelf; neutral = off. — [OscillatorDriftUnisonCharacter.h](https://github.com/surge-synthesizer/sst-basic-blocks/blob/main/include/sst/basic-blocks/dsp/OscillatorDriftUnisonCharacter.h)

### Inferences
- [CALC] Recommended oscillator set for M-Theory: (1) Multi-saw: 7 PolyBLEP (or DPW) saws, Szabo detune/mix curves, random phases at voice start (no reset), 2nd-order HPF at the played fundamental, 1/√N gain when the count is variable. (2) Pulse/PWM: PolyBLEP rectangle with the −2pw DC term, PW smoothed per sample and clamped to [0.01, 0.99]. (3) Sync: master/slave phase accumulators with a 32-tap minBLEP ring buffer (VCV algorithm) — the one place where a 2-sample kernel audibly aliases at high slave ratios. (4) Ring: sine/triangle × PolyBLEP saw, optional 2x. (5) FM: 2-operator PM with `sin_2pi_9`, DX-style averaged feedback, per-block index ramp. Sub-oscillator: a PolyBLEP square from the master phase halved (one octave down); noise: seeded xorshift white, optionally one-pole coloured.
- [CALC] Wavetable mip-maps (AMY half-octave scheme) are the simplest way to give drawn/arbitrary waveforms alias-free output with one table read; PolyBLEP is cheaper for pure VA shapes and modulates smoothly.

## 2. Filters: TPT/ZDF SVF, ZDF ladder, Huovilainen, Stilson-Smith, saturation, compensation, key tracking, audio-rate modulation, oversampling

### Takeaway
The Cytomic/Simper trapezoidal SVF (MIT-available, ~9 multiplies per sample) is the right default 12 dB multimode filter; for a 24 dB "analogue" low-pass use the OB-Xd/OB-Xf ZDF 4-pole (closed-form feedback solve, atan soft clip in the first stage) or the Huovilainen ladder at 2x oversampling. All have ready equations and constants in GPL-3 or permissive code, including resonance gain-compensation constants.

### Cited Findings
- [SRC] Cytomic SVF (as implemented in sst-filters; header "available for you to copy in an MIT licensed context"): `g = tan(π·fc/fs)` with fc/fs clamped to [0, 0.499]; `res` clamped to [0, 0.98]; `k = 2 − 2·res`; `a1 = 1/(1 + g(g+k)); a2 = g·a1; a3 = g·a2`; per sample `v3 = v0 − ic2eq; v1 = a1·ic1eq + a2·v3; v2 = ic2eq + a2·ic1eq + a3·v3; ic1eq = 2v1 − ic1eq; ic2eq = 2v2 − ic2eq`; output `m0·v0 + m1·v1 + m2·v2` with LP (0,0,1), BP (0,1,0), HP (1,−k,−1), notch (1,−k,0), peak (1,−k,−2), allpass (1,−2k,0), bell (1, k(A²−1), 0) with k/A, low shelf (1, k(A−1), A²−1), high shelf (A², k(1−A)A, 1−A²). — [sst-filters CytomicSVF.h lines ~16-260, 385-398](https://github.com/surge-synthesizer/sst-filters/blob/main/include/sst/filters/CytomicSVF.h)
- [SRC] Vital's SVF uses the same core with `in = drive·x`, resonance mapping `Q = lerp(0.5, 16, res^3)`, k = 1/Q, drive compensation `drive/(2·res^3 + 1)`, post gain `gain/√drive`, `hardTanh` on the output; its 24 dB mode = SVF → hardTanh → SVF; drive/resonance ramped linearly across each block. — [Vital digital_svf.cpp lines ~69-375](https://github.com/mtytel/vital/blob/main/src/synthesis/filters/digital_svf.cpp); [digital_svf.h lines 26-33](https://github.com/mtytel/vital/blob/main/src/synthesis/filters/digital_svf.h)
- [SRC] OB-Xd 2-pole (SEM-like) in closed form with a diode-pair nonlinearity: `g = tan(π·fc/fs)`, `R12 = 1 − reso`, `tCfb = diodePairResistanceApprox(s1·0.0876) − 1` (−1.035 for "self-oscillation push"), `diodePairResistanceApprox(x) = ((((0.0103592x + 0.00920833)x + 0.185)x + 0.05)x + 1)`; `v = (x − 2·s1·(R12+tCfb) − g·s1 − s2) / (1 + g(2(R12+tCfb) + g))`; `y1 = v·g + s1; s1 = v·g + y1; y2 = y1·g + s2; s2 = y1·g + y2`; LP = y2, BP = y1, HP = v; output gain 0.74. — [sst-filters OBXDFilter.h lines ~70-255](https://github.com/surge-synthesizer/sst-filters/blob/main/include/sst/filters/OBXDFilter.h)
- [SRC] OB-Xd 4-pole ZDF: `R24 = 3.5·reso`; `lpc = g/(1+g)`; `S = (lpc(lpc(lpc·s1 + s2) + s3) + s4)/(1+g)`; `G = lpc^4`; `y0 = (x − R24·S)/(1 + R24·G)`; first-stage state soft-clipped `atan(s1·rcor24)/rcor24` with `rcor24 = (970/44000)·rcrate`; then three TPT one-poles; pole mixing gives LP6/12/18/24 and Xpander modes; output gain 0.6. — [OBXDFilter.h lines ~128-485](https://github.com/surge-synthesizer/sst-filters/blob/main/include/sst/filters/OBXDFilter.h)
- [SRC] Huovilainen ladder (orig. ## 3. Envelopes, LFOs, glide, unison, voice allocation and voice modes

### Takeaway
Analogue-style envelopes are one-pole "RC" segments with an overshooting attack target (OB-Xf: attack toward 1.3; release coefficient recomputed from the current level) or Surge's capacitor model; glide is an RC one-pole on pitch in semitones; voice allocation should steal the oldest note (or highest/lowest in priority modes) and re-allocate stolen notes on release, unlike Tone.js which drops notes.

### Cited Findings
- [SRC] OB-Xf ADSR: attack `coef = (ln 0.001 − ln 1.3)/(fs·A_ms/1000)` (A scaled by 1/(1/3)), update `out = out − (1 − out)·coef` (approach toward 1.3), constants atkCoefStart 0.001, atkCoefEnd 1.3, atkValueEnd 0.1 (attack ends at out > 0.9), optional linear-attack blend; decay `coef = ln(min(S + 1e-4, 0.99))/(fs·D_ms/1000)`, `out += out·coef` until within 1e-5 of S; release `coef = (ln 1e-5 − ln(out + 1e-4))/(fs·R_ms/1000)` computed from the level at note-off, so release time is level-independent; silent below 2e-5. — [OB-Xf AdsrEnvelope.h lines ~26-33, 70-75, 208-293](https://github.com/surge-synthesizer/OB-Xf/blob/main/src/engine/AdsrEnvelope.h)
- [SRC] Surge "analog" ADSR (capacitor model): charge `v_c1` toward `v_cc = 1.01` with `coef = 2^min(0, coeff_offset − (param·etScale + etMin))`, `coeff_offset = 2 − log2(fs/BLOCK_SIZE)` (block-rate), switch to discharge when v ≥ 1, decay toward S (optional S², ∛S shapes), release toward 0; times on a log2-seconds scale with etMin −8 (≈ 3.9 ms) and etMax 3.32 / 5 / 6.91 (10 s / 32 s / 120 s) in different envelope flavours. — [sst-basic-blocks ADSREnvelope.h lines 61-260](https://github.com/surge-synthesizer/sst-basic-blocks/blob/main/include/sst/basic-blocks/modulators/ADSREnvelope.h); [DiscreteStagesEnvelope.h lines 48-62](https://github.com/surge-synthesizer/sst-basic-blocks/blob/main/include/sst/basic-blocks/modulators/DiscreteStagesEnvelope.h)

- [CALC] Envelope implementation: per-sample one-pole `env += (target − env)·c`, `c = 1 − exp(−1/(τ·fs))`; attack target 1.3 with switch at ≥ 1.0 (the analogue "fast top" curve); decay/release τ chosen so the −80 dB point equals the knob time (τ = T/ln(10^4) ≈ T/9.21); recompute c only when a time changes.
- [CALC] Voice modes: poly = new voice (or steal) per note-on, envelopes restart from the current level (no reset to 0, avoids clicks); mono = one voice, envelopes retrigger every note; legato = one voice, envelopes keep running when a note is played while another is held, glide only on legato transitions; a last-note-priority stack restores the previous held note on release. - [CALC] Glide: RC one-pole on semitones (constant time, exponential) as in OB-Xf; "constant rate" glide = linear ramp in semitones per second.
- [CALC] LFO: phase accumulator; shapes sine (`sin_2pi_9`), triangle, saw up/down, square, S&H, smoothed random; 250 Hz output smoothing; per-voice (free or retriggered with phase offset) or global; tempo sync `f = BPM/(240·ratio)`; delay/fade-in ramp.

## 4. Effects in the browser: chorus/flanger, phaser, delay, distortion — native nodes vs worklet

### Takeaway
Echo delay, chorus (no feedback), all-pass phaser without feedback, reverb and EQ can be native nodes; anything with a short feedback loop (flanger with feedback, feedback phaser) needs a worklet, because the spec clamps a DelayNode inside a cycle to at least one render quantum (128 frames = 2.67 ms at 48 kHz). WaveShaperNode's 2x/4x oversampling exists but its filters are unspecified, so distortion is better done in the worklet with ADAA or explicit oversampling.

## 5. Performance and architecture: AudioWorklet, JS vs WASM vs WASM SIMD, voice counts, garbage-free code, smoothing, messaging, OfflineAudioContext

### Takeaway
In V8 (Chromium/WebView2) carefully written TypeScript is as fast as scalar WASM for this DSP; WASM SIMD gives ~1.6-1.8x by running 4 voices per vector. Measured costs leave large headroom (light voice ~8 ns, heavy 2x-oversampled-ladder supersaw voice ~100-240 ns per voice-sample), so 16-voice polyphony with unison is realistic on a laptop. Keep all DSP inside one AudioWorkletProcessor per synth track, drive it with timestamped MessagePort events (SharedArrayBuffer optional and only with cross-origin isolation), and render offline by instantiating the same processor in an OfflineAudioContext.

### Cited Findings
- [SRC] Render quantum: default 128 frames; `AudioContextOptions.renderSizeHint` ("default" | "hardware" | integer) "is a hint that might not be honored"; implementations must support 1 frame to 6 s; OfflineAudioContext also takes the hint. — [index.bs lines ~780-800, 2398-2410, 2999, 12208-12217](https://github.com/WebAudio/web-audio-api/blob/main/index.bs)
- [SRC] `audioWorklet` is an attribute of BaseAudioContext (so an OfflineAudioContext has its own AudioWorklet and the module must be added to it). — [index.bs lines 817, 859-862](https://github.com/WebAudio/web-audio-api/blob/main/index.bs)
- [SRC] AudioParam arrays passed to process(): "if no automation is scheduled during this render quantum, the array MAY have length 1". — [index.bs line 11475](https://github.com/WebAudio/web-audio-api/blob/main/index.bs)
- [SRC] process() must return true to stay alive while producing output; a missing return is falsy. — [MDN AudioWorkletProcessor.process](https://github.com/mdn/content/blob/main/files/en-us/web/api/audioworkletprocessor/process/index.md)

### Inferences
- [CALC] Realistic laptop budget: assume 2-3x slower per core than the measurement under power saving plus other worklets (vocal chain, drums); plain TypeScript then still supports 16 voices × (supersaw or 2-3 oscillators) × 2x-oversampled nonlinear filter with headroom, and 8 voices × 7-voice unison per key. WASM is not needed for speed; consider it (Rust or AssemblyScript, SIMD) only for a large unison/oversampled engine or to avoid JIT warm-up glitches on the first notes (pre-warm by rendering silent blocks at startup).
- [CALC] Architecture recommendation:
  1. One `AudioWorkletProcessor` per synth track holding the whole voice pool (structure-of-arrays Float32Array/Float64Array state preallocated in the constructor; no objects, closures, array literals, string building or `postMessage` allocations in process()); voices rendered into 128-frame scratch buffers, summed, then the track FX (distortion/chorus-flanger/phaser/delay) in the same processor; stereo output.
  2. Control: the main thread sends timestamped events (`{frame, type, note, vel}`) over MessagePort ahead of time (the app already schedules on the audio clock); the processor keeps a preallocated event queue and splits each 128-frame block at event frames for sample-accurate note-ons. Patch parameters as k-rate AudioParams or messages, each smoothed with a 5-20 ms one-pole or per-block linear ramps (Vital style) to avoid zipper noise.
  3. SharedArrayBuffer only for high-rate UI telemetry (meters, scopes) and only when COOP/COEP are set (Tauri `app.security.headers`; Vite `server.headers`; coi-serviceworker on static hosting). A MessagePort-only design works everywhere, including OfflineAudioContext.
  4. Offline/WAV export: create the OfflineAudioContext, `await ctx.audioWorklet.addModule(url)`, build the same graph, pass the whole song's event list via `processorOptions` or a message before `startRendering()`. Because all DSP lives in the processor and depends only on events and seeded RNGs, offline output equals live output; avoid a Worker/SAB render thread, which is not synchronised with offline rendering.
  5. Coefficients at control rate (8-32 samples) with interpolation; polynomial sine (`sin_2pi_9`), rational tanh, tabled 2^x; per-sample transcendental math only where audio-rate modulation is patched.
  6. Seed every random source (drift, slop, supersaw phases, noise) per voice so renders are reproducible.

### Gaps
- Whether Chromium/WebView2 has shipped `renderSizeHint` by Nov 2026, and WebKit/Safari AudioWorklet and OfflineAudioContext+worklet performance, could not be verified (chromestatus.com, webkit.org blocked).
- No in-browser measurement on the real audio thread (Chromium/WebView2) was run; Node/V8 numbers are a proxy for the same JIT, not for audio-thread scheduling overhead.
- The cprimozic.net article on an AudioWorkletProcessor performance pitfall could not be fetched.

## 6. Open-source code to learn from or port, with licences

### Takeaway
Everything needed exists in code portable into GPL-3.0-or-later: VCV (GPL-3.0-or-later), Surge sst-basic-blocks (GPL-3.0-or-later) and sst-filters (GPL-3, CytomicSVF also MIT), OB-Xf (GPL-3.0-or-later), Odin 2, Vital, Helm, Dexed, Surge XT (GPL-3), MSFA and Chrome samples (Apache-2.0), AMY, Tone.js, elliptic-blep (MIT), Tale's PolyBLEP (zlib), Faust libraries (STK MIT-style / LGPL with exception). The supersaw gist, Szabo's thesis, Cytomic papers and Zavalishin's book are formula references only; discoDSP's OB-Xd repository no longer holds source.

### Inferences
- [CALC] Licence mechanics (not legal advice): GPL-3.0-only files (Odin 2, Vital, Dexed, sst-filters, Surge XT, chowdsp say "v3" without "or later" in the parts read) can be combined into a GPL-3.0-or-later project, but the combined work can then only be distributed under GPL-3.0; to keep the whole app "or later", prefer porting from GPL-3.0-or-later code (VCV, sst-basic-blocks, OB-Xf) and permissive code (MIT, zlib, ISC, BSD, Apache-2.0, STK), or re-implement from the equations. Keep licence headers of every ported file and a NOTICE for Apache-2.0 code.
- [CALC] Port map: oscillators ← Tale PolyBLEP (zlib) + VCV minBLEP sync (GPL-3+) + Szabo numbers (REF); filters ← CytomicSVF.h (MIT) + OB-Xf 2/4-pole (GPL-3+) + Faust/MoogLadders RK/Stilson (BSD/Unlicense/STK); envelopes/glide/voice allocation ← OB-Xf (GPL-3+); drift/unison ← sst-basic-blocks (GPL-3+); FM ← MSFA (Apache-2.0); effects ← Faust phaflangers (LGPL+exception/STK), chowdsp ADAA (GPLv3 — or re-derive first-order ADAA), Odin 2 constants as formula reference; web plumbing ← Chrome samples (Apache-2.0).

### Gaps
- Vitalium (DISTRHO fork) and Helm DSP code were not examined; Surge XT's in-repo oscillators were not read beyond the sst libraries.
- "Or later" status of Surge XT/sst-filters/chowdsp was judged from README/LICENSE text only, not from every file header.
- Signalsmith elliptic-blep licence was read from the vendored copy, not from the upstream repository.
