## Q1. libmypaint / MyPaint brush engine: full dab model, blending formulas, input mapping, stock brushes

### Takeaway
libmypaint (SPDX `ISC`, GPL-3.0-or-later compatible) is a small, fully portable "dab stamper": every stroke segment is converted into N soft elliptical dabs where N = dist/actual_radius x dabs_per_actual_radius + dist/base_radius x dabs_per_basic_radius + dt x dabs_per_second; every one of ~60 settings is `base_value + sum of piecewise-linear curves(input)` over 18 inputs (pressure, two low-passed log-speed inputs, random, stroke-progress, direction, tilt, custom...). Realism comes from (a) per-dab gaussian position/radius jitter, (b) the 0..1 "stroke" ramp used as a paint-load proxy, (c) a smudge bucket that low-pass-filters canvas colour and is mixed into the brush colour, and (d) optional 10-band spectral (weighted-geometric-mean) pigment mixing. The stock .myb brushes (CC0-1.0) give ready-made parameter sets for dry-brush, charcoal, oil, watercolour, splatter and fan/flat bristle brushes.

**Setting evaluation (input -> setting curves)** — [mypaint-mapping.c L146-L188](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-mapping.c#L146-L188)
- [SRC] `value = base_value + SUM_over_inputs curve_j(input_j)`. Each curve is a piecewise-linear polyline of 2..64 (x,y) points; outside the first/last point the first/last *segment* is extrapolated linearly (the loop only advances while `x > x1`, so there is no clamping); a flat segment (`y0==y1` or `x0==x1`) returns y0. All inputs contribute additively (never multiplicatively); log-scaled settings (radius, stroke duration, offset multiplier) are how multiplicative behaviour is obtained.

**Inputs (how each is computed)** — [mypaint-brush.c L708-L904 `update_states_and_setting_values`](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L708-L904)
- [SRC] `pressure_in = pressure * exp(pressure_gain_log)`. Mouse = 0.5 when pressed (tooltip in brushsettings.json).
- [SRC] Speed: `norm_speed = hypot(dx,dy)/dtime * viewzoom` (px/s at 100% zoom). Two one-pole low-pass states: `speedN_slow += (norm_speed - speedN_slow) * (1 - exp(-dtime / speedN_slowness))` with defaults `speed1_slowness = 0.04 s` (fine), `speed2_slowness = 0.8 s` (gross). `exp_decay(T,t)` returns 0 when `T <= 0.001` (i.e. no filtering).
- [SRC] Speed -> input mapping: `input = ln(gamma + speed_slow) * m + q`, `gamma = exp(speedN_gamma)` (default setting 4.0), with m, q solved from two hard-coded constraints `fix1_x = 45, fix1_y = 0.5` (speed 45 maps to 0.5) and `fix2_x = 45, fix2_dy = 0.015` (slope at 45 is 0.015): `m = 0.015 * (45 + gamma)`, `q = 0.5 - m * ln(45 + gamma)`. — [mypaint-brush.c L547-L579](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L547-L579)
- [CALC] With the default gamma setting 4.0: gamma = 54.6, m = 1.494, q = -6.374, so speed 0 px/s -> input -0.40; 45 px/s -> 0.5; ~980 px/s -> 4.0 (the "soft maximum" of the speed inputs). The source comment says x is "pixels per basic dab radius" but the code feeds px/s x zoom (comment is stale).
- [SRC] `random` input: one fresh uniform [0,1) per dab (`rng_double_next`), redrawn only when a dab is drawn (L1470). `rand_gauss` = sum of 4 uniforms x 1.73205 - 3.46410 (approx. N(0,1), bounded to +-3.46). — [helpers.c L62-L70](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/helpers.c#L62-L70)
- [SRC] `stroke` input (0..1 ramp = distance along stroke; the standard "paint load / fade" driver): `norm_dist = hypot(dx,dy)/base_radius` (distance in units of base radius); `stroke += norm_dist * exp(-stroke_duration_logarithmic)`; `wrap = 1 + max(0, stroke_holdtime)`; if `stroke >= wrap`: if `wrap > 10.9` (holdtime > 9.9 means infinite) stroke stays 1.0, else `stroke = fmod(stroke, wrap)`; input is `min(stroke, 1)`. Stroke restarts when pressure rises above `stroke_threshold + 0.0001` and ends when it falls below `0.9*threshold + 0.0001`. Defaults: `stroke_duration_logarithmic = 4.0` (min -1, max 14), `stroke_holdtime = 0` (max 10). — [L755-L767, L879-L892](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L755-L892)
- [CALC] So the stroke input reaches 1.0 after travelling `exp(stroke_duration_logarithmic)` base radii: default 4.0 -> 54.6 radii; 6.0 -> 403 radii; 1.18 (pointy_ink) -> 3.25 radii.
- [SRC] `direction` (0..180, ignores 180-degree flips) and `direction_angle` (0..360): low-pass of the motion vector in *distance* not time: `fac = 1 - exp(-step_len / (exp(direction_filter*0.5) - 1))`, `dir += (d - dir)*fac`; default `direction_filter = 2.0`. For the 180-degree version the vector is negated first if the negated vector is closer to the old state. — [L850-L872](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L850-L872)
- [SRC] `custom` input: `custom_state += (custom_input_setting - custom_state) * (1 - exp(-0.1 / custom_input_slowness))` per update step; lets one random/pressure mix drive many settings coherently (used by the Dieterle bristle brushes to pick a "bristle index" per dab). — [L874-L877](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L874-L877)
- [SRC] Tilt: `ascension = degrees(atan2(-xtilt, ytilt))`, `declination = 90 - hypot(xtilt,ytilt)*60`; no tilt -> declination 90. `attack_angle = smallest_angular_difference(ascension, direction_angle + 90)`. — [L1306-L1326, L802](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L1306-L1326)
- [SRC] `gridmap_x/y`: position modulo a `256 * exp(gridmap_scale)` px grid, rescaled to 0..256 — intended "to add paper texture by modifying opacity" (tooltip). — [L731-L746](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L731-L746)

**Pointer pre-filtering (per motion event, before dabs)** — [mypaint-brush.c L1353-L1396](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L1353-L1396)
- [SRC] Tracking noise: if `tracking_noise` (0..12, default 0) is set: `noise = base_radius * tracking_noise`; the next `0.5*noise` px of input path are *skipped* (so the noise is independent of event rate), then `x += noise*rand_gauss(); y += noise*rand_gauss()`. This is the engine's hand-tremor / "many small lines in random directions" generator.
- [SRC] Slow tracking: `fac = 1 - exp(-100*dtime / slow_tracking)`; `x = X + (x - X)*fac` (one-pole low-pass on position, time constant = slow_tracking/100 s; default 0, range 0..10).
- [SRC] `slow_tracking_per_dab`: `actual_xy += (xy - actual_xy) * (1 - exp(-step_ddab / slow_tracking_per_dab))` — same filter but in dab-count units (L826-L830).
- [SRC] Engine reset if `dtime > 5 s` (L1304, L1398); stroke state then starts at `STROKE = 1.0` ("as if the stroke was long finished").

**Dab spacing** — [`count_dabs_to` L1253-L1287](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L1253-L1287), [`stroke_to` loop L1426-L1497](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L1426-L1497)
- [SRC] `dabs = dist/actual_radius * dabs_per_actual_radius + dist/base_radius * dabs_per_basic_radius + dt * dabs_per_second` (defaults 2.0, 0.0, 0.0). For elliptical dabs `dist` is measured in the dab's own frame with the minor-axis component multiplied by the aspect ratio (so thin dabs moving sideways are stamped more densely).
- [SRC] The fractional remainder is carried in state `PARTIAL_DABS`; x, y, pressure, tilt and *time* are linearly interpolated between motion events for each dab; settings are re-evaluated before each dab; `FLIP` toggles +1/-1 per dab (used by the mirrored offsets).
- [CALC] Default spacing = radius/2 (2 dabs per actual radius = 25% of diameter). Stock painterly brushes use 5-6 dabs per radius (spacing ~ 8-10% of diameter); the Dieterle flat brush uses 25.

**Per-dab parameter computation** — [`prepare_and_draw_dab` L1042-L1250](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L1042-L1250)
- [SRC] Opacity: `opaque = clamp(max(0, opaque) * opaque_multiply, 0, 1)`. Convention: pressure is mapped to `opaque_multiply` (base 0), which is what stops painting at zero pressure.
- [SRC] Opacity linearisation (compensates for overlapping dabs): `dabs_per_pixel = max(1, (dabs_per_actual_radius + dabs_per_basic_radius) * 2)`; `dabs_per_pixel = 1 + opaque_linearize * (dabs_per_pixel - 1)`; `alpha_dab = 1 - (1 - opaque)^(1/dabs_per_pixel)`. Default `opaque_linearize = 0.9`.
- [SRC] Position: `actual_x/y` + directional offsets + `norm_dxy_slow * offset_by_speed * 0.1 / viewzoom` (velocity-vector low-pass with time constant `max(0.002, exp(offset_by_speed_slowness*0.01) - 1)` s) + `rand_gauss() * offset_by_random * base_radius` on each axis (std-dev = offset_by_random x base radius).
- [SRC] Directional offsets (v2): `offset_x/y` (canvas), `offset_angle` (perpendicular to stroke direction: angle = direction - 90 deg + `offset_angle_adj`), `offset_angle_2` (mirrored: sign alternates with FLIP every dab), plus tilt- and view-relative variants; all multiplied by `base_radius * exp(offset_multiplier)` and clamped to +-3240 px. — [L586-L664](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L586-L664)
- [SRC] Radius: `actual_radius = clamp(exp(radius_logarithmic), 0.2, 1000)`. `radius_by_random`: `radius = exp(radius_logarithmic + rand_gauss()*radius_by_random)` and, if the dab got bigger, `opaque *= (actual_radius/radius)^2` (constant paint per dab).
- [SRC] Anti-aliasing: if `radius*(1-hardness) < anti_aliasing` px (default 1.0), hardness is lowered and radius raised keeping the "optical radius" `radius - (1-hardness)*radius/2` constant: `hardness_new = (r_opt - aa/2)/(r_opt + aa/2)`, `radius_new = aa/(1-hardness_new)`.
- [SRC] Colour dynamics: HSV change (`h += change_color_h`; `s += s*v*change_color_hsv_s`; `v += change_color_v`), then HSL (`l += change_color_l`; `s += s*min(|1-l|,|l|)*2*change_color_hsl_s`).
- [SRC] Eraser: `eraser_target_alpha *= (1 - eraser)`; the dab then blends toward that alpha (see Normal_and_Eraser).

**Dab mask (shape/hardness)** — [mypaint-tiled-surface.c L226-L372, L376-L490](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-tiled-surface.c#L226-L490)
- [SRC] For pixel centre (xp+0.5, yp+0.5): `xx, yy` = offset from dab centre; rotate by dab angle: `yyr = (yy*cs - xx*sn) * aspect_ratio; xxr = yy*sn + xx*cs; rr = (yyr^2 + xxr^2) / radius^2` (rr = squared normalised distance; aspect_ratio >= 1 squashes the dab across its angle).
- [SRC] Opacity falloff is two linear segments *in rr*: `opa = (1-softness) * (rr <= hardness ? 1 + rr*-(1/hardness - 1) : hardness/(1-hardness) * (1 - rr))`, 0 for rr > 1. hardness=1 gives a hard disc; hardness 0 draws nothing; softness 1 draws nothing. Radius < 3 px uses an analytic anti-aliased rr (`calculate_rr_antialiased`, 1 px AA border).
- [SRC] Dabs with radius < 0.1, hardness 0, softness 1 or opaque 0 are skipped. `normal = (1-lock_alpha)*(1-colorize)*(1-posterize)`; the four blend modes are applied in sequence with weights `normal*opaque*(1-paint)`, `normal*opaque*paint` (spectral), `lock_alpha*opaque*(1-colorize)*(1-posterize)`, `colorize*opaque`, `posterize*opaque`. — [L497-L560, L613-L680](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-tiled-surface.c#L497-L680)

**Per-pixel blending (premultiplied RGBA, 15-bit fixed point)** — [brushmodes.c](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/brushmodes.c)
- [SRC] Normal: `a_t = mask*opacity; dst.a = a_t + (1-a_t)*dst.a; dst.rgb = a_t*color + (1-a_t)*dst.rgb` (source-over with straight brush colour onto premultiplied dst).
- [SRC] Normal_and_Eraser (used whenever smudge/eraser makes `color_a < 1`): `a_t = mask*opacity; a_b = 1-a_t; a_t2 = a_t*color_a; dst.a = a_t2 + a_b*dst.a; dst.rgb = a_t2*color + a_b*dst.rgb`. I.e. the pixel is pulled toward (color, color_a): "when smudging over a region that is 60% opaque the result will stay 60% opaque"; color_a=0 is a pure eraser.
- [SRC] LockAlpha: as Normal but `a_t *= dst.a` and dst.a unchanged. Colorize: PDF "Color" non-separable mode (SetLum with Rec.709 weights 0.2126/0.7152/0.0722) lerped by `mask*opacity`, alpha kept. Posterize: `round(c*n)/n` lerped in.
- [SRC] Pigment ("paint_mode", v2) variant of each: convert brush colour and un-premultiplied canvas colour to a 10-band reflectance (`rgb_to_spectral`: `r,g,b` first mapped to `c*(1-0.001)+0.001`, then `spd[i] = spectral_r_small[i]*r + spectral_g_small[i]*g + spectral_b_small[i]*b`), mix with a **weighted geometric mean** `spd_out[i] = spd_a[i]^fac_a * spd_b[i]^(1-fac_a)` where `fac_a = a_t / (a_t + (1-a_t)*dst.a)`, convert back with the 3x10 matrix `T_MATRIX_SMALL`, re-premultiply. Minimum opacity 150/32768 enforced. For the eraser variant spectral vs additive is cross-faded by canvas alpha with `spectral_blend_factor(x) = 0.5 + b/(1 + |b|*1.65), b = 8x - 3`. The exact 10-band tables are in [helpers.c L39-L59](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/helpers.c#L39-L59); `WGM_EPSILON 0.001` in helpers.h.
- [SRC] `paint_mode` default is 1.0 (fully spectral) in brushsettings.json; a constant `paint_mode <= 0` selects "legacy smudge" (plain RGB).

**Smudge (pick-up and smear of canvas paint)** — [`update_smudge_color` L920-L997, `apply_smudge` L999-L1035](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L920-L1035)
- [SRC] State: a "smudge bucket" = premultiplied RGBA smudge colour + last sampled canvas colour + `recentness`. Up to 256 buckets selectable per dab via `smudge_bucket` (so each offset "bristle" can carry its own colour).
- [SRC] Per dab (only if `smudge_length < 1` and smudge is used): `update_factor = max(0.01, smudge_length)`; `recentness *= update_factor`; the canvas is re-sampled only when `recentness < min(1, (0.5*update_factor)^smudge_length_log + 1e-16)` (so long smudge lengths sample rarely — a performance trick), otherwise the previous sample is reused. On the very first dab `update_factor = 0` (bucket initialised with the canvas colour).
- [SRC] Canvas sample `get_color(x, y, smudge_radius)`: `smudge_radius = clamp(radius * exp(smudge_radius_log), 0.2, 1000)`; weighted average under a dab mask with hardness 0.5 / softness 0.5; pixels sub-sampled (every `int(radius*7)`-th pixel guaranteed plus random rate `1/(7*radius)`). — [mypaint-tiled-surface.c L803-L925](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-tiled-surface.c#L803-L925)
- [SRC] `smudge_transparency`: if > 0 and sampled alpha < it (or < 0 and alpha > -it) the dab is not drawn at all.
- [SRC] Legacy update: `smudge = update_factor*smudge + (1-update_factor)*a*[r,g,b,1]` (one-pole low-pass in dab units; `smudge_length` IS the pole: 0 = instantly canvas colour, 1 = never changes; default 0.5). Spectral update: `mix_colors(prev_smudge, sampled, update_factor, paint_mode)`.
- [SRC] Apply: `f = min(1, smudge)`; `eraser_target_alpha = clamp((1-f) + f*smudge.a, 0, 1)`; legacy `color = (f*smudge.rgb + (1-f)*brush.rgb) / eraser_target_alpha`; spectral: `mix_colors(smudge, brush, f, paint_mode)`. The dab is then drawn with `color_a = eraser_target_alpha` via Normal_and_Eraser, so smudging also drags transparency.
- [SRC] `mix_colors(a,b,fac)`: `alpha = fac*a.a + (1-fac)*b.a`; spectral weight `sfac_a = fac*a.a / (a.a + b.a*(1-fac))`; `spd = spd_a^sfac_a * spd_b^(1-sfac_a)`; result lerped with plain RGB mix by `paint_mode`. — [helpers.c L564-L604](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/helpers.c#L564-L604)

### Inferences
- [CALC] Minimal faithful port to TypeScript: (1) one function `evalSetting(base, curves, inputs)`; (2) the per-event pre-filter (tracking noise -> slow tracking); (3) `countDabs` + interpolation loop; (4) per-dab jitter/offset; (5) mask `opa(rr)` — in WebGL2 this is a 6-line fragment shader on an instanced quad; in Canvas 2D a cached radial-gradient sprite per (hardness) approximates it (the falloff is linear in r^2, i.e. `1 - rr*k`, not a gaussian); (6) Normal_and_Eraser blend = premultiplied lerp toward (color*color_a, color_a), i.e. `dst = (color*color_a*a_t, color_a*a_t) + (1 - a_t)*dst`. When color_a = 1 this is ordinary premultiplied source-over (`blendFunc(ONE, ONE_MINUS_SRC_ALPHA)`). When color_a < 1 (smudging/erasing) the destination factor `(1 - a_t)` differs from `1 - src.a`, so a single fixed-function pass cannot do it in WebGL2 (no dual-source blending); options are two passes per dab (pass 1: `blendFunc(ZERO, ONE_MINUS_SRC_ALPHA)` with src.a = a_t; pass 2: `blendFunc(ONE, ONE)` adding `(color*color_a*a_t, color_a*a_t)`), or reading dst in the shader via a ping-pong framebuffer. Ping-pong is required anyway for spectral mixing.
- [CALC] For an auto-painter with no stylus: synthesise `pressure(t)` and `dtime` (speed) envelopes per stroke; the engine then delivers taper (pressure->radius S-curve), speed thinning (speed1 -> radius negative slope ~ -0.14 to -0.3 log units across the range), lag (slow_tracking), tremor (tracking_noise 0.05-0.2 for oil; 1.4 for spray; 12 for splatter) and depletion (stroke ramp -> smudge up, smudge_length down) "for free".
- [CALC] Paint run-out in MyPaint is not a reservoir model; it is a deterministic function of distance travelled (the `stroke` input), with length `exp(stroke_duration_logarithmic)` base radii. A music-driven app can override this with its own load variable fed through the `custom` input.

## Q2. Krita: Bristle (hairy), Colour Smudge, Sketch, Spray, pixel-brush spacing / rotation / scatter / fuzzy sensors, texture strength

### Takeaway
Every Krita paintop file read here carries `SPDX-License-Identifier: GPL-2.0-or-later` (so it can be translated into a GPL-3.0-or-later app with attribution). The Bristle engine is literally "one 1-px line per opaque pixel of the brush tip" with per-bristle ink counters indexed into a depletion curve; Colour Smudge is "copy the pixels under the previous dab (smear) or their average colour (dull) into the current dab, then lay brush colour on top at rate^2", plus a separate height-map layer for the lightness/impasto mode; Sketch connects the current point to earlier points within a radius; Spray scatters N particles in a disc with selectable radial/angular distributions.

**Bristle ("hairy") engine** — `GPL-2.0-or-later` (Lukas Tvrdy 2008-2010) — [plugins/paintops/hairy/hairy_brush.cpp](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/hairy/hairy_brush.cpp), [kis_hairy_paintop.cpp](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/hairy/kis_hairy_paintop.cpp), [bristle.h](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/hairy/bristle.h), [trajectory.cpp](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/hairy/trajectory.cpp)
- [SRC] Bristle creation (`fromDabWithDensity`): the brush-tip mask is rendered once; for every pixel with alpha != 0, with probability `density` (= densityFactor% / 100; RNG seeded 0), a `Bristle(x - cx, y - cy, length = alpha)` is created and takes the pixel's colour. So **bristle count = number of non-transparent tip pixels x density**, and bristle "length" (0..1) = tip opacity at that pixel (soft-edged tips give short outer bristles).
- [SRC] Per input segment pi1 -> pi2 (`paintLine`), for each bristle: `randomX, randomY = (U*2 - 1) * randomFactor` (fresh uniform jitter per bristle per segment); `shear = pressure * shearFactor` where `pressure = mousePressure * pi2.pressure * 2`; transform = rotate(-angle) . scale(scale) . translate(randomX, randomY) . shear(shear, shear), applied to the bristle's tip-space (x, y). If `connectedPath` is off (default) both end-points use the same transformed offset (parallel hair segments, re-jittered each segment so hairs "jump"); if on, each bristle continues from its own previous end-point (continuous wobbly hairs). `scale = sizeSensor * scaleFactor`.
- [SRC] "Threshold" option: bristle skipped when `length < 1 - pressure` — i.e. low pressure paints only the long (central, opaque-tip) bristles, so the stroke narrows/breaks up as pressure drops.
- [SRC] Each bristle is rasterised as a 1-px DDA line (`getLinearTrajectory`: step 1 px along the major axis). Each plotted pixel: non-AA `darkenPixel` (write only if existing dab alpha < new alpha, i.e. MAX-alpha so overlapping bristles don't build up) or, with `useCompositing`, source-over; AA `paintParticle` splits opacity bilinearly over 4 pixels: `(1-fx)(1-fy), fx(1-fy), (1-fx)fy, fx*fy`.
- [SRC] Ink depletion: each bristle has an integer `counter` incremented **per pixel drawn** by that bristle; `inkDepletion = curve[min(counter, inkAmount-1)]` where the user curve (default `"0,0;1,1;"` = linear) is sampled into `inkAmount` entries (default 1024). So a bristle is "empty" after it has drawn `inkAmount` pixels (default 1024 px of travel). `bristle.inkAmount = 1 - inkDepletion`.
- [SRC] Opacity depletion (default on when depletion enabled): un-weighted `opacity = bristle.length * bristle.inkAmount` (clamped 0..1); weighted: `opacity = pressure*pressureWeight + length*bristleLengthWeight + inkAmount*bristleInkAmountWeight + (1 - inkDepletion)*inkDepletionWeight`. Saturation depletion: `saturation = pressure * length * inkAmount * (1 - inkDepletion) - 1` passed to an HSV adjustment (un-weighted), or the same weighted sum minus 1.
- [SRC] Without depletion: bristle opacity = `length`.
- [SRC] "Soak ink": on first touch each bristle samples the canvas colour under its own offset (`colorifyBristles`) — a multi-colour loaded brush.
- [SRC] Mouse-pressure simulation (`computeMousePressure`, used when `useMousePressure`): `factor = max(0, 1 - distance/20)`; `p = (4*oldP + 0.02 + factor)/5`; `mousePressure = 1 - p`; scale and pressure are multiplied by it. Constants `scale = 20.0`, `minPressure = 0.02`. (A 5-tap IIR that converts segment length -> pressure: short slow segments -> p near 1 -> mousePressure near 0... i.e. fast = larger.)
- [SRC] Defaults (`KisHairyBristleOptionData.h`, `KisHairyInkOptionData.h`): useMousePressure false; scaleFactor 2.0; randomFactor 2.0; shearFactor 0.0; densityFactor 100.0 (%); threshold false; antialias false; useCompositing false; connectedPath false; inkDepletionEnabled false; inkAmount 1024; curve "0,0;1,1;"; useSaturation false; useOpacity true; useWeights false; pressure/bristleLength/bristleInkAmount/inkDepletion weights 50 (the first three are divided by 100 in `loadSettings`, `inkDepletionWeight` is NOT divided — reads as 50, apparent bug). — [KisHairyBristleOptionData.h](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/hairy/KisHairyBristleOptionData.h), [KisHairyInkOptionData.h](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/hairy/KisHairyInkOptionData.h)

**Colour Smudge engine** — all 58 files `GPL-2.0-or-later` — [kis_colorsmudgeop.cpp](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/colorsmudge/kis_colorsmudgeop.cpp), [KisColorSmudgeStrategyBase.cpp](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/colorsmudge/KisColorSmudgeStrategyBase.cpp)
- [SRC] Per dab (`paintAt`): compute `dstDabRect` for the new dab; `srcDabRect = dstDabRect translated by (lastPaintPos - newCenterPos)` (integer pixels) — the same-size rectangle under the *previous* dab; the first dab of a stroke paints nothing (only records position). Sub-pixel dab positioning is disabled in smearing mode so src/dst align.
- [SRC] `blendBrush` builds a temp "blend device" the size of the dab, then writes it to the layer through the brush mask with composite COPY at opacity 1 (new engine):
  1. **Smearing** (`blendInBackgroundWithSmearing`): `blend = canvas[dstRect]`; `blend = over(canvas[srcRect], blend, smearRate)` where `smearRateOpacity = smudgeRate * opacity`. (With smear-alpha on, op is COPY: lerp including alpha; at rate 1 it is a plain copy of the previous dab's pixels.) This is a pixel-exact "drag" — image content is translated along the stroke, repeated every dab, giving streaks.
  2. **Dulling** (`blendInBackgroundWithDulling`): `dullingColor = weighted average of canvas under srcRect` (weights = brush mask; Halton(2,3) quasi-random sampling, at least `min(N, max(64, 2% of N))` samples, sample area = srcRect scaled by `smudgeRadius`); `blend = over(dullingColor, canvas[dstRect], dullingRate)` with `dullingRateOpacity = 0.8 * smudgeRate * opacity`. One flat colour per dab -> soft blending without streaks.
  3. **Colour rate**: `blend = compositeOp(paintColor, blend, colorRateOpacity)` with `colorRateOpacity = colorRate^2 * opacity` (new engine). The composite op is the brush's blending mode.
- [SRC] Legacy (pre-"new engine") rates: smear and dulling applied at opacity 1 into the temp, final blit opacity `= smudgeRate * opacity`, `colorRateOpacity = lerp(0, max(1 - maxSmudgeRate, 0.2), colorRate * opacity)`, dulling sample is an unweighted average. — [KisColorSmudgeStrategyMaskLegacy.cpp](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/colorsmudge/KisColorSmudgeStrategyMaskLegacy.cpp), [KisColorSmudgeSampleUtils.h](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/colorsmudge/KisColorSmudgeSampleUtils.h)

- [SRC] **Lightness / impasto mode** (`KisColorSmudgeStrategyLightness`): three per-layer devices persist between strokes — `colorOnlyDevice` (flat colour, 16-bit), `heightmapDevice` (RGB8 grey), `projectionDevice` (what the user sees). Per dab: (a) run the normal smudge/colour blend on the colour-only device through the tip's alpha; (b) blit the tip's grey lightness image onto the height map with OVER at `opacity * overlayAdjustment`, where `overlayAdjustment = 1` in OVERWRITE mode and `lerp(smudgeRate - 0.01, 1.0, paintThickness)` in OVERLAY mode; (c) `projection = modulateLightnessByGrayBrush(color, heightmap)`. Paint-thickness < 1 first compresses tip contrast around mid-grey: `gray = (gray - 127) * thickness + 127`. — [KisColorSmudgeStrategyLightness.cpp](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/colorsmudge/KisColorSmudgeStrategyLightness.cpp)
- [SRC] Lightness modulation formula (Peter Schatz 2020, `GPL-2.0-or-later`): for pixel HSL lightness z and height value x in 0..1 (0.5 = neutral): `x' = (x - 0.5) * strength * alpha + 0.5`; `L_out = clamp((1 - (4z - 1)) * x'^2 + (4z - 1) * x', 0, 1)` — the quadratic through (0,0), (0.5,z), (1,1); then `setLightness(rgb, L_out)` (HSL). Same curve is used for "lightness map" brush tips with z = lightness of the paint colour. — [libs/pigment/KoColorSpacePreserveLightnessUtils.h](https://github.com/KDE/krita/blob/master/libs/pigment/KoColorSpacePreserveLightnessUtils.h)

**Sketch engine** — `GPL-2.0-or-later` — [plugins/paintops/sketch/kis_sketch_paintop.cpp](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/sketch/kis_sketch_paintop.cpp), [KisSketchOpOptionData.h](https://github.com/KDE/krita/blob/afc124763282f5387735760cdda838c1c81545a1/plugins/paintops/sketch/KisSketchOpOptionData.h)
- [SRC] State: `m_points` = every mouse position of the stroke so far. Per new point P: (1) optionally draw the plain segment prev -> P (`makeConnection`); (2) loop over ALL earlier points Q: `distance = |Q - P|^2`; connect if `distance < thresholdDistance` (simple mode: `(radius*scale)^2`) or, in mask mode, if Q falls on a non-zero pixel of the brush-tip mask centred on P; (3) density test: `probability = distance / (thresholdDistance * currentProbability)` (when `distanceDensity`, default on) else `1 - currentProbability`; connect when `U >= probability` (so nearer points are connected more often); (4) draw a line: with `magnetify` (default on) from `P + diff*offsetScale` to `Q - diff*offsetScale` where `diff = Q - P`, `offsetScale = offset% * 0.01` — i.e. only the middle part of the chord P-Q is drawn (offset 30% leaves the central 40%), producing the "web/shading" between nearby passes; without magnetify a short tick `P +- diff*offsetScale`. ### Inferences
- [CALC] Krita's bristle engine is a 60-line algorithm in TS: precompute `bristles[] = {x, y, len, counter, prevX, prevY}` from a tip mask (or simply a jittered disc with `len = 1 - r^2`), then for every path segment draw each bristle as a thin line with `alpha = len * (1 - depletionCurve[counter])`, `counter += segmentLengthPx`. In WebGL2 draw them as instanced line quads; MAX-alpha compositing inside the stroke buffer (`gl.blendEquation(gl.MAX)`) reproduces `darkenPixel` and stops alpha build-up between bristles. Bristle count vs width: with a round tip of diameter D px and density 1, count = PI*D^2/4 (e.g. D=20 -> ~314 bristles; density 0.3 -> ~94) [CALC from `fromDabWithDensity`].
- [CALC] Smearing is cheap in WebGL2: per dab, draw a quad at the new position sampling the canvas texture at `uv - (pos - lastPos)`, mixed by `smudgeRate*opacity`, masked by the tip — needs ping-pong or `copyTexSubImage2D` of the dab rect. Dulling = one 1x1 average (mip level or small sample kernel) per dab.
- [CALC] The impasto trick (separate grey height map, modulate lightness with the quadratic through (0.5, L)) is a very cheap way to get thick-paint relief without real lighting: keep an R8 height texture, stamp bristle-texture tips into it, and apply the quadratic in the present shader.

## Q3. p5.brush, perfect-freehand, rough.js: pressure simulation, vibration, tips, hatching, bleed fill

### Takeaway
All three are `MIT` (portable into GPL-3.0-or-later with notice retained). p5.brush (v3.2.1, now a WebGL2 instanced-point renderer) builds every line from thousands of tiny dots: per step a "grain" survival test, gaussian-plus-uniform lateral scatter that widens as pressure drops, dot diameter proportional to pressure squared, and a parametric bell-shaped pressure envelope randomised per stroke; pigment is composited with Kubelka-Munk spectral mixing. perfect-freehand turns points into a variable-width outline polygon, simulating pressure from point spacing (slow = thick). rough.js draws each line twice as slightly different cubic Beziers with bowing and end-point offsets.

Taper: `radius *= min(startEase(runLen/taperStart), endEase((total - runLen)/taperEnd))`, clamped to >= 0.01; `taper: true` = whole stroke length.
- [SRC] Outline: left/right points offset perpendicular to `lerp(nextVector, vector, dot(vector, nextVector))`; points closer than `(size*smoothing)^2` (squared) to the previous kept point on that side are skipped; when the direction reverses (dot < 0) a 13-segment semicircular cap is inserted; round start cap 13 segments, round end cap 29 segments over 1.5 turns. Output is one closed polygon to fill (Canvas `Path2D`), typically smoothed with quadratic curves through midpoints [SEC: README usage].

**rough.js** — `MIT` (Copyright 2019 Preet Shihn), v4.6.6, commit `56a27621` — [src/renderer.ts](https://github.com/rough-stuff/rough/blob/56a2762171b1294d643501e8d14f120db6b27bd7/src/renderer.ts), [src/generator.ts](https://github.com/rough-stuff/rough/blob/56a2762171b1294d643501e8d14f120db6b27bd7/src/generator.ts)
- [SRC] Defaults: `maxRandomnessOffset 2`, `roughness 1`, `bowing 1`, `strokeWidth 1`, `curveTightness 0`, `curveFitting 0.95`, `curveStepCount 9`, `fillStyle 'hachure'`, `hachureAngle -41`, `hachureGap -1` (= `strokeWidth * 4`), `fillWeight -1` (= strokeWidth/2 per README [SEC]), `disableMultiStroke false`, `preserveVertices false`, `fillShapeRoughnessGain 0.8`.
- [SRC] Line wobble (`_line`): every line is ONE cubic Bezier with randomised end-points and control points: `offset = maxRandomnessOffset` (reduced to `length/10` when `offset^2 * 100 > length^2`, i.e. for lines shorter than 20 px); length-dependent gain: `1` if length < 200, `0.4` if > 500, else `-0.0016668*length + 1.233334`; bowing: `midDisp = bowing * maxRandomnessOffset * (dy, -dx) / 200`, then randomised in `+-midDisp * roughness * gain` (perpendicular bulge = up to 1% of length x bowing); `divergePoint = 0.2 + U*0.2`; control points at `divergePoint` and `2*divergePoint` along the line, each + midDisp + `U(-offset, offset) * roughness * gain` per coordinate; end-points jittered by the same. **Double stroke** (`_doubleLine`): the line is drawn twice, the second pass ("overlay") with half the jitter (`offset/2`) — this is what gives the sketched look.
- [CALC] So for a 100-px line at defaults: end-point jitter +-2 px (first pass), +-1 px (second), bow up to +-1 px; for a 600-px line everything is scaled by 0.4.
- [SRC] Curves: points jittered by `U(-offset, offset)*roughness` then joined as a Catmull-Rom-like spline converted to cubic Beziers with tangent factor `(1 - curveTightness)/6`. Ellipses: step count `max(9, 9/sqrt(200) * sqrt(2*PI*sqrt((rx^2+ry^2)/2)))`; radii randomised by `+-(1 - curveFitting) = +-5%`; start angle random `U(-0.5, 0.5) - PI/2` rad; drawn slightly past closure with lead-in/out points at 0.9 and 0.98 radius (overshoot loop like a hand-drawn circle); two passes.

### Inferences
- [CALC] p5.brush's default-dot model is the cheapest realistic pencil/charcoal/dry-brush texture available in WebGL2: one instanced draw call per stroke, no bristle state. For a paint-like look, raise `weight`, lower `spacing`, and use type `custom`/`image` tips with `rotate: natural`.
- [CALC] p5.brush's pressure bell (`1/(1+|x|^(2c))`, c ~ 3-3.5, rise side 1.2x wider than the fall side, peak position jittered by `c0*U(-1,1)`) is a ready-made "attack-sustain-release" envelope for an auto-painter, and maps naturally onto a note envelope.
- [CALC] perfect-freehand's simulated pressure is only a function of sample spacing relative to brush size, so an auto-painter can drive thickness simply by spacing its emitted path points according to the desired velocity profile (dense points = slow = thick).
- [CALC] rough.js contributes two transferable ideas: draw the stroke twice with different jitter, and scale jitter down for long strokes (gain 1 -> 0.4 between 200 and 500 px).

## Q4. Classic bristle-brush research in open code (Strassmann, Baxter dAb, Chu & Tai MoXi, DiVerdi/Adobe wet brush)

### Takeaway
I found no open implementation that names Strassmann, dAb or the Adobe bristle brush as its source; the closest open, portable equivalents are (a) Krita's bristle engine (1-px line per bristle + per-bristle ink counter = the Strassmann idea in 2-D, GPL-2.0-or-later), (b) David Li's "Fluid Paint" (MIT, WebGL): 10-100 bristles, each a 10-vertex position-based-dynamics rod that is dragged over the canvas and splats paint + velocity into a 2-D fluid solver — the nearest thing to dAb/Adobe-style physical bristles in the browser, and (c) a 2026 Rust/WGSL port of MoXi (MIT OR Apache-2.0) with every lattice-Boltzmann parameter listed. Bristle splitting in all of them is emergent (jittered bristle positions, per-bristle stiffness, per-bristle ink) rather than modelled explicitly.

**The papers themselves (not re-read; summarised from memory, treat as secondary)**
- [SEC] Strassmann, "Hairy Brushes" (SIGGRAPH 1986): a 1-D array of bristles swept along a spline-interpolated position+pressure path; each bristle carries its own ink quantity/colour that is decremented as it deposits, so depleted bristles leave gaps (dry-brush streaks); width follows pressure; a "dip" object sets the initial per-bristle ink. Krita's hairy engine reproduces the per-bristle counter + depletion curve; whether Krita's code derives from Strassmann is not stated in the files read.
- [SEC] Baxter et al., "dAb" (SIGGRAPH 2001): 3-D deformable brush (spring-mass skeleton + surface), bidirectional paint transfer between brush and canvas, wet/dry canvas layers. No open implementation found.
- [SEC] DiVerdi et al. (Adobe, 2010-2013, e.g. "Industrial-strength painting with a virtual bristle brush", "Painting with polygons"), Chen et al. "Wetbrush" (2015): per-bristle physical simulation with bidirectional pickup. No open implementation found.

### Inferences
- [CALC] For a browser auto-painter the practical ladder is: (1) Krita-style stateless bristle lines with ink counters (cheap, deterministic, gives dry-brush for free); (2) add Harmony-ribbon inertia per bristle (`ease` 0.6-0.8, `div` 0.1) to get lag/splay on direction changes; (3) full Fluid-Paint PBD bristles only if wet-in-wet oil is a headline feature (needs float render targets and ~20 constraint passes per frame per brush).
- [CALC] Bristle splitting can be approximated without physics by giving each bristle a random stiffness in [0, 0.3] and letting lateral offset grow with (1 - stiffness) x speed x pressure — this mirrors how Fluid Paint's bending constraint produces splay.
- [CALC] A MoXi-style LBM (9 distributions per cell, a few thousand steps to dry) is feasible in WebGL2 with ping-pong float textures, but is an order of magnitude heavier than p5.brush's analytic watercolour shader; for music-driven real-time work the analytic rim/granulation/bloom shader is the better first target.

## Q5. What concretely makes a computed stroke look hand-made (numbers from code)

### Takeaway
Across all engines the same six ingredients recur, each with concrete constants: (1) width tied to speed through a low-pass filter (time constants 0.04 s and 0.8 s in MyPaint; `0.275` rate in perfect-freehand), (2) an asymmetric pressure bell with a soft start and a faster release, jittered per stroke, (3) per-dab position/size/alpha jitter of roughly 10-30%, (4) a position low-pass / mass-spring lag around 8-10 Hz, (5) spacing of 5-25% of the dab diameter, growing sub-linearly with size, and (6) a load variable that falls with distance and raises smudge/gaps. None of the code bases contains a measured tremor spectrum; "tremor" is injected as spatial noise, not as a frequency.

### Inferences
- [CALC] A minimal "hand" recipe consistent with all sources: generate the path at >= 180 samples/s; pass the target through a spring (f0 ~ 8.6 Hz, zeta ~ 0.66) or a 20-45 ms one-pole; derive pressure as an asymmetric super-Lorentzian bell (rise 1.2 : fall 0.8, exponent ~6-7, peak position +-15% jitter); make width fall ~15-30% from slow to fast and rise with pressure along an S-curve; taper the first ~3 radii from ~0.5x; jitter each dab's diameter +-15% and alpha -25/+10%; scatter laterally by 0.15-0.75 of the stroke weight with gaussian tails that widen as pressure drops; add heading noise of a few degrees with a spatial period of 1-3% of canvas width; and draw long strokes with less relative jitter than short ones.
- [CALC] Because every engine expresses tremor in space (per px or per radius) rather than time, a music-driven painter can freely choose the temporal mapping: e.g. modulate `tracking_noise`/`scatter` amplitude from spectral flux while keeping the spatial correlation length ~0.5 radius (MyPaint) to 1% canvas (p5.brush).

### Gaps
- Tremor spectra: no source read gives a physiological tremor frequency or amplitude spectrum. The commonly cited 8-12 Hz physiological tremor band is general literature knowledge [SEC, unverified here] and was not found in any code; the 8.6 Hz spring frequency of ink-stroke-modeler is a smoothing cutoff, not a tremor model.
- "Acceleration at start" is not modelled explicitly anywhere read; it is implied by speed-filter time constants and taper curves.
- No measured data on bristle count per mm for real brushes in these sources.

## Q6. Splatter, flick, drip and stipple models in open code

### Takeaway
Licensed open code offers good *spray/splatter/stipple* generators (MyPaint splatter brushes, Krita spray distributions, p5.brush spray, MyPaint Dieterle "Splash") but I found no licensed, well-maintained open model of gravity drips or of flick physics (parent droplet + satellites); those have to be designed, using the distributions below as building blocks. Short touches differ from pulled strokes only by which spacing term dominates: time-based dabs (`dabs_per_second`) and sparse distance-based dabs (0.05 per radius) versus dense distance-based dabs.

### Cited Findings
- [SRC] MyPaint `tanda/splatter-02` (random splatter cloud): one dab per 20 base radii of travel (`dabs_per_basic_radius 0.05`, no per-actual-radius dabs), position sigma 2 radii (`offset_by_random 2.0`) on top of pointer noise sigma 12 radii (`tracking_noise 12`, the maximum), **log-normal droplet size**: `radius = exp(1.3 + N(0,1)*1.5)` px clamped (`radius_by_random 1.5`, the maximum) with the built-in correction `opacity *= (r_nominal/r)^2` for larger-than-nominal droplets (big drops are more transparent), hardness 0.88-1.0, opacity 0.2-0.95 by pressure. — [tanda/splatter-02.myb](https://github.com/mypaint/mypaint-brushes/blob/08da4a48a4b63f2e0f3303942d7c21da8479ea9f/brushes/tanda/splatter-02.myb), [mypaint-brush.c L1099-L1109](https://github.com/mypaint/libmypaint/blob/d5a88fbe6649d5ec776bc42ec8c1f4bb29d7fd7f/mypaint-brush.c#L1099-L1109)

### Inferences
- [CALC] A portable flick/splatter generator assembled from the above: emit K droplets per event with log-normal radius (sigma_ln 0.3 for spray up to 1.5 for heavy splatter), `opacity ~ min(1, (r_median/r)^2)`, position = impact point + velocity x U(0, T) (throw distance proportional to gesture speed, cf. `offset_by_speed`) + lateral gaussian whose sigma grows along the throw (cf. Splash `exp(1.22 * t)`), dab elongated along the throw direction for fast droplets (ratio 1 -> 3), and a few "satellites" at 0.1-0.3x radius scattered within 2-4 radii of each large droplet. Only the first three items are taken from code; satellite counts and elongation are my design suggestions, not sourced.
- [CALC] Drips are not in any licensed source read. A workable model consistent with the engines above: a drip is a pulled stroke under gravity whose `stroke`-style load variable decreases with distance, whose width follows load (S-curve), speed proportional to load above a threshold (stops when load < threshold), with tracking noise ~0.05-0.2 radii for lateral wander and a terminal bead (time-based dabs while speed -> 0, as in ink_blot). This is an inference, not a transcription.

### Gaps
- No licensed open implementation of paint drips (gravity runs) or of physically based flick/satellite droplet statistics was found. GitHub repository search surfaced only unlicensed or toy repos (e.g. `sllark/realistic-spray-paint`, `coachaji/Paint-Like-Pollock`, `mikefey/text-drip` — all "no licence" per the search listing, hence not portable and not read). GitHub code search and non-GitHub hosts were unavailable.
- Droplet-size distributions in the engines are design choices (uniform, log-normal, uniform-in-log), not measurements; no source ties them to fluid physics.
