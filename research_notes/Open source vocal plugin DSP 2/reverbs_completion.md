## Room: the complete per-sample algorithm of freeverb3 `progenitor2` as shipped in Dragonfly Room

### Takeaway
The earlier notes (section D) already hold every table and default correctly; what was missing is the exact element equations, the order of operations inside one sample, the tap read semantics, the modulation/noise sources and the per-rate integer sizes. All of that is below, so Room can be ported without opening the C++ again. Three details matter most: the 15/16 output taps are read *after* the delay writes with `get_z(k)` = "written k-1 samples ago"; the nested all-passes carry their own decay gains (0.938/0.844/0.906 per second, not just a loop gain); and the code's left tap list deviates from its own comment in one tap.

**Element equations *[src]*** — [allpass_t.hpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/allpass_t.hpp), [allpass.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/allpass.cpp), [delay_t.hpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/delay_t.hpp), [comb_t.hpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/comb_t.hpp)
- Plain delay `process(x)`: `out = buf[i]; buf[i] = x; i = (i+1) % size`. `getlast()` = `buf[i]` (the sample that is `size` samples old, read *before* this sample's write). `get_z(k)` = `buf[i - k]` (wrapped once): when called **after** the write of the current sample, `get_z(1)` is the sample just written, so `get_z(k)` is the line input delayed by `k-1` samples. No bounds check in the `_get_z` variant the reverb uses.
- Plain all-pass `_process(x)`: `z = buf[i]; x += fb*z; out = z - fb*x; buf[i] = x`. (Used by the 4 cross-feed all-passes.)
- Modulated all-pass `allpassm._process_dc(x, mod, fmod)` (the 10 input all-passes use the non-decay form `_process`, i.e. `decay = 1`): buffer length `size + modsize`, `writeidx = 0`, `readidx = 2*modsize` at reset, so the nominal delay is `size - modsize` samples plus the modulation offset `(mod+1)*modsize` in `[0, 2*modsize]` (centre = `size`). Per sample: `m = (mod + 1)*modsize; fl = floor(m); frac = 1 - (m - fl); a = readidx - fl; b = a - 1` (both wrapped); `z1 = buf[b] + frac*(buf[a] - z1)` (first-order all-pass interpolation with state `z1`); `readidx++`; `feedback_mod = feedback + fmod`; `buf[writeidx] = x + z1*feedback_mod; out = decay*z1 - buf[writeidx]*feedback_mod; writeidx++`.
- Double-nested all-pass `allpass2._process(x)` (`buffer1` = inner, size1; `buffer2` = outer, size2): `x += fb2*b2; out = decay2*b2 - x*fb2; x += fb1*b1; buffer2[i2] = decay1*b1 - x*fb1; buffer1[i1] = x` where `b1 = buffer1[i1]`, `b2 = buffer2[i2]` are the oldest samples; both indices then advance.
- Triple-nested all-pass `allpass3._process(x, mod)` (`buffer1` innermost and modulated, length `size1 + size1mod`, `readidx1 = 2*size1mod`; `buffer2` middle; `buffer3` outermost): `x += fb3*b3; out = decay3*b3 - fb3*x; x += fb2*b2; buffer3[i3] = decay2*b2 - fb2*x; t = buffer1[b]*frac + buffer1[a]*(1-frac)` (**linear** interpolation here, with `m = (mod+1)*size1mod`, `fl = floor(m)`, `frac = m - fl`, `a = readidx1 - fl`, `b = a - 1`); `x += fb1*t; buffer2[i2] = decay1*t - fb1*x; buffer1[writeidx1] = x`.
- `get_z1/2/3(k)` on the nested all-passes read `bufferN[idx - k]` with the same "after the write" semantics (for `buffer1` of `allpass3` the reference index is `readidx1`).
- Output comb `_process_ff(x, g)`: `out = buf[i]*g + x; buf[i] = x` (feed-forward echo with LFO-controlled gain).

**Filters, LFOs and noise *[src]*** — [efilter.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/efilter.cpp), [efilter_t.hpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/efilter_t.hpp), [biquad.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/biquad.cpp), [biquad_t.hpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/biquad_t.hpp), [fv3_defs.h](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/fv3_defs.h)
- DC cut: `out = x - x1 + g*y1` with `c = 2*fc/fs`, `g = (sqrt(3) - 2*sin(pi*c)) / (sin(pi*c) + sqrt(3)*cos(pi*c))`; default 5 Hz.
- First-order filters (`iir_1st`, direct form I: `out = x*b1 + y1; y1 = out*a2 + x*b2`). `setLPF_BW`: `t = tan(pi*fc/fs); b1 = b2 = t/(1+t); a2 = (1-t)/(1+t)`. `setHPF_BW`: `b1 = 1/(1+t); b2 = -b1; a2 = (1-t)/(1+t)`. These are the input LPF (`inputdamp`, 20 kHz, clamped to fs/2), the two loop dampers (`damp`) and the LFO smoothers.
- Biquads are RBJ, direct form I (`y = b0*x + b1*x1 + b2*x2 - a1*y1 - a2*y2`), bandwidth mode: `w = 2*pi*fc/fs; alpha = sin(w)*sinh(ln2/2 * bw * w/sin(w))`. LPF: `b0 = b2 = (1-cos w)/2/(1+alpha), b1 = (1-cos w)/(1+alpha), a1 = -2cos w/(1+alpha), a2 = (1-alpha)/(1+alpha)`. APF: `b0 = (1-alpha)/(1+alpha), b1 = -2cos w/(1+alpha), b2 = 1, a1 = b1, a2 = b0`. Used for: bass-boost LPF (`damp2` 500 Hz default, bw 2 octaves), bass all-pass (150 Hz, bw 4), output LPF (`outputdamp`, bw 2; clamped to `fs/2.5`).
- LFO = unit phasor rotated by `2*pi*f/fs` each sample (`re,im` rotation, output `im`, renormalised every 10000 samples), i.e. a sine starting at 0. `lfo1` at `spin` Hz then scaled and smoothed by a first-order LPF at `spinlimit` (20 Hz); `lfo2` at `spin2` (2.4 Hz), LPF at `spinlimit2` (12 Hz).
- `noise1` is `noisegen_pink_frac`: a table of `2^15` samples built by midpoint displacement with Hurst constant 0.5 (`r = 2*H^2 + 0.3` initial amplitude, divided by `2^H` per level, values clamped to +/-1, random numbers from C `rand()`), consumed one value per audio sample. In the original library the whole 32768-point table is regenerated in one call when it runs out (once every 0.68 s at 48 kHz); Dragonfly merged a change on 2026-11-14 (PR #191 "amortise-pink-noise") that spreads the regeneration over the block (two steps per sample).

**Per-sample order of operations (late reverb, both channels) *[src]*** — [progenitor2.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/progenitor2.cpp)
1. `outL = dccutL(inL); outR = dccutR(inR)`.
2. `mnoise = noise1(); lfo = lfo1_lpf((lfo1() + 0.09*mnoise) * wander); mnoise *= 0.06` (modnoise1 = 0.09, modnoise2 = 0.06). One LFO and one noise value serve both channels.
3. Input diffusion, 10 stages, `sign = -1` initially and flipped after every stage: `outL = iAllpassL[i](outL, mod = lfo*sign, fmod = mnoise)`; `outR = iAllpassR[i](outR, mod = lfo, fmod = mnoise*sign)`. Coefficient `-idiff1`; excursion `p_(32/3 = 10, fs/34125)` samples (17 at 48 kHz).
4. Cross-feed: `crossL = CL3(CL2(CL1(CL0(outL))))`, same for R with the CR table, plain all-passes with coefficient `+odiff1`. Then `outL = lpf_in(outL + 0.4*crossR); outR = lpf_in(outR + 0.4*crossL)` (crossfeed = 0.4; `lpf_in` = first-order LPF at `inputdamp`).
5. Loop re-entry: `crossR = delayR_58.getlast(); crossL = delayL_37.getlast()` (the full-length outputs of the last delay of each half, read before they are written this sample); `outL += loopdecay * (crossR + bassb * lpfBassL(bassAPL(crossR)))`; `outR += loopdecay * (crossL + bassb * lpfBassR(bassAPR(crossL)))`.
6. First half of each side: `outL = APm_L2.process_dc( delayL_16( APm_L1.process_dc( dampL(outL), lfo, mnoise ) ), -lfo, -mnoise )`; `outR = APm_R2.process_dc( delayR_ts( APm_R1.process_dc( dampR(outR), -lfo, -mnoise ) ), lfo, mnoise )`. `APm_L1` = 239 (coef diff1, decay d2), `APm_L2` = 392 (coef diff2, decay d3), `delayL_16` = 2; `APm_R1` = 205, `APm_R2` = 329, `delayR_ts` = 1; excursion `p_(32, fs/34125)` (47 at 48 kHz).
7. Second half: `delayL_37( AP3_L( delayL_31( AP2_L( delayL_23(outL) ) ), lfo ) )` and `delayR_58( AP3_R( delayR_49( AP2_R( delayR_40(outR) ) ), -lfo ) )`. Sizes @ 34125: `delayL_23` 1055, `AP2_L` (inner 1944, outer 612), `delayL_31` 344, `AP3_L` (inner 1212 with modulation excursion 121, middle 816, outer 1264), `delayL_37` 1572; `delayR_40` 1460, `AP2_R` (2032, 368), `delayR_49` 500, `AP3_R` (1452 with excursion 5, 688, 1340), `delayR_58` 16.
8. Coefficients/decays: `AP2`: `fb1 (inner) = diff4 = 0.25`, `fb2 (outer) = diff3 = 0.406`, `decay1 = d1`, `decay2 = d2`. `AP3`: `fb1 = fb2 = diff4`, `fb3 = diff3`, `decay1 = decay2 = d1`, `decay3 = d2`. With `T = rt60/RSFactor`: `loopdecay = 0.237^(1/T)`, `d1 = 0.938^(1/(T*decayf))`, `d2 = 0.844^(1/(T*decayf))`, `d3 = 0.906^(1/(T*decayf))`, `decayf = 1`.
9. Output taps (read after step 7; indices are the tables scaled with `f_`, see below). Left = "Dout":
   `0.469 * dL23[1]`
   `+ 0.219 * ( dL31[40] - dR49[192] + dL31[276] - dR40[110] - dR49[468] )`
   `+ 0.064 * ( dL37[1572] + AP2_L.z1[121] + AP2_L.z2[480] - AP2_R.z2[103] + AP3_L.z1[26] + AP3_L.z2[780] + AP3_L.z3[1200] - AP3_R.z2[310] )`
   `+ 0.045 * dL37[780]`
   Right = "Bout":
   `0.469 * dR40[625]`
   `+ 0.219 * ( dR49[468] - dL31[312] + dR49[24] - dL37[36] - dL23[790] - dL31[189] )`
   `+ 0.064 * ( dR58[8] + AP2_R.z1[10] + AP2_R.z2[359] - AP2_L.z2[30] + AP3_R.z1[10] + AP3_R.z2[109] + AP3_R.z3[1310] - AP3_L.z2[800] )`
   `+ 0.045 * dR58[10]`
   (numbers in brackets are @ 34125 Hz; `z1/z2/z3` = inner/middle-or-outer/outer buffer of the nested all-pass as defined above). The left side has 15 taps and the right side 16. ### Inferences
- Because the two modulated all-passes at the head of each half-loop and the nested all-passes all apply `decay` to their delayed path only (not to the feed-through path), they are not true all-passes when `decay < 1`: they are lossy, and at short decay settings they do most of the damping of the tail while `loopdecay` (as low as 0.02 at 0.3 s) barely recirculates anything. The Room sound at vocal settings (0.3-1.0 s) is therefore largely one pass through 10 + 2 + nested 5 all-pass stages per side plus cross-feed: a dense burst rather than a recirculating tail. That is structurally unlike the 8-line FDN the app currently re-voices as "Room".
- The Diffuse control maps to `idiff1 = odiff1 = diffuse/120`, so the vocal presets (86-98 %) run the 10 input all-passes at 0.72-0.82: very high diffusion, which is what gives the room its smooth, non-fluttery onset on consonants.
- For a Rust port: all sizes can be computed at parameter-change time with `p_`; buffers should be pre-allocated for the largest case (Size 32 m at 96 kHz gives a factor of 9.0, so the longest all-pass, 2032, needs about 18.3k samples plus the excursion); the `floor()` in the modulated all-passes can be an integer truncation because the modulation offset is never negative; and the pink-noise table should be generated incrementally or replaced by a cheap smoothed noise, since the original regenerates 32768 values in one call.
- A mono-in port can keep both input chains: the same mono signal through the L and R input all-pass tables already gives decorrelated L/R injection, which is how Dragonfly behaves with a mono source on both inputs.

### Gaps
- I did not diff Dragonfly's vendored freeverb3 against the latest upstream freeverb3 release (nongnu.org is not reachable from this sandbox); the only local change I can see is the amortised noise generator merged on 2026-11-14.
- The exact random sequence of the modulation noise depends on C `rand()` and cannot be reproduced bit-for-bit in Rust; it does not need to be (it is a +/-9 % perturbation of the LFO and +/-0.06 of the all-pass coefficients).
- The origin of the tap weights and of the "normalized decay attenuation for 1 s" constants is only documented by the source comment citing the Lexicon 224 manual; I did not consult the manual.

## Chamber: which open algorithm gives a dense, bright echo-chamber sound distinct from plate and hall, with its complete inner loop

### Takeaway
No open reverb models a physical echo chamber, so "Chamber" has to be chosen by measured behaviour. Three candidates are fully specified below and behave very differently (measured from their original C++): (1) freeverb3 **`nrevb`** as its author wrote it (18 parallel damped combs plus the dry signal through 8 series all-passes) is dense from the first milliseconds, the brightest of everything measured, has a real RT60 control and costs about 74 ns per stereo sample; (2) Airwindows **kChamberAR** (25-delay 5x5 tank, 3x3 early delay grid, saturation) is dense within about 15-30 ms and true stereo, but its decay is fixed in code (about 1 s) and its author calls it "dirty, aggressive, and wild"; (3) Airwindows **Chamber** (12 golden-ratio delays in three feed-forward 4x4 banks) is the one its author says "always sound[s] like a chamber", but it is **dual mono** (identical L and R from a mono input, measured) and its echo density builds slowly (0.1-0.4 s to a dense tail). My recommendation for the vocal chain is `nrevb` as the Chamber engine, with Airwindows Chamber as an optional sparse "slap chamber". One surprise: Dragonfly Plate's shipped "Nested" mode does **not** run the 18-comb `nrevb` loop any more (see the finding below), so a port must follow `nrevb.cpp`, not the plugin's audible behaviour.

### Cited Findings

**What the authors say** — [Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt), [what.txt](https://github.com/airwindows/airwindows/blob/master/what.txt)
- Chamber: "a feedforward reverb, using three banks of four delays each in a Householder feedback matrix, except it's feedforward. Only the very end feeds back into the beginning again ... (it is dual-mono like Verbity ...). And the delays go to a longest delay (maximum delay size) and each one in turn, back to the first, is exactly the golden ratio smaller than the previous." ... "It'll always sound like a chamber, hence the name". Its Darkness control is "tweaked so that the fall-off over time is always accurate to the sound of audio decaying in air ... but the tone-shaping is darkened using very warm, basic IIR filters", and it has a high-pass "Very useful for a chamber or plate send". `what.txt` tags it `[coll=Basic,Recommended]`.
- Chamber2: "don't use Chamber2 where Chamber will do" (it only adds a variable ratio, which turns the reverb into a "blur echo", and uses far more memory).
- kChamberAR: "So I didn't get the Abbey Road chamber, not really ... it's a tape echo into a chamber gone terribly wrong ... dirty, aggressive, and wild ... I honestly think this works better as an instrument".

**Airwindows Chamber: complete algorithm *[src]*** — [ChamberProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Chamber/ChamberProc.cpp), [Chamber.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Chamber/Chamber.cpp), [Chamber.h](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Chamber/Chamber.h)
- Controls (all 0-1, defaults all 0.35): A Bigness, B Longness, C Liteness, D Darkness, E Wetness.
- Set-up per block: `overallscale = fs/44100`; `cycleEnd = clamp(floor(overallscale), 1, 4)`; `size = A^2*0.9 + 0.1`; `regen = (1 - (1-B)^6) * 0.123`; `highpass = C^2 / sqrt(overallscale)`; `lowpass = (1 - D^2) / sqrt(overallscale)`; `interpolate = size * 0.381966011250105`.
- Delay lengths (integers, truncated at every step): `delayE = 19900*size`, then each next = previous x 0.618033988749894848204586 in the order E, F, G, H, A, B, C, D, I, J, K, L. At `size = 1`: E 19900, F 12298, G 7600, H 4697, A 2902, B 1793, C 1108, D 684, I 422, J 260, K 160, L 98; at the default (A = 0.35, size 0.21025): 4183, 2585, 1597, 987, 609, 376, 232, 143, 88, 54, 33, 20 (my arithmetic). Buffers are declared 20000, 12361, 7640, 4722, 2916, 1804, 1115, 689, 426, 264, 163, 101 samples per channel. These are core-rate samples: the same counts are used at 44.1 and 48 kHz.
- Per input sample, each channel identically (state per channel): `iirC = iirC*(1-highpass) + in*highpass; in -= iirC` (one-pole high-pass); `iirA = iirA*(1-lowpass) + in*lowpass; in = iirA` (one-pole low-pass).
- Every `cycleEnd`-th sample the reverb core runs:
  1. Feedback smoothing (in-loop damping): for X in A..D: `feedbackX = feedbackX*(1-interpolate) + previousX*interpolate; previousX = feedbackX`.
  2. Bank 1 write: `I <- in + feedbackA*regen; J <- in + feedbackB*regen; K <- in + feedbackC*regen; L <- in + feedbackD*regen`; advance, read outputs `oI, oJ, oK, oL` (each delayed by exactly `delayX` samples: the index wraps when it exceeds `delayX`, so the buffer period is `delayX + 1` and the read happens after the increment).
  3. Bank 2 write: `A <- oI - (oJ+oK+oL); B <- oJ - (oI+oK+oL); C <- oK - (oI+oJ+oL); D <- oL - (oI+oJ+oK)`; read `oA..oD`.
  4. Bank 3 write: `E <- oA - (oB+oC+oD); F <- oB - (oA+oC+oD); G <- oC - (oA+oB+oD); H <- oD - (oA+oB+oC)`; read `oE..oH`.
  5. `feedbackA = oE - (oF+oG+oH); feedbackB = oF - (oE+oG+oH); feedbackC = oG - (oE+oF+oH); feedbackD = oH - (oE+oF+oG)`.
  6. Wet sample `= (oE + oF + oG + oH) / 8`.
- When `cycleEnd > 1` the wet sample is linearly interpolated across the skipped samples and then passed through `cycleEnd - 1` two-sample averages (`(x + prev)*0.5`); at 44.1/48 kHz neither happens.
- Then a second one-pole low-pass with the same `lowpass` coefficient (`iirB`), then the wet/dry law (`wet = 2E` clipped to 1, `dry = 2 - 2E` clipped to 1), then Airwindows' floating-point dither.
- Each mix `y_i = x_i - (sum of the other three)` is -2 times a 4x4 Householder reflection (gain 2 per bank), so the loop is lossless at `regen = 1/8 = 0.125`; the code's maximum is 0.123 (loop gain 0.984 per trip). Output is divided by 8 for the same reason.
- **Chamber2** differs only in: `size = A*0.9 + 0.1` (linear), `delayE = 9900*size`, ratio `echo = 0.618... + 0.381...*(1 - Thick)` instead of the fixed golden ratio, `regen = (1 - (1-B)^2)*0.123`, `interpolate = (1 - echo)*0.381966...`, an extra pre-delay of `sqrt(9900*size)` samples, no high-pass/low-pass, and feedback values A and C swapped between the left and right channels. Defaults 0.34 / 0.31 / 0.28 / 0.25. — [Chamber2Proc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Chamber2/Chamber2Proc.cpp), [Chamber2.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Chamber2/Chamber2.cpp)
- *[measured]* Feeding the same mono signal to both inputs, Chamber and Chamber2 produce L and R that differ only at dither level (difference energy about 1e-11 against a signal energy of about 2e3 over one second), i.e. the wet signal is mono. kChamberAR and kPlateA under the same test give a difference energy of the same order as the signal (true stereo). Compiled from the files above with a stub VST header.

**Airwindows kChamberAR: complete algorithm *[src]*** — [kChamberARProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/kChamberAR/kChamberARProc.cpp), [kChamberAR.h](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/kChamberAR/kChamberAR.h), [kChamberAR.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/kChamberAR/kChamberAR.cpp)
- Controls and defaults: A Input 1.0, B Delay 0.5, C Regen 0.0, D Low Cut 0.0, E Wetness 0.5. `downRate = fs/cycleEnd`; `speed = (1-B)^3*80 + 1`; `steedRegen = C^2*0.618`; `iirAmount = (D + 0.02)*1000/downRate`; tank `regen = 0.0002825` (a constant: no decay control); tape buffer length `adjPredelay = downRate` samples (one second).
- Tables (core-rate samples; source comment "1 to 40 ms, 52 seat room"): early `A..I = 17, 503, 43, 71, 653, 353, 641, 5, 439`; tank `A..Y = 263, 103, 43, 349, 109, 71, 173, 11, 311, 331, 5, 353, 359, 7, 23, 367, 29, 313, 3, 251, 383, 191, 17, 233, 101`.
- Fixed band-pass biquads (`K = tan(pi*f)`, `norm = 1/(1 + K/Q + K^2)`, `a0 = K/Q*norm, a1 = 0, a2 = -a0, b1 = 2*(K^2-1)*norm, b2 = (1 - K/Q + K^2)*norm`; run as `out = in*a0 + s1; s1 = in*a1 - out*b1 + s2; s2 = in*a2 - out*b2`): `fixA` at `3059/downRate` with Q 0.0166464 (inside the tank); `fixC` and `fixD` at `217/downRate` with Q 0.0039204 (tape path). The Q values are far below 1, so these are very broad band-passes.
- Front end, in order, once per core sample: `x *= A` (if A < 1); `x += steedRegenState * steedRegen`; high-pass `iirA = iirA*(1-iirAmount) + x*iirAmount; x -= iirA`; clip to +/-1.4137166941154 then "BigFastSin" `x = (x/2)*(2.8274333882308 - |x|)` (sign kept); `fixD` band-pass; **tape delay**: a write head that moves backwards through the one-second buffer by `speed` samples per core sample, filling the skipped cells with a linear ramp from the previous to the current input, and a read at the new head position, which gives a delay of about `1/speed` seconds (12 ms at B = 0, 91 ms at B = 0.5, 1 s at B = 1; my arithmetic) and pitch slides when B moves; the delayed sample is stored as `steedRegenState`; second high-pass (`iirB`, same amount); `fixC` band-pass; two cascaded two-sample averages. The result `x` feeds the early grid and the tank in parallel.
- Early grid (plain delays, not all-passes; three stages of three with the mix `(sum of the other two) - self`): left `A, B, C <- x`; then `D <- (oB+oC)-oA, E <- (oA+oC)-oB, F <- (oA+oB)-oC`; then `G <- (oE+oF)-oD, H <- (oD+oF)-oE, I <- (oD+oE)-oF`; `earlyL = oG + oH + oI`. Right walks the transposed grid: `C, F, I <- x`; then `B <- (oF+oI)-oC, E <- (oC+oI)-oF, H <- (oC+oF)-oI`; then `A <- (oE+oH)-oB, D <- (oB+oH)-oE, G <- (oB+oE)-oH`; `earlyR = oA + oD + oG`.
- Tank, left channel: bank 1 `A..E <- x + feedback{A..E}L * regen`; `oA` passes the `fixA` band-pass; bank 2 `F..J`, bank 3 `K..O`, bank 4 `P..T`, bank 5 `U..Y`, each written with `y_i = 3*x_i - 2*(sum of the other four)` of the previous bank's outputs in order; two-sample averages ("mulch") on `oQ` (before the bank-5 mix) and on `oV` (before the feedback mix). Right channel uses the same 25 lengths in transposed order: bank 1 `E, J, O, T, Y <- x + feedback{E,J,O,T,Y}R * regen` with `oE` through `fixA`; bank 2 `D, I, N, S, X`; bank 3 `C, H, M, R, W`; bank 4 `B, G, L, Q, V`; bank 5 `A, F, K, P, U`; mulch on `oG` and `oF`.
- Feedback (cross-coupled), each a `3*x - 2*(others)` mix of a final bank with the named output as the `x` term: `feedbackAL <- right {A | F,K,P,U}`, `feedbackBL <- right {F}`, `feedbackCL <- left {W | U,V,X,Y}`, `feedbackDL <- left {X}`, `feedbackEL <- left {Y}`; `feedbackER <- left {U}`, `feedbackJR <- left {V}`, `feedbackOR <- right {K}`, `feedbackTR <- right {P}`, `feedbackYR <- right {U}`.
- Output: `wetL = (oU+oV+oW+oX+oY)*0.0016 + earlyL*0.25` (right: `(oA+oF+oK+oP+oU)*0.0016 + earlyR*0.25`); gain tracker `wet *= gainOut; gainOut += sin(min(|4*wet|, 4)) * wet^4`, `gainOut` clamped to [0.0078125, 1] before use (a fast limiter-like element: `sin(4)` is negative, so loud samples pull the gain down and quiet ones let it recover); two cascaded two-sample averages; linear interpolation when `cycleEnd > 1`; clip to +/-2.8 and "BigFastArcSin" `y = 2x / (2.8274333882308 - |x|)` (sign kept); wet/dry as in Chamber.
- The 5x5 mix has gain 5 per bank, so the lossless regen is `1/5^5 = 0.00032`; the fixed 0.0002825 is a loop gain of 0.883 per trip. The sum of the 25 delays is 4399 samples, so the mean trip through five banks is 880 samples = 20 ms at 44.1 kHz, which gives an RT60 of roughly 1.1 s (my arithmetic, ignoring the band-pass and averaging losses, which shorten it).

### Inferences
- Why these sound unlike the plate and the hall, from the code: `nrevb` is a parallel structure (18 independent damped combs summed, then smeared by series all-passes), so it has no single loop period and no early/late split; the direct signal enters the all-pass chain at once, hence the immediate density and the very bright spectrum. Airwindows Chamber has no all-pass anywhere and no early stage; one pass through its three banks emits 4 x 4 x 4 = 64 signed echoes whose delays are sums of one length from each bank, spread geometrically, and the tail is those bursts recirculated through one gain, which is why its density builds slowly (measured above) and why its author describes the un-regenerated sound as "a weird stuttery slapback". The Dattorro plate is a two-delay figure-eight with all-pass smearing and the zrev2 hall is eight long lines with band-shelved decay.
- Which to build: for "dense and bright, no distinct early pattern, adjustable decay" the measurements favour `nrevb`'s real loop. Its known weakness is structural: 18 fixed parallel combs (49-98 ms) can ring metallically at long decays, so I would cap its decay near 2 s and give it light modulation or keep it as a short-to-medium chamber; this is a judgement from the structure, not something I measured.
- Decay for a port: the loop gain per trip is `g = regen/0.125` and the mean trip time is the sum of the three banks' mean lengths (about 62 ms at the default size, 96 ms at Bigness 0.5, 294 ms at Bigness 1.0 for a 44.1 kHz core; my arithmetic). A decay control in seconds can therefore be mapped as `regen = 0.125 * 10^(-3 * T_trip / RT60)` instead of the Longness curve. This mapping is my derivation, not in the source, and treats the mean path as the loop time, so it is approximate.
- Stereo for a mono vocal: the source gives no stereo mechanism for Chamber. The smallest change is to run the right channel with a slightly different `size` (a few percent), which changes all twelve lengths; this is a design decision of the port, not something the Airwindows code does. kChamberAR's transposed-grid trick needs a square bank layout and cannot be applied to a 3x4 arrangement.
- kChamberAR is not adjustable enough for a general chamber (fixed regen, about 1.1 s; a very short 20 ms trip; saturation and a level-dependent gain element in the path). If it is used, it is a "character chamber/slap" preset; exposing `regen` between about 0.00024 and 0.00031 would give a decay control, which is a port decision (kPlateA does exactly this with its Damping control: `regen = (B*0.415 + 0.16)*0.0001 + 0.00024`).
- Airwindows' "sample-rate handling" means a 48 kHz session runs the 44.1 kHz tables unscaled (all times 8.1 % shorter) and a 96 kHz session runs them at a 48 kHz core with linear interpolation. For this app (48 kHz main target) either accept that, as the original does, or scale the lengths by `fs/44100`; for Chamber the latter is harmless because its lengths are computed, not hand-picked primes.

### Gaps
- The newer Airwindows plates (kPlate140, kPlate240: "Pear filters", "SubTight", Bezier "DeRez") and kStation/kWoodRoom/kCathedral inner loops were not read; the earlier notes' gap for them stands. kPlateB/C/D loops were not read either.
- No listening test or third-party review backs the claim that Airwindows Chamber resembles a physical echo chamber; the evidence is the author's own description and the structure.
- I did not find any open, well-regarded model of a specific physical chamber (Capitol, Abbey Road) with a compatible licence.

## Cloud/ambient: the complete Cloud Seed (CloudSeedCore, MIT) signal flow, its reproducible random generator, and programs usable without the GUI

### Takeaway
The earlier notes (section J) already describe the blocks and the parameter scaling correctly; this section adds the exact pseudo-random generator and which random number feeds which constant (verified by re-implementing it and matching the C++ output), the processing order, the hidden costs (block-size-dependent loop time, about 67 MB of buffers, 1.2-2.3 microseconds per sample as shipped) and programs converted to physical units. CloudSeedCore ships only one program ("Dark Plate"); the nine legacy v1 programs use a different (SHA-256-based) random generator and a different multitap, so their numbers transfer as structure (stage counts, times, feedbacks, decays) but not as seeds.

### Cited Findings

**The random generator, exactly *[src, verified]*** — [LcgRandom.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/LcgRandom.h), [RandomBuffer.cpp](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/RandomBuffer.cpp)
- State `x` is a 64-bit unsigned integer initialised to the seed. Each draw: `x = (22695477 * x + 1) & 0xFFFFFFFF`; value `= (float)x / (float)UINT_MAX` (32-bit float division, so the result is rounded to float precision; range 0..1). The first value returned is already one step past the seed.
- `Generate(seed, count, crossSeed)` builds series A from `seed` and series B from `~seed` (bitwise NOT of the 64-bit seed; only its low 32 bits matter after the first step) and returns `A[i]*(1 - crossSeed) + B[i]*crossSeed`.
- Check values (my re-implementation in Python matches the compiled C++ to all printed digits): seed 1 gives 0.005284203, 0.501993477, 0.667579949; seed 218 with crossSeed 0 gives, for indices 24..35, 0.023407 0.651329 0.044498 0.716252 0.181995 0.978246 0.507741 0.079632 0.791238 0.395359 0.799665 0.411414, and with crossSeed 1: 0.140516 0.357801 0.753165 0.763153 0.808820 0.395949 0.568531 0.113004 0.333760 0.068416 0.223389 0.056430.
- Seeds are integers `floor(param * 999.999)` (0..999). Per-channel cross value: right channel `0.5 * CrossSeed`, left channel `1 - 0.5 * CrossSeed`. — [Parameters.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/Parameters.h), [ReverbChannel.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ReverbChannel.h)

**Which random number sets which constant *[src]*** — [MultitapDelay.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/MultitapDelay.h), [AllpassDiffuser.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/AllpassDiffuser.h), [ReverbChannel.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ReverbChannel.h)
- Multitap: `r = Generate(SeedTap, 768, cross)`; for tap `j = 0..255`, three consecutive values: `phase = (r[3j] < 0.5) ? +1 : -1`; `gain_j = 10^((-20 + 20*r[3j+1])/20) * phase`; `position_j = j + r[3j+2]`. At run time, tap offset `= (int)(position_j * LengthSamples / Count)`; tap weight `= gain_j * (exp(-offset/LengthSamples * 3.3) * decay + (1 - decay)) * 3/sqrt(1 + Count) * (1 + 2*decay)`; only the first `Count` taps are used. The `exp()` is evaluated per tap per sample in the shipped code.
- All-pass diffuser (early: seed `SeedDiffusion`; in line `i`: seed `SeedPostDiffusion * (i + 1)`): `r = Generate(seed, 36, cross)`; stage `k = 0..11`: `delay_k = (int)(DelaySamples * 10^r[k] * 0.1)`; `modAmount_k = ModAmount * (0.85 + 0.3*r[12 + k])`; `modRate_k = ModRate * (0.85 + 0.3*r[24 + k]) / fs`. Only the first `Stages` stages run; all share one feedback value. (The class default seed is 23456 until a seed parameter is applied.)
- Delay lines: `r = Generate(SeedDelay, 36, cross)`; line `i = 0..11`: `modAmount_i = LineModAmount * (0.7 + 0.3*r[i])`; `modRate_i = LineModRate * (0.7 + 0.3*r[12 + i]) / fs`; `delay_i = (int)((0.5 + r[24 + i]) * LineSizeSamples)`, raised to `modAmount_i + 2` if smaller; `feedback_i = 10^(-3 * delay_i / DecaySamples)`.
- LFO start phases are **not** seeded: each modulated all-pass and delay initialises its phase with C `rand()` (`0.01 + 0.98*rand()/RAND_MAX`), so two instances differ unless `srand` is fixed. — [ModulatedAllpass.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ModulatedAllpass.h), [ModulatedDelay.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ModulatedDelay.h)

**Processing order and element equations *[src]*** — [ReverbController.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ReverbController.h), [ReverbChannel.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ReverbChannel.h), [DelayLine.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/DelayLine.h), [Lp1.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/Lp1.h), [Biquad.cpp](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/Biquad.cpp)
1. Controller: `cm = InputMix*0.5`; `inL' = inL*(1-cm) + inR*cm`, `inR' = inR*(1-cm) + inL*cm`; then two independent channels.
2. Channel: optional one-pole high-pass, optional one-pole low-pass (`alpha = (2 - cos w) - sqrt((2 - cos w)^2 - 1)`, `y = (1-alpha)*x + alpha*y`); gate (`x*x < 1e-9 -> 0`); pre-delay (integer samples); optional multitap; optional early diffuser; the result is the "early" signal.
3. Each of `LineCount` lines receives the same early signal. Line: `x = in + feedback * loopOut` -> modulated delay (two-point linear interpolation, LFO recomputed every 8 samples: `total = delay + modAmount*sin(2*pi*phase)`, `phase += modRate*8`) -> [tap here if LateMode = PRE] -> optional diffuser (1-8 stages in the parameter mapping) -> optional low shelf -> optional high shelf -> optional one-pole low-pass -> `loopOut` -> [tap here if LateMode = POST].
4. All-pass stage: `z = interp(buffer, delay); v = in + z*fb; write v; out = z - v*fb`. With modulation off the read is an integer delay.
5. Sum of the line taps x `1/sqrt(LineCount)`; `out = dry*in + early*earlySignal + late*lineSum` (the dry term uses the channel's mixed input).
- The shelves are second-order (Butterworth-style, `K = tan(pi*f/fs)`, `V = 10^(|gain|/20)`); in the parameter mapping the shelf gains only cut (-20..0 dB).
- `loopOut` reaches the next iteration through a block FIFO, so the real loop time is `delay_i + blockSize` samples for the block size the host uses (64 samples = 1.3 ms at 48 kHz); the RT60 formula ignores this.

## Spring: the chowdsp spring reverb in Surge XT, complete algorithm and constants, and whether it is worth including for vocals

### Takeaway
The earlier notes (section L) have the formulas right but understate the dispersion: each of the 16 cascade stages is a **second-order nested** Schroeder all-pass, so one pass is 32 first-order sections and one trip round the loop is 64. The code lives in the Surge repository (not in sst-effects), is GPL-3.0-or-later, and is "based loosely" on the Välimäki/Parker/Abel parametric spring papers. As shipped it is dual mono (mono in gives mono out, measured), sparse and "boingy" by design, and expensive (627 ns per stereo sample measured, 3 % of a core) mostly because of how it is implemented. For a vocal chain it is an optional character effect, worth including only as a late, low-priority type.

### Cited Findings

**Provenance and licence *[src]*** — [SpringReverbEffect.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/SpringReverbEffect.h), [SpringReverbProc.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/SpringReverbProc.cpp)
- Header comment: "SpringReverb is a spring reverb emulation, based loosely on the reverb structures described in the following papers: V. Valimaki, J. Parker, and J. S. Abel, 'Parametric spring reverberation effect,' Journal of the Audio Engineering Society, 2010; Parker, Julian, 'Efficient Dispersion Generation Structures for Spring Reverb Emulation', EURASIP, 2011. The original implementation can be found at: https://github.com/Chowdhury-DSP/BYOD/tree/main/src/processors/other/spring_reverb".
- File headers state GPL-3.0-or-later. A search of the sst-effects repository for "spring" finds nothing: the spring is in `surge/src/common/dsp/effects/chowdsp/spring_reverb/` only.

**Complete per-sample algorithm *[src]*** — [SpringReverbProc.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/SpringReverbProc.cpp), [SpringReverbProc.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/SpringReverbProc.h), [SchroederAllpass.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/SchroederAllpass.h), [ReflectionNetwork.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/ReflectionNetwork.h), [Shelf.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/shared/Shelf.h), [chowdsp_DelayInterpolation.h](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/shared/chowdsp_DelayInterpolation.h)
- State: four lanes `s[0..3]` = (left main, left feedback, right main, right feedback), processed together by 16 all-pass stages.
- Per sample, per channel `c` (main lane `m = 2c`, feedback lane `m + 1`):
  1. `s[m] = HP40( tanh( in - feedbackGain * longDelay.pop() ) ) + shake[n]` (fast tanh approximation; state-variable high-pass at 40 Hz; `shake` is zero unless "Knock" fired).
  2. All four lanes go through the 16 stages. Stage = nested all-pass of order 2: outer `d = inner(delay.pop()); x += g*d; delay.push(x); out = d - g*x`, where `inner` is a first-order all-pass of the same form with the same delay length and the same `g`. Delay per element `(0.35 + 3*size)` ms with Thiran (first-order all-pass) fractional interpolation. Gains per lane `(+g, -g, +g, -g)` with `g = 0.5 - 0.4*spin`, so the feedback lanes use the opposite sign.
  3. `longDelay.push(s[m+1])` (the feedback lane, i.e. the previous output after a second pass through the cascade); `s[m] -= reflections.pop(); reflections.push(s[m])`; `s[m] = LP(s[m])` (state-variable low-pass); output `= s[m]`; `s[m+1] = s[m]` for the next sample.
- So the loop is: input minus feedback -> tanh -> 40 Hz high-pass -> 16 nested all-passes (+g) -> minus reflection network -> damping low-pass -> **output** -> one sample -> the same 16 nested all-passes on the other lanes (-g) -> long delay (third-order Lagrange interpolation) -> feedback gain.
- Parameter laws (all controls 0-1; defaults size 0.5, decay 0.5, reflections 1.0, spin 0.5, damping 0.5, chaos 0, mix 0.5): `T60 = 0.5 * 9^(0.95*decay - 0.7*(1 - size^2))` s; long delay `= 1000 + size*0.099*fs` samples, plus `chaos^3 * smoothed(rand01 * delay * 0.07)` (new random target every block, 50 ms linear smoothing); `feedbackGain = 0.001^(delay / (T60*fs))`; damping low-pass `= 4000 * 4.5^(1 - damping)` Hz.
- Reflection network: four delays of `0.07, 0.17, 0.23, 0.29` s x `size` (Lagrange), all fed the same signal; outputs `o_i`; Householder `o_i + (-2/4)*sum(o)`; each multiplied by `0.001^(d_i/(T60*fs)) * 0.23 * mix * (0.735 + 0.235*size)` with `mix = 0.95 * reflections^2`; averaged (`sum/4`); then a first-order shelf with low gain 1.0 and high gain `-1 - 9*damping` dB, transition 800 Hz. Its output is subtracted from the main lane and the result is pushed back into all four delays.
- Knock ("shake"): a half-sine burst `2*sin(pi*i/N)` of `N = fs * (0.0005 + 0.0005*rand01) * (1 + 0.5*size)` samples added after the high-pass.
- Both channels use identical parameters, and the chaos value is shared; there is no cross-coupling.
- Values at the defaults at 48 kHz (my arithmetic): all-pass element delay 1.85 ms (88.8 samples), `g` = 0.30, long delay 3376 samples (70.3 ms), `T60` = 0.448 s, `feedbackGain` = 0.338, damping low-pass 8485 Hz, reflection delays 35 / 85 / 115 / 145 ms, shelf -5.5 dB above 800 Hz.

**Measured *[measured; SpringReverbProc compiled from the Surge sources with stub `globals.h`/`UnitConversions.h`, g++ -O3 -msse4.2, 48 kHz, 32-sample blocks]***
- 627 ns per stereo sample (3.0 % of one core).
- Mono signal on both inputs: difference energy between L and R 2.6e-4 against a signal energy of 394 over one second; L/R correlation of the impulse response 1.00. The wet output is effectively mono.
- Impulse response at the defaults: first arrival 14.8 ms; normalised echo density reaches 0.5 only after 292 ms and 0.9 after 1.57 s; RT60 estimate 1.20 s (longer than the 0.448 s `T60` of the main loop because the reflection network recirculates); spectral centroid of the first 200 ms 4.9 kHz. At size 0.7, decay 0.8: first arrival 19.5 ms, density 0.5 after 75 ms and 0.9 after 157 ms, RT60 3.46 s.

### Inferences
- The low echo density is the point of the algorithm: a spring is a dispersive delay line, so the model produces repeating, frequency-smeared echoes ("drip"/"boing") rather than a diffuse tail. That makes it unlike every other type in this file and unsuitable as a general vocal reverb; it suits lo-fi, surf, dub and rockabilly vocal treatments at low mix. This is a structural judgement; I found no reachable source that evaluates this specific model on vocals.
- The measured cost is implementation overhead more than algorithm: every one of the 32 SIMD delay lines and 5 scalar ones is allocated at 2^18 samples, every all-pass read uses Thiran interpolation, and the cascade runs four lanes although the two channels are identical. A mono Rust port (two lanes: main and feedback), with buffers sized to the 3.35 ms maximum element delay, needs per sample about 64 first-order all-pass updates (each two multiplies, two adds, one interpolated read), five interpolated delay reads, two state-variable filters, one shelf and one tanh; I would expect it to cost a fraction of the measured figure, but that is an estimate.
- For mono-in/stereo-out, run one spring and pan it, or de-correlate the second channel with a small size offset (not in the source).
- Fractional (Thiran) delays in the all-passes matter only when Size is modulated; with a fixed size the element delay could be rounded to an integer with a slight retune.

### Gaps
- The two papers the header cites were not read (journal hosts unreachable); I cannot say how far the code departs from them beyond the header's own "based loosely".
- BYOD's original implementation was not diffed against Surge's.
- No vocal-specific settings exist in the source; the Surge defaults are the only shipped values.

## Shimmer: is there a credible open-source pitch-shifted-feedback reverb compatible with GPL-3.0-or-later?

### Takeaway
Yes, two, both with readable source and compatible licences: **"Oliverb"** from the Parasites alternative firmware for Mutable Instruments Clouds (MIT; a Griesinger/Dattorro loop whose feedback is read from the loop delays through a two-tap cross-faded delay-line pitch shifter) and Guitarix **"GxShimmizita"** (GPL-2.0-or-later; the zita-rev1 FDN with a pitch shifter inserted in each of the eight feedback paths). Neither is a famous studio shimmer, but both are complete, small and directly portable; Shimmizita maps one-to-one onto the zrev2-style FDN the app already has.

### Cited Findings

**Oliverb (Parasites Clouds) *[src]*** — [oliverb.h](https://github.com/mqtthiqs/parasites/blob/master/clouds/dsp/fx/oliverb.h), [granular_processor.cc](https://github.com/mqtthiqs/parasites/blob/master/clouds/dsp/granular_processor.cc), [fx_engine.h](https://github.com/mqtthiqs/parasites/blob/master/clouds/dsp/fx/fx_engine.h), [random_oscillator.h](https://github.com/mqtthiqs/parasites/blob/master/clouds/dsp/random_oscillator.h), [README](https://github.com/mqtthiqs/parasites/blob/master/README.md)
- Licence: the repository README states "Code (STM32F projects): MIT license" and `oliverb.h` carries the MIT permission notice (copyright line Emilie Gillet 2014; the Parasites fork is by Matthias Puech). Commit read: `32fa66f` (2021-02-18).
- Source comment: "This is the Griesinger topology described in the Dattorro paper (4 AP diffusers on the input, then a loop of 2x 2AP+1Delay). Modulation is applied in the loop of the first diffuser AP for additional smearing; and to the two long delays for a slow shimmer/chorus effect."
- Memory map in samples (the module runs at 32 kHz): input all-passes `113, 162, 241, 399`; loop A `dap1a 1253, dap1b 1738, del1 3411`; loop B `dap2a 1513, dap2b 1363, del2 4782` (16384-sample buffer, 16-bit storage). Every read offset is `(length - 1) * size` (Hermite interpolation), so Size scales all times.
- Per sample: (a) smear: read `ap1` at `10 + 60*LFO1` and write it back at offset 100; (b) `acc = (L + R) * input_gain`; four all-passes, each read at `(len-1)*size + lfo_k*mod_amount` with gain `kap`, written with `-kap`; `apout = acc`. (c) Half A: `acc += del2[(len-1)*size + lfo*mod] * decay * (1 - shift) + del2[phase] * tri * decay * shift + del2[half] * (1 - tri) * decay * shift`; one-pole low-pass (`state += lp*(acc - state)`); one-pole high-pass (`state += hp*(acc - state); acc -= state`); soft limit `x*(27 + x^2)/(27 + 9x^2)`; all-pass `dap1a` (read gain `-kap`, write `+kap`); all-pass `dap1b` (`+kap`, `-kap`); write `del1`, then `acc *= 2` = left output. (d) Half B: `acc = apout +` the same three reads from `del1`; low-pass, high-pass, soft limit; `dap2a` (`+kap`, `-kap`); `dap2b` (`-kap`, `+kap`); write `del2`, `acc *= 2` = right output.
- The pitch shifter is only a moving pair of read taps on the loop delays: `ps_size = 128 + (3410 - 128)*size`; `phase += (1 - ratio)/ps_size` wrapped to [0, 1); `tri = window(2*min(phase, 1 - phase))` with the raised-cosine table `window(t) = 1 - (cos(pi*t) + 1)/2`; taps at `phase*ps_size` and `(phase*ps_size + ps_size/2) mod ps_size`, weights `tri` and `1 - tri`. With `ratio = 2` the taps sweep toward the write head one sample per sample, which reads the delay at double speed (one octave up).
- Module mapping: `ratio = 2^(pitch/12)` (pitch in semitones); `shift` (blend of shifted versus normal feedback) is 0 while `|pitch| < 0.3` semitones, ramps linearly to 1 at 0.7 semitones; `decay = density*1.3 + 0.15*|pitch|/24`; `input_gain = 0.5`; `kap (diffusion) = 0.3 + 0.5*spread`; `size = 0.05 + 0.94*size_knob`; `lp = 0.03 + 0.9*x`, `hp = 0.01 + 0.2*y` (one-pole coefficients, from the two halves of the texture knob); `mod_amount = reverb_knob*300` samples; nine random LFOs (smoothed random walk through a raised-cosine table, minimum step 0.3) with slope `mod_rate^6 / 200`; freeze sets input gain 0, decay 1, lp 1, hp 0.

**Guitarix GxShimmizita *[src]*** — [shimmizita.inc](https://github.com/brummer10/guitarix/blob/master/trunk/src/LV2/faust/shimmizita.inc), [shimmizita.dsp](https://github.com/brummer10/guitarix/blob/master/trunk/src/LV2/faust/shimmizita.dsp), [gx_shimmizita.cpp](https://github.com/brummer10/guitarix/blob/master/trunk/src/LV2/gx_shimmizita.lv2/gx_shimmizita.cpp)
- Licence: the LV2 wrapper header is GPL "either version 2 of the License, or (at your option) any later version" (Hermann Meyer, Andreas Degert, Pete Shorthose, Steve Poskitt, 2012). Commit read: `2a357f6`.
- Source comment: "Modifiend version of zita FDN reverb. The parametric pitch shifters bank embedded into it." Structure in Faust: `((bus(2N) :> allpass_combs(N) : feedbackmatrix(N)) ~ (delayfilters(N) : pitchshifters(N) : fbdelaylines(N)))` with `N = 8`, the zita-rev1 tables (all-pass delays 20.346 ... 19.123 ms, total delays 153.129 ... 219.991 ms, all-pass coefficient +/-0.6 alternating, Hadamard matrix, low-shelf plus special low-pass decay filter scaled by `1/sqrt(8)`).
- Pitch shifter per line ("borrowed from faust examples: pitch_shifter.dsp"): window `w = 2048` samples, cross-fade `x = 1024`; `i = 1 - 2^(s/12)`; `d = (d + i + w) mod w`; output `= fdelay(d)*min(d/x, 1) + fdelay(d + w)*(1 - min(d/x, 1))`, then a dry/wet mix per line (`ps dry wet`, default 0.5).
- Controls: `shift` -6..+6 (semitones, default 0), `mode` -3..+3 spreads the shift across lines as `shift + shift*mode*coef_i` with `coef = (1/2, 1/3, 1/2, 1/4, 1/2, 1/8, 1/2, 1/3)` for `mode >= 0` and `(1/5, -1/2, 1/3, -1/2, 1/6, -1/3, 1/3, 1/2)` for `mode < 0`; an envelope follower and an LFO (`speed` 0.1-10 Hz, `depth`) modulate the shift; decay controls as zita (`f1` 200 Hz, `t60dc` 3 s, `t60m` 2 s, `f2` 6 kHz); reverb dry/wet 0.5.

**Other things checked** — [Airwindows what.txt](https://github.com/airwindows/airwindows/blob/master/what.txt), [Galactic notes in Airwindopedia.txt](https://github.com/airwindows/airwindows/blob/master/Airwindopedia.txt)
- Airwindows has pitch tools (PitchDelay, PitchNasty, GlitchShifter) but no reverb with a pitch shifter in the regeneration path; Galactic's "Detune" is a quadrature vibrato on the input (earlier notes, section K).
- *[secondary, search summary only]* Commercial references for the effect (Eventide ShimmerVerb: "pitch-shifters sit in the feedback loop"; ValhallaShimmer) and a Sound On Sound technique article exist, but those hosts are not reachable from this sandbox, so no wording from them is quoted here. — [SOS: Creating shimmer reverb effects](https://www.soundonsound.com/techniques/creating-shimmer-reverb-effects) (not opened)

### Inferences
- The standard shimmer structure, as both sources implement it, is: reverb loop -> pitch shifter (usually +12 semitones, sometimes +7 or +19) -> filter -> back into the reverb input or loop, with a blend between shifted and unshifted feedback and loop gain kept below 1. Oliverb puts the shifter inside a two-branch all-pass loop by moving the feedback read taps; Shimmizita puts one shifter in each FDN line.
- Cheapest route for this app: add Oliverb-style shifted taps to the existing Dattorro plate (two extra interpolated reads per half-loop and a shared phase ramp; no new buffers), or add one delay-line shifter on the feedback of the zrev2 FDN (Shimmizita runs eight; one shifter on the mixed feedback bus is a simplification of mine). Both add no latency, because the shifter sits in the feedback path, not the direct path.
- A two-tap delay-line shifter with a window of tens of milliseconds (2048 samples, 43 ms at 48 kHz, in Shimmizita; 128-3410 samples, 4-107 ms at 32 kHz, in Oliverb) produces audible amplitude modulation and smeared transients on a dry signal; inside a reverb loop those artefacts are hidden by the diffusion, which is why both sources get away with the simplest possible shifter.
- For vocals, shimmer needs a low-pass in the loop (each trip adds an octave, so energy climbs toward Nyquist) and a high-pass to stop low-frequency build-up; Oliverb has both one-pole filters and a soft limiter in the loop for exactly this reason.

### Gaps
- No evidence of reputation for either implementation on vocals; "credible" here means maintained, readable, complete and correctly licensed.
- The Faust `pitch_shifter.dsp` example the Guitarix file borrows from was not opened separately; the equations above are from the Guitarix copy.
- I did not render audio from either shimmer.

## Echo-density build-up and what audibly distinguishes these algorithms (evidence from the code and from rendered impulse responses)

### Takeaway
Measured on impulse responses rendered from the original C++ at 48 kHz, the algorithms fall into three clearly different groups: immediately dense (zrev2 hall, progenitor2 room, kPlateA, kChamberAR, `nrevb`: Gaussian-like within 15-40 ms of the first arrival), slowly dense (Dattorro plate about 200 ms, Cloud Seed "Dark Plate" about 120 ms, Airwindows Chamber 110-390 ms) and deliberately sparse (spring: 0.3-1.6 s). The second axis is brightness (spectral centroid from 2 kHz for the vocal room/hall presets to 9-12 kHz for Chamber and `nrevb`) and the third is where the first energy arrives (0 ms for the freeverb3 engines, 11-37 ms for Chamber, about 50 ms for Cloud Seed's late lines).

### Cited Findings

**Method *[measured]*.** A unit impulse was fed to both inputs; wet-only output; 4 s rendered. Normalised echo density (NED) = fraction of samples in a 20 ms Hann-weighted window whose magnitude exceeds the window's RMS, divided by 0.3173 (the value for Gaussian noise), after Abel and Huang's echo-density measure; 1.0 means fully diffuse. Times are measured from the first arrival (first sample above -60 dB of the peak) and cannot resolve below 10 ms. RT60 is a Schroeder-integral estimate (-5 to -35 dB, doubled). "Centroid" is the power-spectrum centroid of the first 200 ms. "L/R" is the correlation coefficient of the two outputs over 2 s. The analysis script is mine; the reverbs are the unmodified sources cited in the other sections.

**Structural evidence from the code *[src]*** — [progenitor2.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/progenitor2.cpp), [zrev2.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/zrev2.cpp), [strev.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/strev.cpp), [nrevb.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/nrevb.cpp), [ChamberProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Chamber/ChamberProc.cpp), [kChamberARProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/kChamberAR/kChamberARProc.cpp), [ReverbChannel.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ReverbChannel.h), [SpringReverbProc.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/SpringReverbProc.cpp)
- Series all-pass sections before or inside one loop trip, per channel: progenitor2 10 input + 4 cross-feed + 2 + 2 (double-nested) + 3 (triple-nested) = 21, with element lengths 2-60 ms at the reference size; zrev2 10 input + 1 per line; strev (Dattorro) 4 input + 2 per half-loop; nrevb 8 in series after 18 parallel combs; Airwindows Chamber, kChamberAR tank and Verbity2 none (pure delays through un-normalised Householder mixes: 4^3 = 64 paths per trip for Chamber, 5^5 = 3125 for the 5x5x5 tanks); Cloud Seed 0-12 early plus 0-8 inside each of up to 12 independent comb loops; spring 32 first-order sections per pass, all with the same 0.35-3.35 ms delay.
- Recirculation times: progenitor2 half-loops are dominated by all-pass memory (plain delays 1055 + 344 + 1572 samples left, 1460 + 500 + 16 right, at 34125 Hz); zrev2 lines 125-257 ms x size/80; Dattorro tank delays 106-150 ms; nrevb combs 49-98 ms; Chamber mean trip 62-294 ms depending on size; kChamberAR mean trip 20 ms; Cloud Seed lines 0.5-1.5 x the size parameter (48-144 ms in Dark Plate); spring 21 ms + size x 99 ms.
- Frequency-dependent decay: zrev2 has per-line low and high shelves (three-band RT); progenitor2 one first-order damper per half-loop plus a bass-boost path; Dattorro one first-order damper per half-loop; nrevb one-pole inside every comb; Chamber a one-pole on the four feedback values with coefficient proportional to size; kChamberAR two-sample averages and fixed band-passes; Cloud Seed optional shelves and a one-pole per line; spring one state-variable low-pass in the loop.

### Inferences
- What a listener will hear as "different types", in order of strength: (1) spring versus everything else (sparse dispersive echoes); (2) Cloud Seed and Galactic versus the rest (very long decays, about 50-100 ms before the wash arrives, slow modulation); (3) plate versus room/hall: the Dattorro plate is bright and takes about 200 ms to become fully dense, whereas the zrev2 hall and progenitor2 room are dense within 20-40 ms and much darker at their vocal settings (centroid 2-4 kHz against 4.8 kHz); (4) room versus hall: nearly identical density, so the difference is decay length, the room's bass-boost path and early-reflection pattern, and the hall's three-band decay and longer lines; (5) chamber: only a bright, immediately dense algorithm (`nrevb`'s real loop) or a bright sparse one (Airwindows Chamber) is clearly distinct from both plate and hall.
- The app's current "Room/Chamber/Cloud = re-voiced 8-line FDN" will all share the FDN's signature (same density curve, same modal pattern scaled). Replacing Room by the nested-all-pass loop, Chamber by the parallel-comb structure and Cloud by the independent diffused combs changes the topology class each time, which is what makes them audibly distinct.
- kPlateA is as dense as the hall almost immediately (21 ms) because of its 3x3 all-pass front end and 25 short delays (5-829 samples); it is a different plate from Dattorro, darker (3.4 kHz centroid with default damping), and could serve as a second plate, as the earlier report suggested.

### Gaps
- NED is one proxy; I did not compute modal density, colouration measures or listening tests. The 20 ms window blurs anything faster than 10 ms.
- MVerb, Plateau, zita-rev1, MI Clouds reverb and Surge Reverb 1/2 were not rendered in this pass.
- The Echo-density reference (Abel and Huang, AES 2006) was applied from memory of the method; the paper itself was not reachable to cite directly.

## CPU cost: measured time per sample of the original C++ and per-sample operation counts

### Takeaway
Measured in this sandbox at 48 kHz (mono signal on both inputs, stereo out, 64-sample blocks unless stated), the original implementations cost between about 30 ns and 2.3 microseconds per stereo sample: Dattorro plate 56-80 ns, early reflections 26-38 ns, `nrevb` real loop 74 ns, Airwindows Chamber 80 ns, kChamberAR 229 ns, kPlateA 253 ns, progenitor2 room 185-345 ns, zrev2 hall 202-403 ns, chowdsp spring 627 ns, Cloud Seed "Dark Plate" 1198 ns. One 48 kHz sample period is 20833 ns, so even the heaviest program here is under 6 % of one core of a 2.1 GHz server CPU, and everything except Cloud Seed and the spring is under 2 %.

**Real-time hazards found in the sources *[src]***
- freeverb3's pink-noise generator (used by progenitor2 and strev for modulation noise) originally rebuilt a 32768-point table in a single call whenever it ran out; Dragonfly merged an amortised version on 2026-11-14 (PR #191). A port should not copy the original behaviour. — [efilter_t.hpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/efilter_t.hpp)
- freeverb3 re-allocates buffers in `setsize` on every size or sample-rate change (`new`/`delete` inside `setRSFactor`); the triple-nested all-pass even frees and re-allocates all three buffers. Pre-allocate in a port. — [allpass.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/allpass.cpp), [revbase.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/revbase.cpp)
- The library's default `UNDENORMAL` macro calls `fpclassify` on many intermediate values; with flush-to-zero set it is pure overhead (removing it cut the plain -O3 times above by 22-25 %). — [fv3_defs.h](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/fv3_defs.h)
- CloudSeedCore allocates nothing per sample but its objects are tens of megabytes of fixed arrays, and `RandomBuffer::Generate` returns `std::vector`s on every seed, size, decay or modulation parameter change (heap allocation on the parameter path). — [RandomBuffer.cpp](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/RandomBuffer.cpp), [ReverbChannel.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ReverbChannel.h)
- The spring's constructor uses `std::random_device` and its `setParams` draws a random number every block; harmless, but not deterministic. — [SpringReverbProc.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/SpringReverbProc.cpp)

### Inferences
- With the plate at about 60-80 ns and the hall at 200-400 ns already in the app, adding the room (about the cost of the hall), the comb chamber (about the cost of the plate) and a right-sized Cloud engine fits comfortably: only one reverb type runs at a time on the send, so the budget is the single most expensive type, not the sum.
- At a 64-sample buffer (1.33 ms) the heaviest shipped program measured here (Cloud Seed Dark Plate, 1.2 microseconds per sample) uses about 77 microseconds per buffer on this CPU; the room or hall about 13-26 microseconds.
- Much of the room/hall cost is `floor()` in 28 modulated all-pass reads (a libm call without SSE4.1) and the denormal macro; a Rust port that truncates with an integer cast and relies on flush-to-zero should land near the lower end of the measured range. This is inferred from the difference between the compiler configurations, not from profiling.
- Mono-in/stereo-out saves little for the freeverb3 engines (both channel chains are needed for the stereo field) but halves Airwindows Chamber and the spring if they are run as mono cores.

### Gaps
- No Rust measurements; these are C++ timings of the reference code on a shared virtual machine.
- MVerb, Plateau, zita-rev1 and Oliverb were not compiled.
- I did not profile where time goes inside each algorithm; statements about `floor()`, denormal checks, dither and cache effects are inferences from the code and from flag-to-flag differences.

## Sample-rate scaling cautions

### Takeaway
The sources use four incompatible conventions (reference-rate tables with prime rounding, raw 44.1 kHz sample counts with integer undersampling, times in seconds or milliseconds, and fixed tables for a fixed hardware rate), and several contain constants that silently do not scale. A port that must sound the same at 44.1, 48 and 96 kHz has to handle each case explicitly.

### Cited Findings
- freeverb3 (progenitor2, zrev2, strev, nrev/nrevb): tables at 34125, 34125 (input all-passes of zrev2), 29761 and 25641 Hz respectively; every length is `floor(table * fs * RSFactor / ref)` then incremented to the next prime, so integer lengths, and therefore exact echo patterns, differ per rate and per size; output-tap indices are scaled without prime rounding; modulation excursions scale with `fs/ref` only, except the triple-nested all-pass excursion in progenitor (121 / 5 samples), which also scales with the size factor; times given in milliseconds (22 ms output comb, pre-delay) and early-reflection taps in seconds scale directly. — [revbase.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/revbase.cpp), [progenitor.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/progenitor.cpp), [earlyref.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/earlyref.cpp)
- Prime rounding distorts short elements most: progenitor's right-channel excursion table value 5 becomes 7 at 48 kHz and 17 at 96 kHz; the 1-, 2- and 16-sample delays become 1, 2 and 23 at 48 kHz (my arithmetic from `p_`, see the Room table). — [progenitor.cpp](https://github.com/michaelwillis/dragonfly-reverb/blob/master/common/freeverb/progenitor.cpp)
- Airwindows: delay tables are raw sample counts tuned at 44.1 kHz; `cycleEnd = clamp(floor(fs/44100), 1, 4)` runs the core every 1st/2nd/3rd/4th sample with linear interpolation of the output, so 48 kHz uses the 44.1 kHz counts unchanged (times 8.1 % shorter, source comment: "we now shift gears between 44.1k and 48k so our tone is the same, slight changes in delay times") and 96 kHz runs a 48 kHz core. Filter coefficients are corrected with `downRate` in the k-series but only by `1/sqrt(overallscale)` in Chamber. Chamber's lengths are computed (`19900 * size` and golden-ratio steps), not prime tables. — [kChamberARProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/kChamberAR/kChamberARProc.cpp), [ChamberProc.cpp](https://github.com/airwindows/airwindows/blob/master/plugins/LinuxVST/src/Chamber/ChamberProc.cpp)
- CloudSeedCore: all times are milliseconds converted with `ms/1000*fs` and truncated to integers; LFO values are recomputed every 8 samples regardless of rate; all-pass buffers are fixed at 19200 samples ("100ms at 192Khz"), so the 100 ms maximum diffuser delay only holds up to 192 kHz; the effective loop time includes one host block. — [ModulatedAllpass.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ModulatedAllpass.h), [ReverbChannel.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/ReverbChannel.h), [DelayLine.h](https://github.com/GhostNoteAudio/CloudSeedCore/blob/master/DSP/DelayLine.h)
- chowdsp spring: all-pass and reflection delays are in milliseconds/seconds, but the long feedback delay is `1000 + size*0.099*fs` **samples**: the constant 1000 is 22.7 ms at 44.1 kHz, 20.8 ms at 48 kHz and 10.4 ms at 96 kHz, so the spring's echo spacing changes with sample rate. — [SpringReverbProc.cpp](https://github.com/surge-synthesizer/surge/blob/main/src/common/dsp/effects/chowdsp/spring_reverb/SpringReverbProc.cpp)
- Oliverb: fixed sample tables and a fixed 16384-sample buffer for the module's 32 kHz rate; the loop filters are raw one-pole coefficients (`lp`, `hp`), the pitch-shifter window is in samples (128-3410) and LFO slopes are per sample, so all of them are rate-dependent as written. — [oliverb.h](https://github.com/mqtthiqs/parasites/blob/master/clouds/dsp/fx/oliverb.h), [granular_processor.h](https://github.com/mqtthiqs/parasites/blob/master/clouds/dsp/granular_processor.h)
- GxShimmizita: FDN times are seconds x SR (as zita-rev1), but the pitch-shifter window (2048) and cross-fade (1024) are fixed sample counts. — [shimmizita.inc](https://github.com/brummer10/guitarix/blob/master/trunk/src/LV2/faust/shimmizita.inc)

### Inferences
- Recommended convention for the Rust chain: store every table as seconds (table / reference rate) and convert once per sample-rate or size change; apply prime rounding only where the source does (freeverb3) and only to elements longer than a few tens of samples, leaving the 1-16 sample "unit" delays and excursions as plain rounding to avoid the distortion noted above. This deviates slightly from freeverb3 at short elements and is my recommendation.
- Convert Oliverb's and Airwindows' raw coefficients to cutoff frequencies (one-pole: `fc = -ln(1 - a) * fs / (2*pi)`) at their native rates (32 kHz, 44.1 kHz) and recompute per rate; scale the spring's 1000-sample constant as 20.8 ms if 48 kHz is taken as the reference (Surge's default processing rate is the host rate, so there is no canonical choice; this is a port decision).
- Running an Airwindows core "as is" at 48 kHz is faithful to the plugin; scaling its tables by 48/44.1 is faithful to its 44.1 kHz sound. For the fixed prime tables (kChamberAR, kPlate) scaling breaks the tuned set, so prefer running them unscaled; for Chamber scaling is harmless.
- Linear interpolation inside feedback loops (Cloud Seed, Airwindows vibrato, triple-nested all-pass in progenitor) loses more treble at 44.1 kHz than at 96 kHz for the same modulation; keep modulation depths in milliseconds and expect slightly brighter tails at higher rates.

### Gaps
- I did not render the same program at 44.1, 48 and 96 kHz to quantify the differences.

## Recommended shortlist: 5-6 reverb types for vocals, each mapped to one concrete algorithm, with default vocal settings

- Measured cost and character of each engine: see the CPU and echo-density tables above (same sources, compiled and rendered in this session).
- *[secondary, from the earlier report, not re-opened]* Return processing guidance used in the app so far: high-pass 200-600 Hz, low-pass 5-10 kHz and about 3 dB of ducking on the reverb return. — [SOS: Advanced Reverberation, Part 2](https://www.soundonsound.com/advanced-reverberation-0) (not opened in this session)

- Shimmer: add as a switch on the Plate (or Hall) rather than a new type: two Oliverb-style cross-faded read taps per loop delay, +12 semitones, shifted/unshifted feedback blend 0.3-0.5, loop low-pass around 5-6 kHz and a high-pass around 150 Hz, with a soft limiter in the loop. These values are my starting points; the structure is Oliverb's (MIT). The alternative for the FDN hall is the Shimmizita arrangement (GPL-2.0-or-later).
- Optional seventh "Slap chamber" voicing: Airwindows Chamber with Bigness about 0.1-0.2 and Longness about 0.2 (measured RT60 0.7-0.9 s, density 0.5 after 50-60 ms), right channel de-tuned by a few percent in size for stereo. It is cheap (80 ns for the stereo original) but overlaps with a short delay effect, so it is lower priority than the six above.
